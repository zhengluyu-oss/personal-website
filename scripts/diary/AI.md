# 私密日记 RAG 与手动复盘

这一阶段在原 PostgreSQL 日记之上增加私密派生数据，博客及用户仍用 MySQL。默认关闭 `diary.ai.enabled`，不迁移数据库、不回填、不调用模型。真实供应商、生成模型、向量模型、维度和相关性阈值尚待选定；本地 HTTP 夹具仅证明软件链路，不能代表模型质量。

## 手动安装与版本边界

先确认 PG16 及备份、剩余内存和磁盘。生产原有 MemoryMax=512MiB 不因本功能自动提高；应用继续复用最多3个连接的日记池，单个后台 worker。当前隔离验收组合为 PG16.14 / pgvector 0.8.3，固定镜像 `pgvector/pgvector@sha256:131dcf7ff6a900545df8e7e092c270aa8c6db2f2c818e408cb45ec21316b74e6`。生产原有 PG16.15，需要按其发行版安装匹配的 pgvector 二进制并验证，不以容器验证代替原生安装兼容性。

1. 先备份整个日记数据库。不要只导出 `diary` schema，新的完整备份还必须包含 `diary_ai` 和 `diary_vector` 扩展定义。
2. 用管理员连接执行 `000-vector.sql`。扩展固定在 `diary_vector`；发现已在其他 schema 安装会拒绝自动搬迁。不要开放 public 的 CREATE 权限。
3. 用管理员或有权 SET ROLE diary_migrator 的连接，以 `psql -X -v ON_ERROR_STOP=1 -f 002-private-diary-ai.sql` 执行新迁移。该文件使用 psql 元命令，不是应用启动 JDBC 脚本。
4. 重复执行 `002`，再执行原 `001-private-diary.sql`，两者都必须通过。指纹不符时调查漂移，不删除版本表或伪造指纹。
5. 确认9张 AI 业务表 FORCE RLS；应用必须仍用非所有者 `diary_runtime`，无超级用户、BYPASSRLS 或角色成员身份。原三表、历史不可变权限不变。

## 外置模型配置

`ai-config.example.yml` 展示完整字段。将它合并到当前受限配置，或用 `spring.config.additional-location` 加载外置副本，不覆盖现有生产配置。示例通过占位符明确映射带下划线的环境变量；不要猜测 Spring 对多单词属性的环境变量切分。密钥只由后端读取，文件权限仅运行用户可读，不放在 Git、静态目录、浏览器或命令历史。

需要分别确定：provider 标识；两个完整 HTTPS API 地址（embeddings / chat completions，而非网站首页）；独立密钥；精确模型名；向量维度；两者主机名的白名单；供应商训练使用、保留期限、处理地域、删除政策的核实记录；该向量模型的最小相关性阈值。未填、维度不合法、未核实数据政策或未校准阈值时能力检查拒绝启用。白名单仅容纳受信供应商，不能填用户可控制的域名。HTTPS、无 URL 凭据/查询参数、443、公开解析地址、禁止重定向均检查；DNS检查最多5秒。DNS复查不是网络出口防火墙，生产还需在受信 DNS/出口策略中限制供应商地址，不能声称完全消除 DNS 重绑定风险。

首个适配器使用兼容的 `model/input` embeddings 与 `model/messages/max_tokens` chat JSON；不假设所有“兼容”服务行为相同。真实接入需核对路径、认证、批量数量、返回 index/维度、finish_reason、usage、上下文和输出参数。没有供应商契约验收不得宣布已接通真实模型。生成不重试，不给模型工具、联网、数据库或发送消息能力。

额度是次数预算，不是金额封顶：每日北京时间20次生成尝试、200个向量输入（问题也计入），队列5、报告1000。失败/取消可能计费，不自动退回尝试。usage缺失保持未知；目前只累计供应商明确返回的 token 数，不能据此推算完整账单。连接5秒，HTTP含响应正文总时限30秒，响应4MiB，问题1000码点，问答上下文12000，复盘40篇/24000，整个提示32000，输出2000tokens。字符预算不是精确token计数；真实供应商更严格限制需单独收紧并处理拒绝。

## 使用与状态

本人工作区底部“日记助手”展示数据流说明。明确确认后，手动建立索引；随后低频处理新增/修订的当前篇目。暂停阻止后续调用，已发出的批次不能保证撤回；明确重试异常篇目可能再次计费。保存原文不等待模型。模型/维度/切分配置变化会建立新 profile，先暂停并提示重建，不混算旧向量。

问答选择相关片段，最多8块、每篇2块，并标明资料不足/部分索引。索引未完成默认拒绝，用户可明确选择部分资料。云端不可用时，可以继续用原日记“查阅与筛选”的普通关键词搜索；该搜索不产生 AI 回答。

复盘使用预览范围内的完整当前正文，不依赖向量就绪。指定篇目与时间范围二选一；日期默认内容起止闭区间相交，可切换北京时间创建日界。未填内容日期不进入 covered 筛选。超限须缩小范围；新增、修改、删除导致范围摘要变化会拒绝排队或发布。跨日篇目不能推算成每天发生或具体次数。

QUEUED/RUNNING 是等待/处理中；只有校验通过才 SUCCEEDED。UNCERTAIN 表示请求结果未知、可能收费，不会自动重发；取消不承诺撤回。重试未确认提交使用相同 requestId，查询任务不创建新任务。任务标识/幂等凭据保留，删除报告只清理派生报告和原请求中的私密载荷，不删除原文/历史。

报告区分观察、推测、建议和限制。引用必须为服务端来源ID及逐字引文，点击时再核对版本与偏移并高亮。来源变化立即隐藏报告；模型文字通过 Vue 文本节点展示（比可点击 Markdown 更受限），不执行 HTML、脚本、媒体或链接。合法引用不保证推论成立，仍需自己核对。报告可能保留在已打开页面的内存，新的查看/引用会复核来源；登出/换账号会卸载 AI 工作区并丢弃晚到响应。

## 备份、日志与回退

保留原加密备份管道、14天保留与离机副本机制。完整 pg_dump 包含扩展声明，但不含扩展二进制或集群角色；新隔离实例须先安装兼容 PG16/pgvector 和角色，再解密恢复到新数据库。比较全部原文/历史/幂等及 AI 表的摘要，复核 RLS、profile/维度、引用版本；分别重复原001/新002。不要覆盖在线库。`ai-recovery-qa.mjs` 仅在带本变更标签的隔离容器中演练 AES-256-GCM 往返及新库恢复，不能替代生产 age 私钥的保管或生产恢复演练。

日记包和 JDBC 参数日志延续 OFF。不要开启 JDK HTTP client 请求/响应正文诊断、代理请求体日志、PG参数日志、APM载荷或审计正文采集。日记AI路径沿用 no-store/noindex 和本人校验；其他管理员也无权访问。

独立回退只需 `diary.ai.enabled=false` 并重启。保留 PG、扩展、所有派生数据和备份，原文保存继续工作。不要回退原文schema或drop扩展。首次上线仍须完成真实模型虚构语料评测、实际维度的容量校准、资源/费用/隐私核实并取得部署授权。

## 可复现的本地验证

- `verify-ai-postgres.py` 创建固定镜像的有标签隔离容器，验证迁移、RLS、漂移和原schema。
- 准备仅监听127.0.0.1:15432的专属 `diary_qa` 后，设置 `BLOG_DIARY_AI_QA=true` 运行 `mvn -B -q -Dtest=DiaryAi*Test test`；没有这个显式开关时真实 PG 测试跳过。必须保留跳过计数，不能冒充通过。
- 本机Windows JDK的AF_UNIX临时目录过长时，测试参数增加 `-DargLine=-Djdk.net.unixdomain.tmpdir=C:/Windows/Temp`，只影响测试进程，不修改机器全局设置。
- `DiaryAiBrowserFixture` 只在 test-classes 中，需 `BLOG_DIARY_AI_QA=true`，本地端口18002/18004；Vite QA端口15173代理到18002。它使用固定虚构JWT/受控HTTP且绑定回环，绝不可打包部署。
- `ai-browser-qa.mjs` 检查专属站点标记后才写入，设置独立 `DIARY_QA_OUTPUT`、`PLAYWRIGHT_MODULE` 与可用 Chromium 路径。
- 真实模型评测使用 `synthetic-corpus.json` 的20个有依据/8个无依据问题；期望来源recall@8≥90%，无依据全部拒绝补造，人工核对解释与跨日限制。受控HTTP通过不等于完成这一项。
