# 分类博客 Hero 文案部署说明

## 上线顺序

1. 备份生产数据库 `t_category` 表。
2. 上传 `sql/configurable-category-blog-hero.sql` 和 `scripts/migrate-configurable-category-blog-hero.sh` 到脚本约定的 `/tmp` 路径。
3. 执行迁移脚本；只有输出 `MIGRATION_OK` 且四个字段均验证存在后才继续。
4. 部署后端，验证分类新增、编辑、清空及 `/category/list` 公开响应。
5. 部署管理端和博客前端，在一个测试分类填写 Hero 文案并验证桌面端、平板和手机端。

## 线上验证清单

- `/blog` 仍显示默认眉题、双色主标题和简介。
- `/blog/:slug` 显示当前分类配置的 Hero 文案，右侧文章数量保持正确。
- 连续切换两个分类时文案与统计同时变化，没有上一分类残留。
- 只配置部分字段时，其他字段逐项使用默认文案。
- 清空配置并保存后立即恢复默认文案。
- 分类主推荐、文章列表、分类 slug 和文章详情路由保持原有行为。
- 接近长度上限的标题在手机端正常换行，不产生横向滚动。

## 回滚

1. 先回滚博客前端、管理端和后端应用。
2. 新增字段均可为空，可暂时保留，不影响旧应用运行。
3. 确认旧应用稳定且不再读取这些字段后，执行迁移 SQL 末尾注释中的回滚语句。
4. 如需恢复分类数据，使用迁移脚本输出目录中的 `before.sql`。
