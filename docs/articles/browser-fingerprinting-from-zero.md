# 浏览器指纹追踪与反追踪：原理、风险和隐私保护

> 从零理解版，修订于 2026 年 10 月 19 日。本文先解释概念，再解释实现，不要求你提前了解 Cookie、哈希、Canvas 或 WebGL。文中的人数、编号和访问记录都是教学假设，不是对真实网站的测量。

你用 Chrome 打开一个网站，关掉页面，过一会儿又打开。网站有没有办法判断“这次访问可能还是刚才那个浏览器”？

有好几种办法：你可能还登录着，浏览器可能保留着网站发的编号，也可能再次表现出相似的环境特征。**浏览器指纹，讨论的就是最后一种办法：根据浏览器表现出来的一组特征，尝试认出曾经见过的浏览器环境。**

它不是扫描你的手指，也不是网站偷偷读到了一个永远不变的电脑身份证号。先记住这句话，下面再把“一组特征”“表现出来”“尝试认出”逐一拆开。

## 一、先把三个角色认清：你、浏览器、网站

假设你在电脑上打开一个技术博客，整个过程里有三个不同的角色：

- **你**：正在操作电脑的真人。
- **浏览器**：Chrome、Firefox、Safari 等软件，负责打开网页。
- **网站**：向浏览器提供页面、处理请求的服务。

网站首先接触到的是浏览器发来的请求，不是直接接触到屏幕前的真人。即使网站判断“两次访问看起来来自同一种环境”，也不能仅凭这一点断定是同一个人在操作：家人可以共用电脑，同一个人也可以使用不同浏览器。

理解指纹时，最容易犯的错误，就是把下面几句话当成一句话：

```text
两次收集到的特征相同
两次可能来自同一个浏览器环境
两次一定来自同一台物理电脑
两次一定是同一个人
网站知道这个人的真实姓名
```

越往后，需要的额外证据越多。浏览器指纹主要帮助判断前两件事，不能自动证明后面几件事。

## 二、一个生活类比：发号码牌，与看外观认人

假设你去一家店，店员想知道你是不是来过。

第一种办法是给你一张编号为 `A-103` 的会员卡。下次你出示这张卡，店员就能查到卡对应的记录。这类似于一种常见的 Cookie 使用方式：网站让浏览器保存一个编号，以后再按规则带回来。

第二种办法是不发卡，而是记住“灰色外套、蓝色背包、戴眼镜、个子较高”。你再来时，店员根据这些特征猜测是不是见过你。这更接近浏览器指纹的思路：**不一定先存一个编号，而是观察一组现有特征。**

这个类比也说明了它的局限：

- 别人可能穿着相似的衣服，于是被误认成你。
- 你可能换了衣服，于是没被认出来。
- 认出了相似外观，也不代表知道你的姓名。

现实中的浏览器没有“外套”，但有语言设置、显示参数、可用功能和图形处理表现。网站把这些信息组合起来，形成描述浏览器环境的“特征组合”。MDN 对浏览器指纹的解释也强调了收集和组合环境特征，而不是读取一个通用设备序列号。[MDN：浏览器指纹](https://developer.mozilla.org/en-US/docs/Glossary/Fingerprinting)

注意：Cookie 并不只用于识别访客，它也能保存偏好或参与会话管理。这里的号码牌只是帮助理解其中一种用法。

## 三、为什么网站能看到这些信息？我并没有主动填写啊

因为现代网页不只是文字和图片，也包含在浏览器里运行的程序，最常见的语言叫 JavaScript。浏览器向网页提供一些接口，让程序可以完成正常功能。

例如：网页需要知道可用的显示宽度，才能把电脑版布局换成手机版布局；需要知道语言偏好，才能选择合适的界面；需要了解图形功能是否可用，才能决定是否启用某种视觉效果。

所谓 **API，也就是接口**，在这里可以简单理解成“网页程序向浏览器询问信息、调用功能的规定方式”。

例如 `navigator.language`，就是读取浏览器首选语言的一种接口。它可能返回 `zh-CN` 或 `en-US`，并不是读取你的聊天内容或身份证。[MDN：language 属性](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/language)

问题在于：**为了正常功能提供的信息，也可能被另一个程序收集起来用于识别。**有的特征来自直接读取，有的来自执行一次计算并测量结果，并不都需要像麦克风那样单独弹出权限窗口。

但不能由此推出“网页能读取整台电脑”。可用信息受浏览器、版本、接口规则和保护策略限制。具体接口能读到什么，需要逐项判断。

## 四、一个完整例子：几条普通信息怎样变成一组特征

假设某网站在浏览器允许的范围内，观察到了以下数据：

| 特征 | 假设观察值 | 用白话理解 |
| --- | --- | --- |
| 首选语言 | 中文 | 浏览器偏好使用哪种语言 |
| 时区 | 亚洲／上海 | 当前环境怎样解释和显示当地时间 |
| 页面可用宽度 | 1200 CSS 像素 | 页面此时有多少横向排版空间 |
| 像素比例 | 2 | 设备像素与 CSS 像素之间的比例 |
| 某项图形功能 | 支持 | 当前浏览器环境是否提供这项能力 |
| 某次绘图结果 | 结果片段 R | 同一绘图任务最终产生的输出 |

这里的数值只是例子，不是你的浏览器实测。尤其要区分：**浏览器窗口宽度、屏幕分辨率、显示器物理尺寸不是同一个东西。**改变窗口或页面缩放，可能影响部分显示相关数据。[MDN：innerWidth](https://developer.mozilla.org/en-US/docs/Web/API/Window/innerWidth)、[MDN：devicePixelRatio](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)

单看“中文”，很多浏览器都一样；单看“亚洲／上海”，也有很多环境一样。组合更多信息后，相同组合可能变得更少。

为了直观理解，假设网站正在比较 1000 条历史环境记录：

```text
先找首选语言相同的记录：还有 600 条
再在这 600 条里找时区相同的：还有 420 条
继续比较一组显示与功能特征：还有 18 条
再比较某项绘图输出：还有 2 条
```

这只是演示“逐步缩小候选范围”的假设，数字没有真实统计含义。它也不意味着随便收集几个字段就能唯一认出你：这个例子最后仍有两个候选，网站还无法确定是哪一个。

## 五、网站怎样把两次访问联系起来

把上面的例子沿时间展开，就容易理解了。

**第一次访问：**网站收集一组允许获得的特征，记录访问时间以及对应页面；它可以保留特征本身，也可以保留特征的某种整理结果。

**第二次访问：**网站再次收集特征，与历史记录比较。如果足够相似，系统可能判断“这次访问与之前记录的某个环境有关”。

```text
第一次打开网站
    ↓
观察浏览器特征 → 记录一组环境信息
                         ↑
第二次打开网站 → 再次观察 → 比较两次结果
                                ↓
                       相同、相似，或者无法关联
```

有的实现做较直接的相等比较，有的系统会综合多种信号进行匹配。窗口宽度变了，是否仍算同一环境，取决于它比较哪些特征、怎样比较，不能只看某一个字段。

因此，**浏览器指纹是一种观察和关联的方法，不是所有网站都会使用的统一编号制度。**不同网站和不同产品选择的特征、算法、保留方式都可能不同。

### 经常出现的“哈希”，到底在这里做什么

你可能见过一串类似 `9f2a...` 的指纹编号。它可能是把一组特征整理成数据后，再计算出的摘要。

哈希可以先理解为一个按规则生成摘要的函数：输入一段数据，得到一段较短的结果。以常见的密码学哈希为例，同样的输入会得到同样的输出，输入改变通常会显著改变摘要。MDN 的 `digest()` 文档解释了这类摘要计算。[MDN：摘要计算](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest)

但摘要不会凭空增加识别信息。假设两个人的环境被采集后得到完全相同的数据，即使摘要很长，系统也不能靠摘要把他们分开。这不一定是“哈希碰撞”，因为输入本来就相同。

所以，看到一个长字符串，先把它理解成“一组观察结果的编号或摘要”，不要把它当作“网站拿到我的真实身份了”。

## 六、Canvas 指纹为什么听起来神秘，其实是测了一次绘图

Canvas 是网页中的一种绘图能力。网页程序可以在一块画布上画线条、文字、形状或图像，正常用途包括图表、游戏和图片编辑。[MDN：Canvas API](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API)

用于指纹观察时，思路可以拆成四步：

1. 程序要求不同浏览器执行同一个绘图任务。
2. 浏览器使用当前环境完成绘制。
3. 程序在允许的情况下读取画布输出。
4. 比较输出是否有差异，或者为输出计算摘要。

为什么同一个任务可能产生不同结果？你可以想象，同一句话在不同排版环境中显示，字的边缘、间距或像素细节可能略有差异。图形实现和环境的差异，也可能反映在输出中。浏览器的限制或保护还可能影响可读结果。[W3C：浏览器指纹风险与缓解](https://www.w3.org/TR/fingerprinting-guidance/)

这里不是“网站拍了一张你电脑桌面的照片”。它观察的是**网页自己发起的绘图任务产生了什么结果**，不等于获得整个屏幕截图。

你也不需要看到页面上出现一幅画。计算可能发生在不显眼的画布中。因此，“我没看到它画图”不能证明没有这类操作；反过来，网页使用 Canvas 也不代表它在追踪，正常图表同样会使用它。

## 七、WebGL、字体和音频，又分别是在看什么

不要一次记住所有缩写。先记住共同点：**它们都是不同的观察入口，用来了解浏览器环境的表现。**

### WebGL：观察图形能力与渲染环境

WebGL 是网页使用图形能力的一套接口，常见于三维展示和图形程序。部分环境信息或渲染差异可能成为识别信号。

例如，`WEBGL_debug_renderer_info` 扩展在可用时能提供部分图形供应方和渲染器信息。但它不是所有浏览器都保证提供的“显卡身份证”，可用性会受到环境及保护设置影响。[MDN：图形渲染信息扩展](https://developer.mozilla.org/en-US/docs/Web/API/WEBGL_debug_renderer_info)

### 字体：从文字表现推断环境差别

同样一段文字，如果某种字体可用和不可用，显示宽度或回退结果可能不同。程序可以通过测量这些表现寻找差别。

这里需要避免一个误解：“利用字体差异”不代表普通网页能够任意下载你电脑里的全部字体文件。指纹讨论的是可观察或可推断的差异。

### 音频：计算一段声音，不一定是在录音

程序可以让浏览器处理一段自己生成的音频数据，再观察结果。它不一定播放声音，也不一定使用麦克风。

`OfflineAudioContext` 就是一种可以离线处理音频图的接口，结果可以是计算得到的音频缓冲数据，不需要把声音输出到扬声器。**“音频指纹”与“录下你说话的声音”是两回事。**[MDN：OfflineAudioContext](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext)

这些入口是否可用、输出差异是否明显，都要看具体浏览器和条件。本文解释的是方法，不承诺每个网站都能得到同样的信息。

## 八、Cookie、IP、账号和指纹，放在一起比较

这四个词经常一起出现，但解决的问题不同：

| 名称 | 可以先怎样理解 | 为什么不能直接等同一个人 |
| --- | --- | --- |
| 账号 | 用户在网站中使用的账户身份 | 一个账号可以在多台设备使用；也可能被共用或盗用 |
| Cookie | 浏览器按规则保存并向网站发送的数据 | 数据可能被清除，作用范围受规则限制；也可能只保存偏好 |
| IP 地址 | 网站看到的网络来源地址之一 | 多个用户可能共用出口，一个用户也可能更换网络 |
| 浏览器指纹 | 根据可观察环境特征形成的描述与匹配结果 | 不同人可能相似，同一人的环境也可能变化 |

Cookie 的关键在“保存状态，再按规则带回”；指纹的关键在“重新观察环境，再尝试匹配”。浏览器不会把某个网站的所有 Cookie 随意发给任意其他网站。[MDN：HTTP Cookie 的工作方式](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies)

### 为什么清除 Cookie 后，还可能被关联

继续使用会员卡的类比：丢掉会员卡，并不会自动让你的外套、背包和外观都改变。类似地，清除网站保存的数据，不一定改变语言、时区或图形表现。

但是，**网站再次认出你，不一定用了指纹。**你可能重新登录了同一账号，或者仍有其他可关联信息。不能看到“清了 Cookie 仍像被认识”，就直接宣布找到了指纹追踪的证据。

### 为什么改了 IP，也可能没有改变指纹

因为换网络主要改变网络侧条件，不会自动更改浏览器里的语言和所有渲染行为。反过来，两个人使用同一个 IP，也不代表他们的浏览器特征相同。

理解这一点后，就不容易把“换网络”“清数据”“换浏览器”“退出账号”当成同一个操作。

## 九、它究竟能认多准？先分清三个问题

不用先学信息熵公式，只需要问三件事：

**第一，这组特征常不常见？**如果很多环境完全一样，系统就很难靠它们区分访客。

**第二，这组特征稳不稳定？**如果每次观察都变化，很难仅靠直接比较长期关联。

**第三，观察者有没有机会在两次访问中拿到可比较的信息？**没有可连接的数据流，再特别的特征也不能自动把两个网站的记录拼到一起。

例如，一组数据在测试样本里很少见，但浏览器保护让它每次变化，它的“少见”就不自动代表长期好追踪。另一组数据始终不变，但几万人都一样，也不足以唯一识别一个环境。

开源项目 FingerprintJS 展示了实际的浏览器侧特征采集与标识生成，同时说明浏览器端结果存在被修改和识别准确性方面的局限。它也明确区分开源库与商业产品，不能把商业宣传数字直接当作开源库在你的网站上的表现。[FingerprintJS 项目与局限说明](https://github.com/fingerprintjs/fingerprintjs)

这里还有两种相反的错误：

- **错误关联**：把不同环境的记录误当成同一个。
- **关联遗漏**：同一个环境再次访问，却没有匹配上。

所以，指纹可以是辅助判断信号，但不应该被当作密码或登录凭证。网站不能因为“看起来像某个用户的浏览器”，就直接向它交出那个账号的私密数据。

## 十、“跨站追踪”怎么发生？不是网站天然互通

先看单个网站：技术博客记录你在本站阅读哪些文章，再尝试关联下一次访问，观察范围主要是这个网站。

跨站则需要额外条件。假设 A 网站和 B 网站都接入同一个第三方统计或广告服务 T，并且 T 在两处都能获得可比较的信息：

```text
访问 A 网站 → 第三方 T 得到一次观察
访问 B 网站 → 第三方 T 得到另一次观察
                        ↓
                 T 尝试关联两次记录
```

这才有可能形成跨站关联。这里的重要问题是：**谁收集、谁接收、能在哪些网站观察、各次观察能否匹配。**浏览器的隔离和保护策略会影响这条路径。[W3C：指纹类型与关联范围](https://www.w3.org/TR/fingerprinting-guidance/)

不能因此说“A 网站可以随便读取 B 网站的数据库或登录 Cookie”。两者不是同一个机制。也不能说网页里出现第三方代码就一定在做指纹追踪，仍需要检查实际的数据行为。

当一些记录与登录账号连接后，环境特征才可能进一步与账户活动关联。这是“指纹信号加上其他数据”的结果，并不是指纹摘要自己计算出了真实姓名。

## 十一、无痕模式到底保护什么，为什么不等于完全隐身

Chrome 的无痕模式主要提供独立的临时浏览会话：结束无痕会话后，Chrome 不保留该会话的站点数据和浏览记录等信息。但它没有承诺让访问的网站、网络服务提供方等都看不见你的活动。下载到电脑的文件也不会因此自动消失。[Chrome 官方：无痕浏览的作用和限制](https://support.google.com/chrome/answer/95464?hl=en)

你可以把普通窗口与无痕窗口想成两个不同的临时登记簿，但它们仍可能运行在同一套电脑、系统和浏览器上。是否有额外特征保护，要看浏览器及对应版本的实现。

因此：

- 无痕窗口里没有普通窗口的登录状态，不代表所有环境特征都不同。
- 两个窗口里某几个特征相同，不代表它们共享了 Cookie。
- 某个网站判断两次访问有关联，也不证明无痕模式“什么都没做”。

这些机制分别改变不同条件，不能把它们简单分成“绝对有效”和“完全没用”。

## 十二、反指纹保护究竟在做什么

知道识别过程后，保护思路就容易理解了：减少可观察差异，减少长期匹配，或者减少不同网站之间共享观察的机会。

| 保护思路 | 用白话解释 | 主要局限 |
| --- | --- | --- |
| 阻止已知采集脚本 | 不让某些已识别的采集程序运行或请求数据 | 未知脚本或其他路径可能仍存在 |
| 限制部分接口 | 少回答一些细节问题 | 可能影响需要这些功能的网页 |
| 标准化输出 | 让很多浏览器看起来更相似 | 仍要考虑其他特征和网页兼容性 |
| 随机化或按范围隔离 | 让不同访问上下文不容易直接匹配 | 某个输出改变，不代表其他关联路径全部消失 |

Firefox 的官方说明介绍了阻止已知指纹采集者以及限制部分信息的保护方式，实际生效范围取决于浏览器版本和设置。保护设置也可能影响个别网站，应以当前官方说明和实际兼容情况为准。[Firefox：指纹保护](https://support.mozilla.org/en-US/kb/firefox-protection-against-fingerprinting)

不要把“某个测试 ID 变了”理解成“已经绝对无法追踪”，也不要为了让自己更安全，盲目安装一堆功能重叠的扩展。判断一种措施时，要先说明它改变的是哪一条数据路径，再看其他路径是否仍然存在。

对于日常使用者，可以先做几件容易坚持的事：及时更新浏览器，了解并使用内置隐私设置，只保留信任且确有必要的扩展；不要把清 Cookie、无痕模式或换 IP 中的任何一项当成完整的匿名保证。

## 十三、一个可以自己观察的小实验，不懂代码也可以跳过

这个实验不是完整的指纹系统，只帮助你亲眼看到“网页可以读取某些环境信息”。它不生成用户编号，不读取麦克风，不请求服务器，也不保存结果。

把下面内容保存为本地的 `browser-observation.html`，用浏览器打开。只在自己的本地文件里操作，不需要在陌生网站的控制台粘贴代码。

```html
<!doctype html>
<html lang="zh-CN">
<meta charset="utf-8">
<title>本地浏览器信息观察</title>
<h1>本地观察：不会上传结果</h1>
<button id="refresh" type="button">重新观察</button>
<pre id="result"></pre>
<script>
  function observe() {
    const data = {
      preferredLanguage: navigator.language,
      timeZone: Intl.DateTimeFormat().resolvedOptions().timeZone,
      viewportWidth: window.innerWidth,
      viewportHeight: window.innerHeight,
      pixelRatio: window.devicePixelRatio
    };
    document.getElementById('result').textContent =
      JSON.stringify(data, null, 2);
  }
  document.getElementById('refresh').addEventListener('click', observe);
  observe();
</script>
</html>
```

输出字段分别是首选语言、时区、页面视口宽高与像素比例。它们有些经常稳定，有些会随窗口和缩放变化，不能用这五个数值就宣称唯一识别了一个人。

可以按顺序做三次观察：

1. 同一个窗口连续点击，看看值是否变化。
2. 改变窗口大小，再点击，观察宽高是否改变。
3. 在允许打开本地文件的无痕窗口中打开同一个文件，比较结果；不支持时就跳过，不必修改安全设置。

这个实验最重要的是怎样解释结果。窗口缩小、宽度改变，只能证明这个显示条件变了，不代表操作电脑的人换了；普通与无痕的某些值相同，也只能说明这些观察值相同，不能证明账号状态、全部指纹或所有网站的识别结果相同。

它的价值是把抽象概念变成可观察现象，而不是给出一个“隐私安全分数”。

## 十四、看到指纹检测结果时，应该问什么

有的测试网站会告诉你“你的浏览器很独特”。读到这里，可以用几句话检查这个说法的含义：

- 独特是相对于哪个样本？测试过的用户，并不代表全体网民。
- 是哪些特征造成的？某个字段不同，不代表网站知道你的真实身份。
- 同一条件重复测试，结果稳定吗？变化可能来自设置、版本或保护。
- 测试页面收到哪些信息，会保存多久？测试本身也会暴露信息。
- 它展示的是某个指纹库的能力，还是一个商业服务的综合判断？两者不能直接混用准确率。

同样，修改特征也不是越多越好。研究曾讨论过部分修改产生不一致表现的情况，但这类研究需要结合发表时间、工具和实验环境理解，不能据此断言今天所有保护工具都无效。[USENIX：浏览器指纹不一致研究](https://www.usenix.org/conference/usenixsecurity18/presentation/vastel)

## 十五、回到最开始的问题：浏览器指纹到底是什么

现在可以把最开始的一句话补全：

**网站可以观察浏览器提供的信息和执行任务时的表现，将这些特征组合起来，与之前的记录比较，尝试判断是不是再次遇到了相同或相似的浏览器环境。这种方法叫浏览器指纹识别。**

它可能辅助反欺诈，也可能被用于追踪；是否形成隐私风险，还要看收集目的、保存时间、数据接收方，以及是否与账号或跨站活动关联。

读完后，不必背出所有 API。先确认自己能解释下面四句话：

1. **它靠观察环境特征来推断，不是自动读到一张电脑身份证。**
2. **清掉网站保存的编号，不一定改变浏览器本身的表现。**
3. **特征相似不等于已经确认真人身份，识别会有误差。**
4. **保护措施各自改变不同条件，没有一个简单开关能保证所有关联消失。**

如果这四句话已经能用自己的话说明，浏览器指纹的基础就理解了。网站怎样把这些不确定的信号用于安全判断，可以继续阅读 [浏览器指纹与网站风控](/blog/articles/144)；那是建立在本文基础上的下一步，而不是理解本文之前必须掌握的内容。
