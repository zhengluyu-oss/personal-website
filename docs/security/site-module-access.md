# 前台模块访问权限

## 使用方式

在后台“系统管理 → 角色管理 → 前台模块访问”中设置首页、工作经历、个人博客、网站分享、相册和关于我的访问方式。

- 公开访问：游客及登录用户均可查看，六个模块的初始配置均为公开。
- 指定角色可见：至少选择一个启用中的角色；用户拥有其中任一角色即可查看。
- 用户角色沿用角色管理中的“授权用户”，不重复建立用户授权系统。
- 有效的 `ADMIN` 角色始终可查看前台模块；停用角色、删除角色、禁用账号和移除角色成员关系不会继续提供查看权限。
- 导航入口保留。未授权访问会进入权限提示页，不加载目标内容；登录及账号设置不受模块限制。
- 各模块单独保存。并发修改通过 `revision` 校验，冲突返回 409，需重新读取配置。

读取配置要求现有 `system:role:list` 权限，修改配置要求 `system:role:update` 权限。前台查看授权与后台内容管理权限分别校验。

## 实现范围

`/site-modules/access` 只返回模块名称、公开状态和当前访问结果，不向游客暴露角色授权名单。权限判断实时读取有效用户和角色关系，不采用 JWT 内缓存的角色名单。

服务端 MVC 拦截覆盖文章列表、详情、搜索、推荐、随机文章、分类、标签、经历及项目详情、网站分享及迁移入口、相册列表、首页轮播，以及文章评论、点赞和收藏接口。后台已声明 `@PreAuthorize` 的管理方法沿用原来的管理权限。

共享网站信息接口对未授权的首页文案、博客统计/推荐和个人资料字段进行清除。“关于我”正文通过受保护的 `/site-modules/about` 返回。首页不请求或展示未授权的博客和经历摘要；导航分类下拉也不加载未授权内容。权限响应及受控内容接口使用 `private, no-store`。

**权限不会撤回已公开信息，也不会将公共 OSS 图片自动改为私有文件。** 受限相册不再向未授权用户提供图片列表，但已知的公共原图地址仍可通过原文件服务读取。原图、附件和第三方外链需要另行采用私有存储与文件授权方案。

## 发布顺序

本次只准备了代码与迁移文件，未对线上数据库执行操作。

1. 备份目标数据库及当前后端、前台和后台发布版本。
2. 在目标数据库执行 `sql/site-module-access.sql`。新增两张配置/角色关联表，不改现有用户或角色表。
3. 核对六个模块配置均存在；首次安装均为公开。迁移脚本可重复执行，不覆盖已有权限策略。
4. 发布后端，再发布前台及后台。缺少模块配置时后端拒绝提供相应内容，前台显示“暂时无法确认访问权限”，不会默认为公开。
5. 默认公开状态下验证原有页面；创建测试角色并授权测试用户，再验证游客拒绝、指定角色允许、无关角色拒绝、删除授权立即生效以及直接接口访问被拒绝。

回退旧后端可能恢复以前的公开访问行为。已经设为受限的模块需要先采取阻断访问措施或制定明确的权限回退方案，不应只回退应用版本而忽略信息暴露风险。迁移表可保留以便恢复配置。

## 本地验证

```powershell
# 后端权限判定、直连接口、管理权限及共享信息清除
cd blog-backend
mvn -Dtest=SiteModuleAccessServiceTest,SiteModuleAccessInterceptorTest,SiteModuleControllerSecurityTest,SiteModuleMetadataTest test

# 前台路由归属、异常配置拒绝访问与现有回归
cd ../blog-frontend/kuailemao-blog
node --experimental-strip-types --test src/utils/site-module-access.test.ts
pnpm test
pnpm build

# 后台类型检查及构建
cd ../kuailemao-admin
pnpm build
```

后端单元和 MVC 测试使用模拟存储及服务，验证接口不会在权限拒绝时执行原业务；尚未在实际目标 MySQL 数据库上执行迁移和发布验证。
