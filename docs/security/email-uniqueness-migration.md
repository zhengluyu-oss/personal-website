# 邮箱唯一性迁移（待授权上线）

用户于 2026-10-02 批准编写和测试；未授权执行线上迁移。

## 范围与影响

只为 `sys_user.email` 增加完整列唯一索引，保留原有排序规则、邮箱值和账号。NULL 可重复，表示未绑定。停用和软删除账号继续占用邮箱；不自动释放、合并或删除账号。数据库排序规则决定大小写等值语义，应用层比较必须与之兼容。

DDL 会自动提交，可能等待元数据锁或影响写入延迟，不能依靠事务回滚撤销。必须先核对目标库版本、备份及维护窗口。应用层注册、第三方建号和换绑冲突处理未完成前，不单独发布该索引。

## 操作顺序

1. 只读执行 `scripts/security/email-uniqueness-preflight.sql`，只报告重复组、受影响账号和空白地址的数量，不输出邮箱或密码。
2. 任一数量非零时停止。由所有者在受限环境确认历史记录处理方式，迁移脚本不代做处理。
3. 备份目标表到受限位置，并协调暂停注册、换绑和第三方首次建号写入；只读预检与 DDL 之间仍可能出现竞争，DDL 的唯一性校验是最后防线。
4. 获得线上操作授权后，在明确选择的目标库执行 `sql/security-email-uniqueness.sql`。不要使用忽略错误继续执行的客户端选项。
5. 核验 `uk_sys_user_email` 为 email 单列、非前缀唯一索引，账号行及字段未改变，应用能受控处理冲突。

脚本可重复执行；若存在同名但错误定义的索引则停止，不擅自替换。失败可能留下专用于此次迁移的存储过程，重试会重新建立该过程。错误排查不要公开含数据值的数据库原始错误。

## 回退与验证

优先回退应用而保留唯一性约束。删除约束会重新允许身份冲突，不提供自动降级删除步骤。
