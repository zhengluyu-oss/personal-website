# 敏感日志治理操作说明

## 默认行为

`scripts/security/audit-log-inventory.sql` 仅使用只读事务和聚合查询，不修改记录，不输出密码、验证码、用户名、请求地址或异常原文。必须使用明确选定的数据库和只读账号；大型日志表先在受限备份上执行，避免影响线上负载。候选数量不是确认泄漏数量。

代码修复会对入队内容最小化，并对旧队列消息的请求、响应及异常原文再次移除；不会自动修改历史数据库记录。

## 清理前必须确认

1. 按时间窗口、记录 ID、日志类型核实范围，禁止复制敏感原文到聊天、工单或仓库。
2. 由所有者决定保留要求和具体脱敏字段；优先清空敏感字段，保留事件结果、时间和必要追溯信息。
3. 将精确目标记录备份到加密、权限受限的位置，验证可恢复性，制定访问和销毁期限。备份本身仍是敏感数据。
4. 获得针对具体记录/字段的清理授权后，在事务内分批更新并核对数量；本脚本不包含自动更新或删除语句。
5. 核查消息队列、日志文件、备份及外发报告中是否仍有副本；未经核实不批量删除其他数据。
6. 如果凭据确实被非授权人员接触，单独批准密码重置/会话撤销/云密钥轮换方案。删除日志不能让已泄露凭据恢复安全。

## 验收

- 只读盘点前后记录内容与数量不变，报告只含日期和计数。
- 新注册、密码重置、认证失败和队列失败只产生无敏感载荷的审计信息。
- 未授权时停止在盘点与方案阶段；报告必须注明历史数据尚未处理。
