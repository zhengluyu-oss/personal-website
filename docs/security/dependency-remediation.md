# Dependency security evidence

Review date: 2026-10-03. Owner approved Spring Boot 4.x compatibility migration, Java 17 retained. No production deployment.

## Reproduce the inventory

Use Maven `dependency:tree -DoutputFile=target/security-dependencies-after.txt` with the same POM used to package the JAR. Run:

```powershell
python scripts/security/dependency_inventory.py --jar blog-backend/target/blog-backend-0.0.1-SNAPSHOT.jar --maven-tree blog-backend/target/security-dependencies-after.txt --output blog-backend/target/security-dependencies-after.json --osv
```

This reads actual nested runtime JARs and the blog and admin pnpm lockfiles. Output includes hashes, coordinates, unresolved items and advisory identifiers. OSV receives only public package names/versions. It does not receive code, configuration or credentials. `unresolvedJarEntries` must be zero; any pagination flag needs further review. A coordinate match is not a demonstrated exploitable route. Builds/tests and manual reachability review remain mandatory. Reports in `target` are generated and may be overwritten by a clean build.

| --- | --- | --- |
| Spring Boot | 3.1.4 → 4.0.8 | Maintained Java 17 baseline; [official migration guide](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide). Transitional 3.5.16 compilation passed, not used as final supported release. |
| MyBatis-Plus | 3.5.3.1 → 3.5.17 Boot 4 starter | [Official compatibility guidance](https://baomidou.com/getting-started/install/); remove duplicate MyBatis starter, explicitly include pagination parser. Upstream moved IService/ServiceImpl imports to spring packages; business method bodies unchanged. |
| Springdoc / Knife4j | Boot 3 starter → springdoc 3.0.3 + Knife4j UI 4.5.0 | [Springdoc Boot 4 matrix](https://springdoc.org/), [Knife4j pure UI compatibility](https://doc.xiaominfo.com/docs/quick-start/start-knife4j-version). Existing doc.html asset and OpenAPI configuration retained; full docs HTTP acceptance still pending. |
| Tomcat | 10.1.13 → 11.0.26 | Public HTTP ingress. Boot's 11.0.24 baseline predates additional [official security fixes](https://tomcat.apache.org/security-11.html), including request interpretation issues. Override the whole managed Tomcat family. |
| Jackson | 2.15.2 → 2.21.7 and 3.1.7 | MVC now uses Jackson 3; Jackson 2 remains for third-party libraries. Both BOMs overridden together for post-Boot fixes: [core advisory](https://github.com/FasterXML/jackson-core/security/advisories/GHSA-7hhh-6rmp-j9qf), [databind advisory](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-cxp5-3px4-pw24). Specific exploit conditions vary; no assumption that every parser mode is used. |
| RabbitMQ Java client | 5.17.1 → 5.37.0 | Email/audit queue boundary. [Maintainer release notes](https://github.com/rabbitmq/rabbitmq-java-client/releases/tag/v5.37.0); includes parser hardening and TLS updates. No real mail or production broker used in tests. |
| c3p0 | 0.9.5.4 → 0.14.2 | Quartz configurable JDBC pool. [Maintainer security note](https://www.mchange.com/projects/c3p0/) explains removal/locking down of deserialization gadget paths. Do not re-enable unsafe compatibility switches. |
| OkHttp | 4.10.0-RC1 → 4.12.0 | Existing outbound streaming requests; moves off release candidate and old Okio dependency. Keep 4.x API for minimal changes; audit resulting Okio as well. |
| Fastjson / Hutool | 2.0.25 / 5.8.16 → 2.0.65 / 5.8.47 | JSON/cache and general utility runtime paths; preserve serialized cache contracts through tests. No AutoType enablement added. |
| Aliyun OSS SDK | 3.18.1 → 3.18.5 | [Upstream release](https://github.com/aliyun/aliyun-oss-java-sdk/releases/tag/3.18.5); align old transitive core SDK dependencies. Storage tests must use doubles; real object operations are not authorized. |

Security overrides should be removed only when a later Boot BOM manages equal/newer repaired versions and regression tests pass. “Latest BOM” alone is not proof of zero known advisories.

The OSS SDK also brings OpenTelemetry API transitively. Override its BOM to 1.66.0 for the maintainer's [baggage parsing resource-limit fix](https://github.com/open-telemetry/opentelemetry-java/security/advisories/GHSA-rcgg-9c38-7xpx), rather than relying only on gateway header limits. OSS 3.18.5 no longer brings the old ini4j dependency seen in the baseline package.

Rabbit compatibility: retain the existing serialized Map/Log/LoginLog wire format using an exact class allowlist, 256 KiB message limit, depth/reference/array limits, and fixed conversion errors. No blanket deserialization trust switch is enabled. Unexpected or oversized legacy messages fail closed; operations must inspect counts in a restricted environment instead of disabling the policy or dumping payloads. Existing log consumers continue sanitizing legacy log fields before persistence.

## Frontend scope and outstanding review

The owner approved pnpm-only on 2026-10-03. The duplicate blog npm lock was removed (recoverable from Git). The blog pins pnpm 11.3.0, matching its existing v9 lock; admin retains pnpm 8.10.0 and its v6 lock. Run `corepack pnpm` from each project directory to select its declared version. The deployment build now always installs with `--frozen-lockfile`, even when node_modules exists, and stops on manifest/lock drift. Corepack must be available on the local build machine; no global package-manager replacement or production installation was performed. Historical npm-inclusive audit counts cannot be compared directly with the new pnpm-only inventory.

Frontend upgrade, advisory reachability classification, final re-audit and all acceptance remain open. Raw baseline counts are not vulnerability counts. No residual vulnerability has been accepted by the owner through this document.

Baseline matches include GOST counter reuse, name-constraint bypass, LDAP injection and ASN.1 depth-limit bypass; use of those specific cryptographic paths has not been demonstrated in this application.

- Current backend JAR packaging and private-config/resource scan passed. Backend targeted `*Test` suite passed 131 tests with zero skipped after restoring the disposable local MySQL/Redis containers. An earlier attempt failed because Docker was stopped; a separate unit-only run skipped 25 integration tests and is not the integration acceptance result. The full application `BlogBackendApplicationTests` smoke test is outside `*Test` and has not passed this migration's full startup gate.
- Frontend tests: blog 45, admin pagination 2, admin safe preview 3, email-settings component 3; all passed. Inventory tests 5 and pnpm deployment-policy tests 2 passed. PowerShell parsed successfully; deployment script was not executed. Both dist resource/secret scans passed.
