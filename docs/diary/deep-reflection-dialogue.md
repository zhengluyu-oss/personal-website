# 日记深入复盘对话

## 使用方式

“问日记”在所选范围检索相关片段，适合具体问题；“做复盘”读取预览的完整日记，支持可选自定义问题和后续追问。最近七天是用户主动选择的范围，使用北京时间；筛选时间轴仍由用户确认。按内容日期会排除未填日期的篇目，跨日篇目读取全文但不推算逐日次数。预览展示篇目、内容日期与数量；范围变化后必须重新预览。

提示词 v5 允许相关的跨记录联系、替代解释、待核实盲点及通用建议，不再要求问答分项数组为空，也不强制500字或1项假设/2条建议。事实依据、可能解释与一般性建议分别展示。新视角默认展开；引用仍可核对，合法引文不保证解释成立。

完整复盘首轮可携带可选question，旧null请求兼容。后续继续使用完整来源，保留首轮目标与最近8轮有界前文；优先保留用户原话与纠正，再压缩历史AI文本。用户补充用于理解和建议，不能伪装成日记原文。历史AI结论不能作为个人事实证据。引用目录按当前问题与用户前文选择相关句，并保留来源轮转和首尾覆盖。

## 输出与生命周期

`diary.ai.max-output-tokens` 默认及最大值为100000，可配置1至100000；这是最大输出额度，不要求写满，实际用量由供应商返回的usage记录。源正文的完整范围预算仍单独检查，不能用增加输出额度绕过输入预算。

生成等待默认1800秒、配置最多3600秒，向量调用仍采用原短超时。等待期间每15秒检查账号、任务、来源并续租；完整响应先记录可得用量，再由worker与最终事务核对发布资格。跨午夜完成时确保完成日期的用量行存在，调用次数仍按开始日期预留。取消或失效停止本地等待，不保证供应商已停止计费；不会自动重试、续写或重发未知任务。HTTP不占用数据库连接等待。总响应16MiB、正文与结果1600000 Unicode字符、观察/假设等数组1000项是独立的内存安全界限；建议最多20条以兼容现有人工采纳索引0至19，不要求填满。引文长度和来源类型校验保持。

接口依据（2026-10-29）：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)允许max_tokens至393216，当前100000在有效范围。思考开关沿用显式配置；不会因本次扩大额度自动开启。

## 发布与回退

无数据库迁移，不修改历史报告、不重放旧任务。发布须同时更新后端和前端，并备份旧构建及受限配置。生产现有显式800优先于新默认；发布时需在原受限外置配置中更新下面三个非秘密字段，其他凭据/白名单沿用实际配置：

```yaml
diary:
  ai:
    max-output-tokens: 100000
    generation-timeout-seconds: 1800
    max-response-bytes: 16777216
```

长回答可能增加等待时间和单次费用，每日生成次数预算保持。回退恢复应用构建与配置；新报告JSON沿用原结构，原报告仍可阅读。

## 验收

使用合成资料验证完整篇目、问题恢复和幂等、连续11轮复盘、用户条件纠正的上下文、长正文/建议的接受及非法引用拒绝、慢请求心跳与取消，以及页面的完整预览和模型文本安全呈现。不得将这些结构和流程检查宣称为真实模型语义质量证明。

真实质量应以同一组本人主动选择的资料和问题比较：范围是否完整、有无相关而有解释价值的新视角、推测是否清楚、建议能否适配现实条件、追问能否修正。更长或格式正确均不能代替这些标准。本次实施不调用付费模型，不读取真实私人日记，不修改线上配置。
