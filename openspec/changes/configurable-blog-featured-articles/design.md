## Context

博客聚合页当前直接把公开文章查询结果的第一项渲染为大型主推荐卡片；分类页也依赖列表第一项，且分类查询缺少明确的公开状态约束与稳定排序。文章实体已有 `isTop` 字段，但该字段支持多篇文章同时为真，并被现有推荐文章接口使用，因此无法同时准确表达“全站唯一聚合页推荐”和“每个分类唯一推荐”。

本变更横跨数据库、Java 后端、Vue 管理端和博客前端。配置必须对旧数据保持兼容，并在所选文章失效时保证公开页面仍有稳定结果。

## Goals / Non-Goals

**Goals:**

- 允许管理员明确选择 `/blog` 唯一的聚合页主推荐文章。
- 允许管理员为每个文章分类独立选择唯一的分类页主推荐文章。
- 只允许已发布且符合范围约束的文章成为主推荐。
- 在配置缺失或失效时按发布时间稳定回退，并避免主推荐在普通列表中重复。
- 保持现有 `isTop` 推荐业务及文章路由不变。

**Non-Goals:**

- 不重做博客聚合页或文章卡片的视觉设计。
- 不改变文章详情页路由、分类 slug 规则或后端现有 API 路径层级。
- 不支持多个聚合页主推荐、多个分类主推荐或手工拖拽排序。
- 不移除或重新定义现有 `isTop` 字段。

## Decisions

### 1. 将页面推荐存储在页面所有者上

网站信息增加可空的 `blogFeaturedArticleId`，文章分类增加可空的 `featuredArticleId`。全局推荐属于博客页面配置，分类推荐属于分类配置，而不是文章自身的通用状态。

选择该方案是因为单值引用天然保证每个作用域至多一篇，后台操作不需要先清除其他文章标记。替代方案是在文章上增加多个布尔字段，但这需要额外事务保证唯一性，并使全局与分类语义继续耦合；复用 `isTop` 则会影响已有推荐接口，因此不采用。

### 2. 数据库引用可空，应用层执行有效性校验

两个字段均允许为空，并通过迁移新增，不回填旧数据。保存配置时，后端验证文章存在且已发布；分类推荐还必须验证文章属于目标分类。删除、取消发布或移动文章时不要求同步清空引用，读取端会把无效引用视为未配置。

这样可以降低文章更新操作与配置表之间的耦合，并使部署可回滚。代价是可能保留悬空配置值，但公开页面不会使用它，管理员重新保存即可修复。

### 3. 公开读取返回显式的主推荐与普通列表

聚合页和分类页的数据服务在读取时解析有效主推荐：先读取配置文章，校验失败时选择对应范围内发布时间最新的已发布文章。普通文章列表排除最终选中的主推荐文章，并继续按发布时间倒序分页。

优先通过现有文章列表响应增加清晰字段或新增聚合展示 DTO，避免前端再假设 `articles[0]` 是主推荐。具体接口形式在实现时遵循项目已有控制器和 DTO 风格，不触及文章详情路由。

### 4. 后台使用受约束的可搜索文章选择器

网站管理提供“聚合页主推荐文章”单选搜索控件，候选为全部已发布文章；分类管理提供“分类推荐文章”单选搜索控件，候选仅为当前分类已发布文章。两个配置都允许清空，清空表示采用自动最新文章策略。

候选查询复用现有文章管理查询能力；若现有接口无法安全表达筛选，则增加最小化的管理端候选查询 DTO，而不加载文章正文。

### 5. `isTop` 保持原有语义

文章发布页和文章管理列表中的现有置顶/推荐字段不作为页面主推荐来源。本变更在后台采用“聚合页主推荐”“分类页主推荐”的明确文案，减少管理员把三种用途混淆的风险。

## Risks / Trade-offs

- [数据库中可能保留已失效的文章引用] → 公开读取始终校验发布状态和分类归属，并自动回退；管理端展示失效提示或空值。
- [新增引用字段的数据库外键会阻碍文章删除] → 字段可空并采用适合现有数据库能力的 `SET NULL`，若项目迁移体系不稳定则仅建立普通索引并由应用层校验。
- [一次响应中重复查询推荐文章和列表] → 通过批量/定向查询、仅选择卡片所需字段，并在服务层统一解析，避免 N+1 查询。
- [分页总数因排除主推荐而产生歧义] → 总数表达当前范围内全部公开文章数量；普通列表仅排除当页上方已展示的主推荐，前端文章总数仍保持真实。
- [旧前端仍依赖列表首项] → 后端与前端在同一次部署中升级，并保持未配置时的回退行为与当前视觉结果一致。

## Migration Plan

1. 为网站信息和文章分类增加可空的推荐文章引用字段及必要索引。
2. 部署后端实体、DTO、校验和公开读取逻辑；空值时继续自动选择最新文章。
3. 部署管理端配置控件与博客前端显式主推荐消费逻辑。
4. 验证 `/blog`、所有分类 slug 页面、未配置状态、失效配置和空分类场景。
5. 上线后由管理员选择聚合页及各分类推荐文章。

回滚时先回滚前端和后端应用版本；新增可空字段可以保留，不影响旧版本运行。确认不再需要后再单独删除字段，避免不可逆数据丢失。

## Open Questions

- 无。默认聚合页和分类页推荐相互独立，且均允许清空后回到自动最新策略。
