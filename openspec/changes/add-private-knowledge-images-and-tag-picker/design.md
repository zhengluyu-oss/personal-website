## Context

知识库后台 `index.vue` 使用原生 `select[multiple]` 和 `textarea`，博客发布页则使用现有 `MdEditor` 的图片上传回调。知识库原始附件使用 PostgreSQL 元数据、私有 OSS 对象和鉴权下载；前后台预览净化器目前删除全部图片。现有清理任务会删除未登记的旧 OSS 对象。本次设计基于 [proposal.md](proposal.md)，不得把知识库图片送入博客公开上传路径。

## Goals / Non-Goals

**Goals:** 直接勾选标签；在 Markdown 编辑区粘贴、拖放或选择图片；正文与历史版本在授权阅读时显示私有图片；失权后无法再读取；完整处理上传失败、弃用图片、清理和回退。

**Non-Goals:** 公开分享知识库图片、OCR、图片搜索、图床迁移、自动发布博客文章，或改变原始 DOCUMENT 文件解析流程。

## Decisions

1. 后台使用项目已有 `MdEditor` 和 `onUploadImg` 回调，复用博客发布页的交互方式与现有图片压缩工具。标签用复选框呈现，限制 20 个；已选标签始终可取消。上次会话已有一处未提交的复选框本地修改，实施时先核对并完善它，不覆盖其他工作区改动。
2. 新增知识库专属图片元数据表，以 `owner_id + image_id` 为主键，记录条目归属、对象键、MIME、字节数、创建时间和清理状态。表强制 RLS 并纳入知识库运行角色的最小权限、结构健康检查及备份。上传必须属于已保存且未删除的条目；编辑器在首次粘贴前先保存当前新条目，避免无主对象。不能用公开博客 OSS URL 或 base64 正文替代。
3. 上传端只接受经内容检测的 JPEG/PNG/WebP，限制单图大小、像素和条目总量；先写私有 OSS，再登记元数据，登记失败删除对象。图片引用使用应用内部的 `knowledge-image:<UUID>` 标识写入 Markdown，不持久化临时签名 URL。服务端读取按图片 ID 找归属条目并实时调用知识库阅读授权，同时核对条目未删除；响应为正确图片 MIME、`private, no-store`、`nosniff`。
4. 浏览器不能在普通 `<img>` 上可靠附加现有 Bearer 令牌。前后台阅读组件只识别内部图片标识，以带令牌请求取得 Blob，创建短期 object URL 并替换渲染结果中的图片地址；切换条目、失权或卸载时撤销 object URL。净化器继续删除外部图片、SVG 及其他主动媒体，仅允许已识别的内部 Blob 图片显示。令牌不写入 URL、Markdown 或 DOM 属性。
5. 图片元数据保留到所有正文和历史版本不再引用。定期清理只删除过宽限期且未被当前正文或保留的历史版本引用的图片；同一对象不得在数据库标记完成前被视为可重传。现有 OSS 孤儿清理要将图片表对象键计入已登记对象。删除条目后的图片随条目保留/回收规则处理，清理失败可重试。

## Risks / Trade-offs

- [私有图片泄露] → 服务端逐次鉴权、私有 ACL 探针、无签名 URL、无缓存及失权测试。
- [上传成功但正文未保存] → 登记后保留宽限期，编辑器给出明确状态，定时清理无引用对象；上传重试使用请求标识防重复。
- [跨库或上线顺序不一致] → 先备份并迁移 PG，再发布后端，最后发布管理端和博客端；旧端忽略新图片标识但继续可读文本。
- [富文本注入和外部跟踪] → 只解析内部图片标识，延续 HTML 净化；不允许外部图片在知识库预览中自动加载。
- [历史版本扩大存储] → 总量上限、配额核算和历史引用检查；不为显示图片而修改历史正文。

## Migration Plan

1. 在隔离 PG 上重复执行迁移并验证 RLS、索引和运行角色权限；备份线上知识库 schema 与 OSS 对象清单。
2. 线上先执行增量迁移并核对结构，再发布后端、后台和博客前台；验证站主粘贴、授权读者阅读、匿名及撤权拒绝、旧条目和原始附件不受影响。
3. 回退时先回滚前端和后端产物，保留新表及对象供恢复；确认引用与备份后再考虑清理。本次不自动删除生产图片或回滚 schema。

## Open Questions

无阻塞问题。实施时以现有知识库正文大小、OSS 配额和部署配置确定更严格的图片上限，并在接口与界面保持一致。
