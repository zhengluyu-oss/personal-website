## Context

树洞页面通过 `ossUrl('blog/TreeHole/TreeHole-back_compressed.webp')` 设置整屏背景。该对象在线上返回 404，而页面标题、输入框和按钮都以白色文字叠在透明背景上。320px 与 1440px 实测均出现浅色空白背景上的低对比度文字。现有 `mobile-layout` 规格已要求 320px 的输入与提交控件不产生整页横向溢出。

## Goals / Non-Goals

**Goals:**

- 树洞在背景资源不存在或加载失败时仍有稳定、可读的视觉呈现。
- 手机与电脑端的标题、输入内容、占位文字、提交按钮和焦点状态易于辨认。
- 保持当前留言、弹幕及小屏输入行为。

**Non-Goals:**

- 不调整树洞提交 API、数据结构、审核规则或权限。
- 不全面重做树洞交互或其他页面的视觉设计。
- 不把未启用的音乐页面和登录后后台页面纳入本次修复。

## Decisions

1. **移除失效的 OSS 背景引用，使用已有品牌色变量组成页面背景。** 当前没有可验证的同款背景资源；直接换一个未经确认的远程图片仍会有失效风险。纯 CSS 背景随前端发布，避免树洞核心可读性依赖外部对象。若后续恢复图片，可在不改变前景对比度的前提下增加装饰层。
2. **前景使用品牌文字色和实色或足够不透明的表面色。** 标题、输入文字、占位文字和提交按钮均采用与背景明确区分的颜色；输入框不再依赖背后图片形成对比。复用现有语义变量，保留可见的键盘焦点样式。
3. **保持现有布局结构与响应式尺寸。** 只改树洞页面必要的样式和失效资源引用。实施前按项目要求执行 GitNexus impact；完成后在 320px、375px、768px 和 1440px 验证可读性、输入聚焦后提交控件的可见性，以及没有整页横向溢出。

## Risks / Trade-offs

- [背景由图片改为品牌色后视觉氛围会变化] → 与站点现有品牌色保持一致，优先保证信息可读；实施时检查手机和电脑截图。
- [弹幕文字原本依赖深色背景] → 同时检查弹幕文本、头像与背景的对比度，必要时使用局部表面层，不改变弹幕数据和行为。
- [线上缓存仍可能短时保留旧页面] → 发布后核对 `/tree-hole` 实际样式与资源请求；回滚前端构建即可恢复旧版本。

## Migration Plan

无需数据迁移。按现有前端发布流程部署，核对线上树洞不再请求失效的图片、两类视口内容可读；如需回滚，恢复上一版前端构建。
