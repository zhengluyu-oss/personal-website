## Context

本站以个人展示为首要用途，博客承担技术表达与可核验内容的作用。当前 Vue 3 / TypeScript / SCSS 博客端已具备可配置首页、真实文章与经历、公司下的项目展示，以及统一浅色与蓝色品牌。此次调整复用这些能力，不另建作品集数据系统。

本轮代码审查确认了：首页首屏多层文案竞争；关于页使用过大的名字与视口高度分区；经历索引的岗位字级强于公司；910px 时桌面与手机导航同时隐藏；全局自定义右键替代原生操作；项目无目录时仍保留双栏网格，正文可能落入窄栏。浏览器视觉检查未能完成，因此这些判断中的视觉取舍仍需实施阶段的真实渲染验收，不能将本规划当作已通过截图验收。

存在两份相关未完成规划：`refine-home-and-career-presentation` 的展示意图由本变更整合，不叠加执行、不自动归档；`add-experience-project-showcase` 继续负责既有项目能力及其未完成的后台联调与端到端验收。本变更只细化公开展示。其中旧项目变更“公司背景→职责→项目”的展示顺序由本变更的“核心履历→项目目录→补充说明”取代。将来归档同步规格时必须核对这一先后关系，不能让旧展示 delta 覆盖新层级。

## Goals / Non-Goals

**Goals:**

- 首页在保留真实配置的前提下建立更清楚的姓名、职业方向、代表内容与行动入口，允许局部、轻量、短暂的视觉表现。
- 经历聚合页、公司经历页、项目页保持专业阅读界面，清晰表达“经历聚合→某段公司经历→该经历的项目”。
- 关于页承接个人介绍与公开联系路径，不展示不存在的渠道或简历。
- 修复已确认的导航、原生右键和项目无目录布局问题，并补齐对应回归验收。

**Non-Goals:**

- 不改变数据库、公开 API、后台编辑表单、权限或发布流程；不改既有 URL、导航名称、SEO 输出。
- 不创造项目、职责、成果、客户、统计、推荐理由、邮箱或简历；不删除同标题文章，不写生产数据或替换生产媒体。
- 不引入动画框架、新字体服务、新主题切换、粒子、自动轮播、滚动劫持或全站视差；不扩展到文章详情重设计。
- 不自动部署、提交代码或归档其他变更；不替原项目变更宣告其后台验收完成。

## Decisions

### 1. 同一品牌下分开控制视觉强度

继续复用当前浅色、蓝色强调、字体、间距和容器变量。首页首屏采用文字主导的不对称双栏：姓名是主标题，职业方向次之，说明与真实介绍形成较轻的阅读层；右侧保留唯一 Banner 作为辅助视觉。通过留白比例、对齐和轻量局部色面形成辨识度，不用整屏图片、装饰边框或重复口号争夺注意力。首屏以下逐步回到清晰的内容列表。

经历三级页面不继承首页的装饰动效；以公司、项目名称和正文为视觉中心，只保留必要的焦点、按压与状态反馈。关于页使用同一排版语言但不复制首屏的动画舞台。

**备选与取舍：** 全站统一加入动效会削弱经历阅读；全站完全静态无法满足首页适度表现的目标。采用首页组件局部样式与逻辑，避免全局动画选择器泄漏。

### 2. 首屏重新组织信息，不删改有效配置

保留后台首屏眉题、姓名/标题、职业定位、价值说明、简介与说明组的有效内容及其语义。减少同级大字号，长说明移至介绍邻近的辅助区域，小屏并入自然内容流；不以裁切、隐藏、替换为营销口号的方式“精简”。首屏高度由内容决定，长中文允许自然换行，不能强制两行截断。

两个按钮配置都不完整时，默认主按钮“查看工作经历”指向现有经历一级路由，次按钮“阅读博客”指向现有博客一级路由。有任何完整配置时沿用现有配置优先、只展示完整组的规则，不擅自调换站长配置的顺序。Banner 继续选择接口首张非空图片，保留比例预占、加载失败占位和无需等图即可使用的文字入口。

**备选与取舍：** 固定新口号或强行替换按钮虽能统一截图，但会破坏现有配置能力，因此仅改变默认值与视觉层级。

### 3. 首页动效是渐进增强

使用 CSS 与小型局部逻辑，不新增依赖。首页首屏允许一次轻微入场，单项时长不超过 500ms，整体错峰在 900ms 内结束；姓名与主要操作从初始渲染即可识别、操作，不能等待图片或动画结束。对具备精细指针且支持悬停的桌面设备，辅助视觉层可跟随指针做最大约 6px 的轻微平移；不移动主要文字或按钮，不采用持续循环或滚动驱动视差。

小于 768px、粗指针/无悬停、`prefers-reduced-motion: reduce` 时完全静态。监听偏好变化并即时复位；离开首屏或路由卸载时取消帧请求、解绑监听并清理样式。事件更新至多每帧一次，使用 transform，不逐事件触发布局测量。默认 CSS 为可见状态，动效初始化失败仍可阅读。进入页面、减少动画与重复导航纳入验收。

**备选与取舍：** 动画库和复杂 3D 提供更多表现，但增加资源与维护成本，本轮需求不需要。

### 4. 代表内容只从现有真实数据中选取

保留顺序：身份与入口→简短真实统计→代表经历→精选文章→近期文章→关于/已知公开渠道。经历沿用现有顺序和上限，不逐公司追加项目请求来拼装首页作品墙。

精选按现有推荐顺序取最多两篇有效且不同 ID 的文章；有两篇时一主一次，只有一篇时不预留空卡。推荐为空或失败时取最新首篇作为单篇降级精选。近期列表排除所有已精选 ID，自身按 ID 去重后最多五篇，保留原接口顺序；不按标题去重。同 ID 的数值/字符串表示需规范化到一致比较值，缺少可用详情 ID 的项不生成假链接。保持选择工具为纯函数并扩展现有测试。

摘要优先使用接口已有有效摘要；需要正文降级时复用现有安全的纯文本摘要流程，去除围栏代码、Markdown 标记及重复空白后按长度截取，不把代码残片、图片地址或 HTML 当导读，也不改写事实或自动生成推荐理由。经历缺乏摘要时保留公司、岗位、时间等可核验元数据，省略空摘要与装饰性占位。统计未知值不能伪装成 0。各区块继续独立加载与失败降级。

封面使用稳定比例且不遮挡文字，遵循现有媒体完整显示约束；首屏图保留优先加载，屏外图片沿用延迟加载。最多两篇精选是上限，不是必须补齐的配额。

**备选与取舍：** 新建人工精选系统或项目聚合接口超出本次展示调整；使用已有推荐与最新接口足够，并可避免新增请求链。

### 5. 关于与联系从真实身份延伸

重构关于页的巨大名字和固定 `60vh/40vh` 分区为内容驱动布局，保留真实介绍、头像、GitHub 个人主页与源码仓库入口。个人主页和源码仓库用不同文字明确用途，不重复两个含义不明的大图标。沿用已配置的真实职业介绍，不自行把“求职中”换成未经确认的职业状态。

本轮不增加后台字段；在现有前端 `config/site.ts` 增加可选公开联系链接列表及可选简历地址，默认空。现有已知 GitHub 渠道继续有效。新增链接需有清楚标签与合法地址：联系允许 HTTPS 或显式配置的 mailto，简历允许站内资源路径或 HTTPS；拒绝危险协议、协议相对地址与控制字符。不得从提交记录、后台私有字段推断公开邮箱；未提供简历时不出现“下载简历”占位或失效按钮。新窗口链接遵循现有安全属性规范。

**备选与取舍：** 后台维护更灵活，但涉及额外契约与表单；前端可选配置满足当前范围，未配置也能完成此次展示优化。

### 6. 公司是经历主体，项目是下一层入口

聚合页每条仍为清晰可点击的索引行，公司名使用条目主标题，岗位和时间为次级元信息；装饰性 CASE 编号不再是必需信息，不以巨型岗位文字压过公司。不按公司名称合并数据：即使同公司有两段任职，也按独立经历 ID、周期及所属项目保留各自入口。

公司经历页先呈现公司、岗位、时间和可用简述，再展示该经历的项目目录，随后为职责、成果和旧 Markdown 等补充内容。合并重复渲染的同一字段，不做语义猜测式删除；没有项目时紧凑说明并继续显示真实经历资料。保留现有项目公开过滤与父子归属校验，复用已经有效的独立加载和重试逻辑；若当前公司主体与项目请求仍共享整体失败状态，需在前端拆开主次加载状态并补齐项目局部重试，避免项目失败使正常公司资料不可读，不改公开接口。

项目页保留概览、贡献、成果和安全渲染正文。是否启用目录列取决于渲染后实际可用的目录项，复用 Markdown 组件现有目录事件/状态，不能用扫描原始文本的简单正则将代码围栏误当标题。没有 Markdown 或没有目录标题时，显式切换为居中的正文单列；有目录时桌面用目录与正文双栏，小屏目录按现有折叠形式进入内容流。所有模式都不得让正文自动落入 14rem 窄栏，也不删除没有正文但有贡献/成果的项目资料。保留面包屑、同公司项目导航和深链接。

**备选与取舍：** 永久保留空目录列便于 CSS 简化但浪费空间且已有错误；按实际目录状态切换布局更符合内容差异。

### 7. 修复导航与原生浏览操作

保持已有路由与菜单名称，统一桌面/手机分界：宽度大于 910px 使用桌面导航，小于等于 910px 使用手机入口；不能出现两者同时缺失。手机抽屉沿用现有组件，用受视口约束的可读宽度替代固定 40%，建议最大 22rem、两侧保留安全间距，交互目标至少 44px。抽屉打开后正确管理焦点、Escape/遮罩关闭及返回触发按钮的焦点。

可导航项使用具有真实 href 的 RouterLink/链接；展开控件使用按钮。父项同时可访问页面和展开子项时使用独立链接与按钮，不以可点击 div 承载两种行为。保留动态分类子导航，提供 hover、focus-visible、当前路径与 `aria-current` 反馈；子菜单通过 Tab、Enter/Space、Escape 可操作，展开状态使用 `aria-expanded`。嵌套路由的父导航可有视觉当前分组提示，不能把多个链接都声明为当前页面。

移除博客端 App 对全局自定义右键菜单的挂载/初始化与页面级阻止默认事件，恢复链接新标签、复制地址、文本选择和浏览器菜单；不顺手删除可能被其他地方使用的组件。检查全局监听与样式以确保恢复生效，不只隐藏自定义菜单外观。

**备选与取舍：** 仅修复媒体查询无法修复键盘与浏览器原生链接行为，故同时处理语义与焦点；不改现有信息架构。

### 8. 验证范围与资源边界

实现位置主要为 `blog-frontend/kuailemao-blog` 的 Home、About、Experience、Header/Menu、App、site 配置及现有展示工具。改动前执行 GitNexus impact，报告调用方、流程与风险；UNKNOWN 必须补充文本核验，HIGH/CRITICAL 必须先提示风险。保留用户已有未提交修改。

运行现有 `npm test`、`npm run check:routes`、`npm run build`，沿用构建压缩体积检查：初始 JS gzip ≤700KB、CSS gzip ≤180KB、单个 JS gzip ≤450KB，不将编辑器、音乐或图表依赖带入首页入口。按现有性能规格在冷缓存、约 3Mbps 移动网络下验收 FCP ≤2.5s、LCP ≤4s、CLS ≤0.1，并记录实际环境，不能仅以构建成功声称通过视觉或运行性能验收。

真实浏览器至少检查 360、390、430、640、768、899、900、909、910、911、1024、1440px，重点页面使用不同视口高度验证不被固定高度裁切。覆盖长中文、超长 URL、图片失败、0/1/2 条精选、同 ID 重复、同标题不同 ID、稀疏经历、同公司不同任职、项目无正文/无标题/有标题、独立接口失败、减少动画、纯键盘和右键。使用本地测试数据或请求替身，不改线上记录。工具不可用时明确标记未验证项，不勾选对应任务。

## Risks / Trade-offs

- [已有规划重叠，旧 delta 可能回盖新展示顺序] → 实施前核对，旧草案不重复执行；归档同步时确保本变更的公司优先与项目提前语义最终生效，后台剩余责任保留给原项目变更。
- [较长后台文案使首屏变高] → 接受内容驱动高度，缩小辅助字号并自然换行，不隐藏内容来追求固定截图。
- [新增精选数量让首屏以下拥挤] → 限制最多两篇、一主一次，资料不足收缩，不新增装饰卡片或额外请求。
- [指针反馈增加处理成本或造成不适] → 限制幅度、设备与区域，按帧合并、及时清理，减少动画时完全停用。
- [“联系”入口暗示并不存在的联系方式] → 默认沿用已知公开渠道，新渠道与简历均为空且不显示，不补造地址。
- [目录在 Markdown 渲染后才更新] → 以单列作为安全初态，依据实际目录项切换；检查异步更新及项目间切换不残留旧目录。
- [移除自定义右键同时移除站内便捷功能] → 主导航保留全部现有目的地，必要功能仍从原有标准入口访问；不保留全局右键拦截。
- [当前无法取得浏览器截图] → 将真实视觉与交互检查列为实施验收必做项，未执行时如实报告而非默认通过。

## Migration Plan

1. 核对工作区与两个相关未完成变更，只实施本任务内的前端展示调整；先完成纯函数和状态回归测试，再更新首页、关于、经历与公共交互。
2. 无数据库、API、生产数据迁移。新联系配置默认为空，现有 Banner、首屏配置和链接继续工作。
3. 完成自动化、视觉、交互与性能验收后交付本地改动及证据；部署与 Git 提交需另有授权。任何提交前必须完成 GitNexus detect_changes 且无 partial/truncated 未解结果。
4. 如需回退，仅撤回本变更对应的前端改动与新增可选配置，保留用户其他修改；不触碰项目数据或其他变更文件。
