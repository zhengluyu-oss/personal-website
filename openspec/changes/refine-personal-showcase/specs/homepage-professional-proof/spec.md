## MODIFIED Requirements

### Requirement: 专业证明选择可预测且不重复
系统 SHALL 使用确定性规则从现有有效数据中选择代表内容，按可用文章 ID 规范化后的身份去重，同时保留接口顺序；同一文章 MUST NOT 同时占用多个精选位或相邻最新内容位。系统 MUST NOT 因标题相同而合并、隐藏或删除不同 ID 的文章，也不得为缺少有效详情标识的项目构造假链接。

#### Scenario: 推荐文章也存在于最新文章中
- **WHEN** 同一有效文章同时由推荐接口和最新文章接口返回
- **THEN** 页面仅在一个推荐位置展示该文章，并继续从最新数据中选择其他文章

#### Scenario: 推荐内容不可用
- **WHEN** 推荐文章为空、失效或请求失败
- **THEN** 页面使用有效最新文章作为降级内容，且其他首页区块仍保持可用

#### Scenario: 标题相同但标识不同
- **WHEN** 两篇有效文章具有相同标题但不同 ID
- **THEN** 页面将它们视为不同内容，按既有顺序与数量上限选择，不因标题重复过滤或修改记录

#### Scenario: 重复标识采用不同类型返回
- **WHEN** 接口重复返回同一文章的数字 ID 及等价字符串 ID
- **THEN** 系统将它们视为同一文章，只保留一个展示位置

## ADDED Requirements

### Requirement: 摘要以真实文本降级
首页文章与经历 SHALL 优先使用已有有效摘要；需要从正文降级时 SHALL 提取安全的纯文本导读、清除围栏代码与格式噪声并适度截取，MUST NOT 生成新的职责、成果、技术指标或推荐理由。经历缺乏有用摘要时 SHALL 保留真实公司、岗位与时间等元数据，省略空摘要而非填充无事实内容。

#### Scenario: 正文包含代码与 Markdown 标记
- **WHEN** 无有效摘要的正文包含围栏代码、图片地址、链接、HTML 或重复空白
- **THEN** 导读以可读纯文本显示，不执行 HTML，不将代码块、图片地址或格式标记作为主体摘要

#### Scenario: 经历只有基本信息
- **WHEN** 启用经历仅有公司、岗位、时间而没有有效摘要或正文
- **THEN** 首页紧凑展示可核验元数据与详情入口，不生成职责成果或空白摘要卡片

### Requirement: 首页代表内容复用现有请求边界
系统 SHALL 复用现有公开文章、推荐、启用经历与站点信息请求形成代表内容，不为了首页视觉补足项目数量而逐公司查询项目或新增数据接口。各区域 SHALL 保持独立加载与失败降级，未知统计 MUST NOT 作为真实零值展示。

#### Scenario: 经历请求失败但文章成功
- **WHEN** 经历数据不可用而文章数据已成功返回
- **THEN** 文章仍显示，经历区域提供紧凑且可恢复的状态，不阻塞整页或伪造经历

#### Scenario: 统计尚未加载
- **WHEN** 某项统计值尚未取得或请求失败
- **THEN** 等待时显示加载中，失败时显示暂不可用，不以 0 暗示实际数量
