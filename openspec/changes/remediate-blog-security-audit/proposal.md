## Why

安全审查确认，后台收藏预览、认证日志、邮箱换绑、OAuth 回调、文件删除及评论通知存在跨越信任边界的路径；构建产物也包含本地敏感配置。需要在继续扩展博客前封堵这些路径，并分辨依赖告警的真实可达性，避免把扫描计数误认为已确认漏洞。

## What Changes

- 修复后台收藏预览的存储型 XSS，统一不可信文本与受净化 Markdown 的展示边界。
- 对正常和异常审计链路执行结构化脱敏，提供历史敏感日志的只读盘点与经批准清理流程。
- 邮箱绑定和换绑要求匹配账号类型的再次认证；OAuth 登录结果绑定发起登录的浏览器，禁止链接静默替换现有身份。
- 增加经用户于 2026-10-02 批准的邮箱唯一索引迁移；先只读预检，重复数据阻止迁移，不自动删除或合并账号，不执行线上迁移。
- **BREAKING**：文章封面删除不再接受任意 URL 的 GET 删除，改为有权限、上传归属和引用校验的非 GET 操作；旧接口拒绝执行删除。
- **BREAKING**：友链邮件中的 GET 链接仅展示确认页，实际审批必须由具备权限的管理员提交；废弃旧时间戳凭证。
- 评论列表、回复关系与邮件通知统一验证目标可见性，收件人由服务器推导，禁止泄漏私密或未审核内容。
- 阻止本地敏感配置进入发布包，收紧生产构建、配置和依赖基线；按运行时可达性分批升级依赖。
- **BREAKING**：API 改为明确的公开白名单与默认拒绝；跨域请求限定来源。同步更新受影响的前端调用和部署配置。
- 增加实际文件内容校验和分阶段安全响应头策略，保留合法图片、现有视频上传及 Markdown 功能。

## Capabilities

### New Capabilities

- `sensitive-audit-data-protection`: 正常、异常、消息队列日志的最小化与脱敏，历史记录治理流程。
- `secure-account-actions`: 邮箱变更再次认证、浏览器绑定 OAuth、凭据变更后会话失效。
- `secure-link-mail-approval`: 高熵、限时、单次、带管理员权限检查的邮件审批流程。
- `secure-release-baseline`: 敏感配置与测试依赖不得进入生产包，依赖漏洞分级处置和发布验证。

### Modified Capabilities

- `safe-content-rendering`: 将安全渲染边界明确扩展到收藏和后台预览，包括历史恶意内容。
- `file-storage`: 增加内容校验、删除授权与归属约束，调整旧删除接口兼容约定。
- `comment-moderation`: 增加目标可见性、回复关系、通知隐私约束。
- `production-interface-hardening`: 增加显式公开接口清单、跨域白名单、安全响应头要求。

## Impact

- 后端涉及 User/OAuth、LogAspect/日志队列、Article/FileUploadUtils、Link/邮件队列、Comment/收藏及通知查询、Spring Security/CORS、Maven 打包；前端涉及用户安全设置、OAuth 回调、收藏预览、封面操作和审批确认页。
- 复用 Java 17、Spring、Redis、Vue 和既有净化/验证能力；不更换技术栈，不重设计内容数据库。新增短期 Redis 安全状态及命名空间，必要的数据结构变动必须另行说明，不默认引入新业务表。
- 发布配置涉及 Nginx、外置生产配置及部署脚本；需前后端协调发布。旧 OAuth 中间凭证、旧邮件审批链接和旧封面删除请求将失效，需要重新操作。
- 不降低管理员双因素认证要求，不主动缩短现有 24 小时登录有效期；敏感身份信息变更后要求重新登录。
- 本变更包含本地实现、回归测试及操作手册。生产部署、真实密钥轮换和历史日志删除须在说明目标、备份、风险与回退方案后获得操作授权，不因规划完成自动执行。
