## Context

首页中央标题与导航站点名共用 `websiteName`，内容重复且超大居中文字遮挡 Banner 的云层主体。网站信息已通过单表、统一接口和后台表单维护，适合在同一链路扩展首页专属文案。

## Goals / Non-Goals

**Goals:**

- 建立独立于全站名称的首页首屏内容模型。
- 提供足够多、但站长容易理解的配置项，支持介绍、行动按钮和侧栏说明。
- 采用左侧编辑式主内容与右侧轻量说明的不对称构图，保留图片视觉焦点。
- 所有可选区域在字段为空时自动隐藏，并为核心标题提供兼容默认值。

**Non-Goals:**

- 不提供任意拖拽排版或富文本编辑。
- 不允许后台写入任意 HTML 或 CSS。
- 不改变左上角导航、页脚和其他位置对 `websiteName` 的使用。

## Decisions

1. 在 `sys_website_info` 增加十个可空字段：`heroKicker`、`heroTitle`、`heroSubtitle`、`heroDescription`、两组按钮的文字/链接、`heroAsideLabel`、`heroAsideText`。相比 JSON 字段，显式列能沿用当前 DTO 校验和 Bean 映射，后台也更直观。
2. 主标题采用“你好，我是郑陆宇”作为前端回退值，不再回退到 `websiteName`。旧数据库或空配置时仍能正常展示且不会继续重复。
3. 首屏主内容放置于左侧安全区，右侧说明采用小型玻璃卡；移动端折叠为单列并隐藏右侧装饰分隔线。相比中央大标题，这能减少对图片主体的遮挡，并建立更成熟的作品集气质。
4. 按钮仅接受普通链接字符串，前台根据是否为站内路径选择路由/直接导航；字段为空时整组不渲染。描述按纯文本输出，避免注入风险。
5. 使用幂等 SQL 迁移逐列检查并新增字段，同时给当前记录写入默认内容。部署顺序为数据库、后端、管理端、博客前台。

## Risks / Trade-offs

- [新增列未先部署导致后端查询失败] → 部署文档和脚本明确要求先执行幂等迁移。
- [文案过长破坏布局] → DTO、后台输入框和 CSS 同时设置合理长度与换行上限。
- [外链配置错误] → 链接为空时隐藏，外链使用新窗口并增加安全属性。
- [配置项较多增加后台复杂度] → 单独使用“首页首屏文案”分区并给每项提供示例提示。

## Migration Plan

1. 执行 `sql/home-hero-copy.sql`，幂等增加字段并初始化默认内容。
2. 发布后端，使网站信息接口读写新字段。
3. 发布管理端和博客前台。
4. 通过后台修改一项文案并刷新首页验证完整链路。
5. 回滚前端/后端时保留新增可空列，不需要破坏性删列。

## Open Questions

无。布局和默认内容由本次设计确定，站长后续可在后台自由调整。
