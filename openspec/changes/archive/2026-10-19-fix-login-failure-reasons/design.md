## Context

前台与管理端共用 /user/login；Spring Security 完成密码验证后调用 SecurityHandler 的成功回调。管理员成功回调会创建邮箱挑战，AdminLoginChallengeServiceImpl.create 在 60 秒冷却期间抛出 BadCredentialsException。异常被登录失败回调覆盖为 code=1001 的密码错误。UserController 的重发接口同样将所有 BadCredentialsException 映射为验证码错误。

前台“重新登录”只清除浏览器内挑战状态，不解除服务端冷却；这是正常的限流边界，不应靠取消冷却解决。已有成功、验证失败及会话处理契约需要保留。

## Goals / Non-Goals

**Goals:**
- 将已通过密码校验后的验证码发送冷却、发送故障，以可信的业务原因传到两个登录界面。
- 给出安全、可执行的提示，保持失败时无 token、无假登录、无自动重发。
- 使用现有响应结构与状态码，兼容缺少新增字段的旧响应。

**Non-Goals:**
- 不改变密码、验证码、TTL、管理员二次验证及限流政策。
- 不解除返回登录页面后的冷却，不跨刷新恢复挑战，不重构登录页面。
- 不处理本次无关的邮箱输入长度问题，不直接显示全部服务器异常。

## Decisions

### 1. 用受控类型表达发送失败，不按异常字符串判断

引入轻量的管理员验证码发送异常，携带有限原因枚举（CODE_SEND_COOLDOWN / CODE_SEND_UNAVAILABLE）及可选 retryAfterSeconds；不要继续把预期发送失败混入普通 BadCredentialsException。使用异常类型/原因做白名单映射，不透传 exception.getMessage()。备选的“所有异常原文显示”会泄露内部错误且无法保证稳定。

### 2. 保持响应兼容

沿用 ResponseResult：冷却复用 REQUEST_FREQUENTLY(1004)，发送不可用复用 OTHER_ERROR(1008)；data 可增加 reason 和 retryAfterSeconds。msg 为服务端固定中文文案，例如“验证码发送过于频繁，请等待 42 秒后重试”。成功挑战及登录结果结构不变。读取 Redis 剩余 TTL 后向上取整；仅在 TTL 为有限正值时返回秒数，无有效 TTL 时用不带精确数字的安全等待文案。不得通过异常路径重置冷却或创建额外挑战。

### 3. 同一分类覆盖首次登录和验证码重发

SecurityHandler 在已通过密码/OAuth 验证的挑战创建边界捕获受控发送异常，以共享响应映射直接返回；失败回调同样识别该类型。这样不会再经由 OAuth 的通用认证捕获覆盖具体原因。UserController.resendAdminLogin 使用相同映射。明确验证密码成功之后发生的未知基础设施错误使用通用“登录服务暂不可用，请稍后重试”，不误报密码错误；实现时通过实际安全过滤链测试确认异常传递边界。

真正的错误密码、未知账号及不可安全披露的账号状态继续保持统一凭据失败。验证码错误、过期、已消费及耗尽仍遵循现有不枚举验证失败契约，不返回剩余猜测次数。

### 4. 两个客户端使用同一语义，不制造登录成功

审查现有 API 封装，确保业务失败 msg 没有在全局拦截器或页面中被固定“密码错误”覆盖，且每次请求只提示一次。倒计时可直接通过 msg 呈现，本次不要求新增复杂计时组件。首次登录失败保留密码表单；重发失败保留当前挑战与输入入口，不清除挑战或虚报已发送；真正的验证码验证失败仍按原规则清除输入。

### 5. 只记录安全的诊断分类

未知故障只记录阶段、受控分类及必要的异常类型，不记录密码、验证码、token、完整请求或上游响应。失败日志不能反过来覆盖已确定的业务结果。

## Risks / Trade-offs

- [统一处理仍吞掉新异常] → 通过实际 Spring Security 请求链覆盖“密码通过→成功回调冷却异常→失败响应”。
- [明确提示泄露账号状态] → 仅密码已通过的发送阶段返回冷却分类，其他凭据失败维持统一响应。
- [重发失败丢掉仍可用的验证码] → 客户端保留挑战，验证正确码仍可完成，测试确认不删除或刷新其 TTL。
- [TTL 边界产生负数或假倒计时] → 仅暴露有效正数并处理过期/缺失竞态，不承诺绝对发送时刻。
- [混合版本发布] → 保持 code/msg/data 结构和成功契约，旧客户端仍能从 msg 显示文案。

## Migration Plan

不需要数据库、Redis 全局结构或配置迁移。实现并测试通过后，发布后端及必要的两端前端资源，保留上一版回滚。生产验收使用本人登录验证，检查冷却窗口与窗口结束后的恢复；不得在验收记录中保存密码或验证码。本次 Propose 不执行发布。
