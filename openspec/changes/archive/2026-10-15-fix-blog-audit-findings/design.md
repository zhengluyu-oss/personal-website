## Goals / Non-Goals

**Goals:**
- 覆盖报告全部 11 项触发条件，改善身份、评论和对象存储的信任边界。
- 上传、删除和部署失败时保留正确的数据引用及可恢复版本，避免成功提示与实际结果不符。
- 保留既有模块角色、审核、管理员二次验证、首页视频、文章编号/URL和正常媒体功能。
- 默认检查无需真实凭据和生产基础设施，失败条件有自动化证据。

**Non-Goals:**
- 不重做后台布局、角色模型或上传框架，不新增数据库表和大型依赖。
- 不重写旧安全规划中的邮件消费、友链审批、CSP、依赖升级与历史日志治理。
- 不自动修复历史孤儿对象、删除旧 Redis 键、修改线上内容、推送或部署。

## Decisions

### 1. 请求目的地决定凭据，而不是调用了哪个客户端（F1、F9）

使用 URL 解析后的 origin 与受信 API 路径范围判定目的地，基准是页面 origin 和已配置 API baseURL。相对 API、绝对可信 API可附加凭据；外部 URL、协议相对外域、相似域名、非 API 路径不可附加。在不可信请求上同时排除默认或显式残留的博客 Authorization，不依赖 `startsWith`。

第三方一言等内容调用使用无身份客户端或现有独立 fetch；它的响应不能触发清除博客 token。仅博客认证接口明确返回认证失效、过期或损坏存储时执行清理。网络、超时、5xx、取消和普通 403 不等同于令牌失效：保留凭据，将资料标记为待恢复，隐藏依赖未确认资料的特权操作，允许重试成功后恢复。保持“成功保存凭据并取得用户信息后才宣布登录完成”的既有行为。

替代方案：只排除一言域名会遗漏其他外部调用；任何异常立即退出登录会制造误失效；失败后继续展示旧权限会产生错误操作入口。

### 2. 在评论服务校验解析后的目标，复用现有可见性能力（F3、F4）

复用 `SiteModuleAccessService` 和 `ContentVisibilityService`，在公开列表、计数和提交入口执行受支持类型、正数 ID、目标存在/公开状态以及对应模块规则。文章 JSON 提交从 DTO 读取 type，不在拦截器中重复消费请求体。保留管理审核的独立权限，但管理员前台操作也不能凭后台权限绕过私人目标的公开规则。

对 parent/reply 查询服务端记录，确认同目标、审核状态、未删除和有效线程关系；回复收件人由真实记录派生，冲突的 caller `replyUserId` 拒绝或按明确兼容规则核对。失败在保存、计数和调用通知前终止。文章公开转私人后，审核评论也不可经公开接口取得；不可见目标不返回标题/评论数量等泄漏信息。

替代方案：仅在 query 参数拦截无法保护 JSON；仅检查评论审核状态无法保护父目标。本轮不把通知消费时再次检查的旧任务宣称完成。

### 3. 临时封面删除与文章引用写入共享生命周期（F2）

封面上传成功后登记 Redis 临时授权：owner、规范 object key、用途、状态和 24 小时有效期。登记失败不返回可用的取消授权，并对新孤儿对象做受控清理。字段沿用上传响应中的 URL，不增加新表。

取消接口使用 `DELETE /article/delete/articleCover`，保留 `articleCoverUrl` query 字段与发布权限；旧 GET 返回方法不支持且不变更存储。严格核对配置中 HTTPS 存储 origin、用途目录、归属、有效记录及已有引用；拒绝外域、userinfo、query/fragment、原始 key、路径混淆和别人的资源。历史存储域名只可经显式配置或服务端已保存记录识别，不能接受任意域名的同路径。

临时删除与标准文章保存协调同一对象状态：原子认领 pending→deleting 或 pending→publishing，保存事务结束后转为 referenced 或安全恢复 pending。并发流程、过期认领、进程中断及 Redis 故障安全拒绝，不以过期锁自动认定未引用。检查文章封面及正文中的同对象引用；标准 API 引用创建要参与同一协调机制。存储失败时保留可重试授权，已删除/不存在的对象可按已验证 key 幂等处理。

既有文章的历史 URL继续展示及编辑；无临时归属的历史资源不能经取消接口删除。新提交无法证明归属、也不是允许复用的服务端既有记录的封面，给出明确重新上传提示。后台取消操作只清理本次临时上传，已保存文章的封面不走该入口。

替代方案：仅做目录匹配不能防止同目录跨用户和引用竞态；新增持久化资产表超出本次必要范围。原安全规划 6.1/6.2 与 6.3 的相关部分复用本机制。

### 4. 图片替换以引用切换为提交点（F5）

先校验、上传唯一新对象，依据当前数据库引用做条件更新；成功提交后只清理精确旧对象。数据库失败/并发冲突保留旧引用并清理未引用的新对象；若清理失败，记录非敏感的对象键与可重试信息，不谎报回滚了 OSS。并发更新或清理旧资源前需确认它不是当前引用，避免批量列目录后删除全部图片。

适用于站长头像与资料背景；复用首页视频已经采用的提交后清理模式。替代方案是先删旧图或只加 `@Transactional`，都无法让 OSS 随 SQL 回滚。

### 5. 照片由服务端记录决定对象和类型（F8）

按保存的 URL解析可信 `photoAlbum/` 完整 key，不能按父相册 name 重建路径。查实对象类型和 parentId，客户端字段只作兼容校验，不能通过伪造 type 绕过非空相册限制。缺记录、非法 key、存储故障均返回明确失败；已验证路径不存在可视为幂等清理完成。删除数据库记录前确认对象清理成功，数据库失败时仍有记录可重试；说明对象先删而 DB 失败的恢复边界，不声称两者原子提交。

替代方案：递归拼目录仍会受相册改名影响；忽略存储返回值会继续产生孤儿对象。

### 6. 主部署以“本次发布清单”控制放置与恢复（F6）

在任何文件替换之前，为本次所选组件记录目标、校验值和备份；包括 jar、前端及实际会修改的 Nginx。整个放置、重启、健康检查和静态资源核验使用一个可追踪的失败恢复流程；显式超时调用回滚或走统一失败函数，不依赖 `exit 1` 触发 ERR。只恢复本次已修改的组件，不消费以前发布的 previous 目录；尊重配置的目标路径。

恢复 jar 后启动旧服务并核验健康；区分发布失败但恢复成功与恢复失败，始终以非零状态结束失败发布。后端健康使用现有可匿名读取的 `/site-modules/access`：检查 HTTP 成功、业务 code=200 与完整模块结果，避免博客模块设为私人时 `/article/blog-feed` 被误判为进程故障。该路径执行数据库读取，同时无需把 token 写进探针日志。额外独立核验已发布前端入口和资源响应类型。

先用临时目录、假 systemctl/curl/nginx 验证全流程；复用 `deploy-backend-safe.sh` 的备份/恢复经验，不额外维护第二套不一致的部署流程。替代方案是全目录无差别恢复、覆盖 jar 后再备份或仅检查 HTTP 200，均不能证明本次发布可恢复。

### 7. 后台资源与页面导航分开匹配（F7）

调整 `/admin/` 与资源 location 的优先级，确保静态资源选中专用规则；当前资源优先，上一版其次，最终 404。脚本/CSS 正确类型且哈希资源长期缓存；HTML入口不缓存；页面深链接继续回退后台入口。复用 `.previous` 保留一版，不累积旧版本。

### 8. 限流辅助状态与窗口一起结束（F10）

窗口计数、开始时间及 TTL 原子初始化，辅助键使用同一有界窗口；封禁截止时间独立保存，不能随短窗口误解封。旧持久辅助键在被本地新逻辑合法访问时可安全补 TTL，批量生产清理另行授权。Redis 异常保持现有保护语义，不返回空白成功。替代方案只在普通 set 后另加 expire 存在初始化竞态，因此用现有 Redis/Lua 或等价原子操作复用。

### 9. 回归测试必须执行行为而不是通过替身掩盖故障（F11）

邮箱组件测试补全发送确认/错误/取消依赖并实际断言；默认后端测试用隔离配置或最小真实 Spring 装配 smoke test，有明确断言和模拟外部边界，不用生产秘密。真实 MySQL/Redis/OSS集成测试显式 opt-in，无条件时记录跳过原因。保留生产 profile 的失败关闭测试、登录二次验证与 Markdown 防护。

## Risks / Trade-offs

- [封面 DELETE 与旧后台不兼容] → 同一发布交付后端与后台；旧 GET只拒绝，不保留不安全兼容删除。
- [历史封面没有临时授权] → 保留展示与既有引用编辑；取消授权失败给出重新上传说明，禁止自动认领或批量清理。
- [Redis 与 SQL/OSS无法单事务] → 生命周期认领、条件写入、提交钩子和失败关闭；用并发与故障注入验证边界，未确认的资源状态不自动删除。
- [暂时保留 token 可能被误作已确认授权] → 用户资料进入待恢复态，后端仍最终鉴权，前端不展示未经确认的特权操作。
- [部署回滚也可能失败] → 记录备份路径与恢复结果，保留人工恢复说明，探针有时间上限。
- [旧安全变更未来同步覆盖新要求] → 保留任务/规格交集记录；同步时以最新的完整行为要求核对，不盲目覆盖或归档旧变更。
- [GitNexus索引落后且数据库占用] → 实施前恢复当前索引并进行影响分析；无法取得完整结果时报告限制，不能用空调用集推断安全。

5. 历史对象与 Redis 键只盘点，不随本次默认任务批量删除。需要清理时单独提出证据、范围与备份方案。
