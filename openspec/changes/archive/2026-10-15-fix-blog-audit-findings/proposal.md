## Why

2026 年 10 月 14 日代码审查确认了 11 项缺陷，涉及第三方请求附带凭据、评论访问漏检、跨目录删除、上传失败丢旧图、部署恢复、后台旧资源、照片清理、登录恢复、限流状态和回归测试。需要将这些已复现或有明确源码证据的问题集中修复，并用隔离验证保护现有登录、内容审核、首页视频和角色配置功能。

## What Changes

- 请求客户端仅向经过严格 URL 解析的可信博客 API 附加身份；外部内容请求不携带博客凭据，也不能改变博客登录态。
- 评论服务使用解析后的目标类型执行模块与公开状态校验，读取、计数和提交保持一致，回复关系从真实记录核实。
- 封面取消上传只允许调用者持有的未引用临时封面；校验对象源、目录、用途、归属和引用，真实处理存储失败。**BREAKING**：封面删除从 GET 改为 DELETE，同步后台调用，旧 GET 不再执行删除。
- 站长头像/背景先校验和上传新对象，成功切换数据库引用后才清理精确旧对象；失败保留旧图。
- 照片删除依据服务端保存的完整对象键及真实类型，处理嵌套、改名和存储失败，不虚报成功。
- 主部署脚本建立本次组件与备份记录，放置及健康检查失败都恢复本次修改组件，包括后端；超时不得绕过回滚。
- 后台脚本正确命中当前/上一版资源，最终缺失返回 404，不返回后台 HTML。
- 前台仅在明确认证失效时清 token，网络/超时/5xx 安全降级并可重试；限流窗口的辅助状态随窗口过期。
- 修复邮箱设置模拟依赖及后端测试配置隔离，补针对以上触发条件的可执行回归。

## Capabilities

### New Capabilities

- `recoverable-component-deployment`: 本次组件限定、失败恢复、后端与前端备份、回滚后的健康核验。
- `admin-static-asset-continuity`: 后台当前和上一版静态资源匹配、缓存及最终 404。
- `isolated-regression-verification`: 无真实秘密或生产副作用的默认回归与明确的集成测试边界。

### Modified Capabilities

- `blog-auth-session`: 可信 API 的凭据边界，以及认证失效与临时请求失败的区别。
- `file-storage`: 有归属的临时封面删除、提交后替换旧对象、按已保存完整键删除照片及错误契约。
- `comment-moderation`: 评论目标与模块可见性、JSON 提交和回复关系校验。
- `trusted-client-rate-limiting`: 限流计数及辅助窗口状态的过期与一致性。

## Impact

- 涉及博客端 HTTP/用户 store/登录与重试状态，后台文章封面调用与错误提示，后端评论、存储/图片替换、相册和限流服务，主部署脚本及 Nginx 配置，相关测试。
- 复用 Vue/Pinia/Axios、Spring/MyBatis、现有 Redis 和 OSS 抽象；不增加框架、大型依赖或数据库表。临时封面授权记录可复用 Redis；历史媒体继续显示，但没有授权记录的对象不能作为任意取消上传对象删除。
- 默认只在本地或隔离环境实施与验收，不自动提交、推送、部署、清理线上对象、评论或 Redis 历史键。部署脚本改动须先以临时目录和服务替身验证。
- 与未完成的 `remediate-blog-security-audit` 的存储授权、评论目标可见性及最终回归任务有交集；本变更负责上述 11 项触发条件，原变更的通知队列、友链审批、CSP、依赖审计等范围保持独立。后续以证据关联任务，不自动勾选或归档原规划，不重复实现同一机制。
- 实施前需对当前分支重新取得 GitNexus 影响分析；旧审查图谱落后 5 个提交且受锁限制，不能作为完整调用覆盖证据。
