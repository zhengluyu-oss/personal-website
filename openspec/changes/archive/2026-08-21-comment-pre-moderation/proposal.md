## Why

站长无法实时盯评论区时，不当言论可能直接公开展示并带来法律与运营风险。站点已具备后台「是否通过」审核与前台仅展示已通过评论的能力，但新评论默认自动通过。需要改为：评论始终可发，必须经管理员审核通过后才公开展示。

## What Changes

- 新发表评论默认 `is_check = 0`（待审核），不再依赖库默认值 1 自动上线
- 数据库默认改为 0，与代码写入一致
- 前台列表继续只展示已通过评论（现有逻辑保留）
- 用户提交后提示「已提交，待审核」类文案（若现网无提示则补齐）
- 评论计数（Redis）仅在审核通过时增加；发表待审时不计入公开数量（修正现有「发表即 +1」与「审核再 +1」的重复风险）
- **不再**做全站关闭评论开关（撤销原 `site-comment-toggle` 方案）
- 后台既有评论审核页继续作为放行入口

## Capabilities

### New Capabilities

- `comment-moderation`: 文章/留言板评论先审后发策略（默认待审、公开过滤、计数与提示）

### Modified Capabilities

- （无既有主规格强制改名）

## Impact

- 后端：`CommentServiceImpl.userComment` 强制 `isCheck=0`；调整 Redis 计数时机
- SQL：`t_comment.is_check` 默认改为 0
- 博客端：发表成功提示待审核
- 管理端：沿用现有评论审核页（可能仅文案/筛选优化）
- 部署：backend（必要时 blog）；执行 ALTER DEFAULT
