## Context

生产排查确认一次问答在约4秒后进入 `UNCERTAIN/NETWORK_UNKNOWN`，且当时尚未发送生成请求；后续三次问答在约11至13秒后进入 `FAILED/GENERATION_FORMAT`。第二类错误已进入生成阶段。当前日志没有对应的 `finish_reason` 等安全元数据，不能把历史失败直接断言为 token 截断。

`DiaryAiCloud.generate` 将 choices 数量、停止原因、空正文、工具字段和用量异常合并为同一错误；`send` 将超时与异步网络异常合并。`DiaryAiStore.message` 对大多数失败只给出检查配置/限额提示。日记问答、原文复盘和目标行动的期间回顾共享云端客户端，必须一起回归。

现有约束：生成模型 `deepseek-flash`，显式关闭思考，2000 token 输出上限；连接5秒、单次HTTP30秒、响应4 MiB；每日20次生成、200个向量输入，持久幂等、全局单运行租约及严格来源校验。代码关系索引在调查时落后7次提交，图只用于定位；实施前须重新核实当前源码、索引和逐符号影响，不能把旧图的零影响当作安全结论。

相关基线是活动变更 `add-diary-rag-and-ai-review` 与 `add-diary-goal-tracking-and-periodic-reviews` 中的规格，以及当前部署行为；本变更不补写它们的未完成验收。

## Goals / Non-Goals

**Goals:**

- 在现有预算内提高三类生成的可用性，让失败可解释、可测试且不泄露私密内容。
- 使用可选 JSON 模式和任务专用紧凑提示，保留个体结论的真实引用与资料局限。
- 准确区分提交未获确认、向量网络异常、生成截断、响应协议异常与引用校验失败。
- 失败、取消、重启、手动再提交均不隐式重放付费请求，不误称未计费或退还额度。

**Non-Goals:**

- 不更换供应商/模型，不提高输出、时间、每日额度或数据库资源，不重建现有索引。
- 不重做检索排序、日期解析或把 Top-K 问答升级为完整月报；用户要完整期间复盘仍使用现有预览入口。
- 不增加数据库表/列、依赖、流式协议、自动修复JSON、自动续写或备用模型调用。
- 不展示被截断/不合格的部分回答，不放宽引用、租约、来源版本、本人权限或文本渲染检查。

## Decisions

### 1. 错误分类在云端边界完成，仍使用现有任务协议

给共享客户端的调用传入内部阶段枚举 `EMBEDDING` / `GENERATION`。异常保留安全固定错误码及 uncertain 标记；只从已知异常类型判断连接/总超时、连接中断或其他未知网络错误，无法判断时保留明确的 UNKNOWN 分类，不根据异常 message 猜测。

生成响应按顺序检查：有效 envelope/单个 choice → 停止原因 → 实际工具调用/拒绝 → 正文类型及非空 → usage字段。`length` 独立映射 `GENERATION_TRUNCATED`；空正文、非法 envelope/usage、非允许停止原因、工具调用分别分类。已知 `tool_calls` / `function_call` 的 null 或空集合仅表示没有调用，不当作实际工具执行；非空调用仍拒绝，其他畸形类型作为协议异常。

保留现有 `OUTPUT_EVIDENCE_INVALID`，只有本地结果字段、来源ID及逐字引文验证成功才生成报告。HTTP 401/403、429和其他非200分别给予认证拒绝、限流、服务拒绝类别，禁止把供应商原始错误体转发到前端。

错误码写入现有无枚举约束的 `error_code` 文本字段；job响应仍沿用 `id/kind/state/message/reportId/possiblyCharged`。`DiaryAiStore` 与 `CoachingPeriodAi` 复用一个安全消息映射，不让两种任务对同一码给不同解释。旧 `GENERATION_FORMAT` / `NETWORK_UNKNOWN` 只映射历史通用说明，不迁移成新原因。

替代方案：加诊断表或直接返回供应商JSON会增加迁移和泄漏风险；仅在前端猜测原因无法得到实际停止状态，均不采用。

### 2. 显式可选 JSON 模式，不改变现有预算

增加后端外置可选 `diary.ai.generation-json-output`，缺省不发送额外字段以兼容其他供应商；明确启用时生成请求发送 `response_format: {type: json_object}`。只作用于生成请求，向量请求不带该参数。DeepSeek配置启用时继续发送 `thinking: {type: disabled}`；保留完整HTTPS地址、精确主机白名单和重定向禁用。

提示词明确要求 JSON，提供一份语法有效且引用占位清楚的结构示例，并说明必须使用实际来源替换示例标识。JSON模式只提高语法可靠性，不等于 schema 或证据正确，仍执行本地校验。

依据：[DeepSeek Chat Completions 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)（2026-10-16核对）说明支持 `json_object`，同时要求提示词明确要求JSON；`finish_reason=length` 仍可能产生截断。不能据此宣称供应商永远返回完整、符合业务结构的回答。

替代方案：全供应商强制JSON或收到400后无参数重发，分别破坏兼容或增加付费调用；扩大2000 token预算会改变成本边界，本次不采用。

### 3. 按任务精简输出，保留完整输入和证据

问答以 `answer` 为主要内容，优先直接回答问题，通常令 `observations/hypotheses/suggestions` 为空，避免在多处重复相同观点；`summary=null`。提示目标为 answer 不超过600个Unicode码点，引用最多3条、每条不超过60码点，局限1至2条且每条不超过80码点；这些是生成指导，不收紧旧报告的读取契约。

日记复盘及期间回顾保留原有字段和证据类型，采用总输出指导：概览约200码点、观察最多3项、推测最多1项、建议最多2项、局限最多2项；观察/推测正文每项约80码点，建议各字段短句，不在多个字段重复长引文。更新对应提示版本。仍由本地既有字段和精确引文上限做最终校验，不通过减少来源、截断完整范围输入或删除失败字段来伪造成功。

字符指导不是token精确计算。用固定虚构的跨日/月度材料校准可用性；若在2000 token内仍频繁截断，保留真实失败并报告，不静默扩容或多次生成。若确需更长报告，另行调整预算方案。

### 4. 只记录安全且有界的诊断元数据

在云端边界和任务终态生成结构化诊断：内部阶段、固定错误码、归一化停止原因、HTTP状态、实际返回且合法的token数、输出上限、响应字节数、耗时及内部任务标识。未知停止原因写固定 `OTHER`，不原样记录供应商任意字符串；不保留正文长度以外的内容。日志不记录异常堆栈/嵌套异常message、问题、日记、向量、模型正文、URI、headers或密钥。

缺失usage保持未知；取得合法usage后即使截断或引用失败，也沿用既有预算/用量通路记录一次，不能把失败当作未调用、不能记录两次。尝试预留不自动返还。`possiblyCharged` 对已发出或不能排除已发出的向量/生成请求保守处理，阶段提示说明它不等于账单确认；只有能确认没有发送才可说明没有调用。

不回填历史诊断、不恢复或重放历史payload。原日志隐私禁令和通用审计的日记排除保持不变。

### 5. 前端展示失败事实与下一步，保留请求幂等

`202` 对应提交受理，结果卡继续显示等待/处理/终态，不把受理当成功回答。失败卡显示服务端安全原因及针对性动作：网络异常可稍后手动再提交；截断建议更聚焦提问或使用选定范围；认证拒绝提示检查服务配置；引用校验失败说明没有发布结果。旧原因无法细分时明确“不足以确定具体原因”。

收到202后终态重试是用户新发起任务，采用当前表单输入和新的requestId，并在操作旁明确可能再次计费；提交确认丢失仍保留原请求体和原requestId，仅找回原任务。失败后不自动重发、不以读取状态触发生成，取消/过期后的迟到响应不展示。原生草稿保护、分区保留状态、明暗主题及移动布局继续沿用。

## Risks / Trade-offs

- [历史三次失败原因不可恢复] → 只确认原错误码，实施后用安全元数据分辨，不把猜测当已证实根因。
- [紧凑提示减少细节] → 问答突出所问问题，保留证据；完整期间回顾仍保留完整输入、类型化观察/建议，人工核对信息质量。
- [JSON模式仍截断或返回空值] → 精确分类、保持失败关闭、固定虚构语料检验；禁止自动修复/续写和计费重试。
- [共享适配器影响期间回顾和向量检索] → 独立请求体断言和三类任务回归；向量请求不携带生成专用字段。
- [诊断泄漏隐私或usage被伪造] → 白名单字段、数值边界、含秘密探针的负面测试；不记录raw响应或异常链。
- [模型输出具有随机性] → 保留每次原始验收状态与计数，失败不被复测覆盖；不把一次成功称为稳定性保证。

## Migration Plan

1. 本地逐符号影响分析后实现；先用受控HTTP和隔离PG验证请求/错误契约，无生产数据迁移。
2. 执行三类任务、幂等、取消、来源变化、权限、日志和浏览器回归，再用当前供应商的小型固定虚构集做有界真实校准。密钥只从安全环境读取，保存脱敏收据。
3. 配套构建后端与博客前端，说明需重启后端和可选JSON配置影响，按用户部署授权发布；备份旧JAR、前端和外置配置，仅更改所需子项。
4. 健康检查后，在本人真实登录下手动验收问答和范围复盘；不伪造登录凭据、不改库启动任务，不为排错自动发送真实日记。尚未完成的生产验收保持未勾选。
5. 故障时恢复旧JAR/前端和该配置项；新错误码由旧版通用提示兼容。保留所有日记、任务和已有报告，不清库、不返还未知尝试或重放任务。

## Open Questions

无待确认产品范围。待实施验证的事实包括：共享生产响应触发的具体校验项、紧凑提示在2000 token内的通过率、启用JSON模式后的实际契约；这些必须由元数据/受控测试与真实虚构语料收据回答，不通过读取或保存私密模型正文推断。
