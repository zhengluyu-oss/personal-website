## Why

博客目前缺少与公开文章隔离的私人记录空间，无法方便地自由记录、持续补写、查看修改历史并确认内容是否可靠保存。先建立仅站主本人可访问、按篇组织的日记与 PostgreSQL 存储：一篇可以记录过去十几天的经历，也可在同一天写多篇；每篇可选填内容起止日期，为后续经过单独规划的 RAG 和云端 AI 复盘保留准确的原始记录。

## What Changes

- 在博客前台已登录用户入口提供“我的日记”，仅对配置的站主账号开放；不新增公开导航模块或后台通用日记管理入口。
- 以独立日记ID组织记录，不限制每日篇数，一篇可跨多日并持续补写；支持Markdown正文、可选标题及可选内容起止日期，区分创建/修改时间与经历发生的时间。
- 提供按写作日期的日历、分页列表、关键词及可切换的写作时间/内容时间范围筛选；时间范围允许重叠、可以不填写，不把一篇跨日记录拆成多篇。
- 提供自动保存与手动保存，明确显示未保存、保存中、已保存、离线/失败和冲突；只有 PostgreSQL 事务提交并确认对应内容版本后才显示已保存。
- 使用版本条件写入、请求幂等和串行保存，阻止多标签页、重复请求和迟到响应静默覆盖内容；保留修改历史，可将历史版本恢复为新版本。
- 支持有明确确认步骤的删除，以及按日期范围导出 Markdown/JSON 备份；删除保留可追溯墓碑和历史，不在本阶段提供永久销毁或导入。
- 仅日记原文、修改历史和幂等记录使用新增 PostgreSQL 数据源；现有账号、文章及其他博客数据仍使用 MySQL，两个库不做跨库写事务。
- 日记默认私密，所有读取、筛选、导出、历史和写入均在服务端验证身份与归属；不进入公开文章、搜索、推荐、站点地图、通用审计正文或公共 OSS 上传链路。
- 建立无真实秘密的隔离测试、可重复迁移、备份恢复演练与部署开关；PostgreSQL 故障只令日记不可用，不能使公开博客停机或伪报保存成功。

## Capabilities

### New Capabilities

- `private-diary-workspace`: 仅站主可访问的按篇日记界面、可选内容时间范围、日历/列表/筛选、修改历史、受控删除和个人导出，以及私密内容边界。
- `reliable-diary-saving`: 自动与手动保存状态、提交确认、版本冲突、请求幂等、迟到响应隔离、会话切换和未保存内容保护。
- `isolated-postgres-diary-storage`: 独立 PostgreSQL 数据源、日记与历史原子保存、与 MySQL 隔离、功能开关、故障边界、迁移和可验证备份恢复。

### Modified Capabilities

无。沿用现有前台认证、管理员二次验证、安全 Markdown 和公开模块契约；对新日记路径追加更严格的独立约束，不借此重做现有账号或全站权限。

## Impact

- 前台：新增日记路由、页面、接口封装及局部保存状态，在现有用户菜单添加本人入口；不改变首页视频或公开导航结构。
- 后端：新增日记配置、显式认证路径、站主资格检查、Controller/Service/DAO 与限定事务；复用现有 Spring Boot 4、Java 17、JWT 和 JDBC 能力，不引入新后端服务或 ORM 框架。
- 数据库：新增 PostgreSQL JDBC 驱动、独立连接池和日记表；显式保护现有 MySQL 主数据源及 MyBatis 的 MYSQL 方言。凭据和站主账号编号放在外置配置中，不猜测账号、不写入仓库。
- 运维：PostgreSQL 资源预算、仅内网访问、独立低权限账号、迁移与备份恢复手册；新模块通过开关逐步启用，生产迁移与发布另行说明影响后执行。
- 本阶段不安装 pgvector，不生成向量，不接入模型、消息分析任务、行为统计、提醒、公开分享、附件或多人日记服务；此前允许调用云端模型的选择保留到后续阶段。
- 工作区已有归档和未提交的旧修复，实施必须先核对实际源码及 GitNexus 索引，保留无关改动，不将归档视作旧问题已经验收；本次只生成规划，不提交、推送或部署。
