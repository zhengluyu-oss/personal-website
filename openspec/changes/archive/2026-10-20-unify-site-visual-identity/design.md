## Context

用户端首页 Hero 已是暗色影像气质，但 `theme.scss` 亮色 token 仍是冷灰蓝 SaaS（`--brand-canvas: #f5f8fc`、`--brand-accent: #155eef`），暗色则用珊瑚强调；Header 图标密集、搜索图标异色；全局仍残留粉紫 footer 渐变、彩虹滚动条等模板装饰。管理端 `workspace.scss` 又独立一套蓝系。设计审计结论：先统一气质，不动首页模块扩容与权限规则。

约束：保持公开 URL / 主导航目的地 / SEO；字体优先自托管；动效克制并尊重 `prefers-reduced-motion`；管理端仍是 Ant Design 工具台，只对齐口音不改信息架构。

## Goals / Non-Goals

**Goals:**

- 定义「陆屿 · Ink & Ember」视觉口音：画布、墨色、单一强调色、圆角、阴影、字体层级，用户端明暗主题与管理端 workspace 同源。
- Hero（暗色影像）到正文（浅色画布）有可见过渡，不再像跳到另一产品。
- Header 品牌字标更强、导航更静、搜索/登录降权；不删除现有目的地。
- 清除与新口音冲突的遗留杂色与冲突字体用法。
- 管理端登录与 workspace 表面使用同一套强调色与墨色。

**Non-Goals:**

- 不重排首页模块（相册条、主题入口等留给后续变更）。
- 不改模块权限、登录态、路由 slug。
- 不引入 GSAP / 大动效库；不改文章表格交互与后台 IA。
- 不强制替换 Hero 影像素材本身。

## Decisions

### 1. 调色：Ink & Ember（克制暖强调，弃 SaaS 蓝）

- **选择：** 亮色画布改为近中性纸色（非蓝灰 `#f5f8fc`、也避免米色+黄铜套装），墨色近炭黑；单一强调色为克制 ember（与现有暗色 `--brand-accent: #ee8168` 同族），亮/暗共用同一「暖强调」语义。
- **理由：** Hero 影像偏夜景暖高光；亮色继续用 `#155eef` 会固定「上下两套站」；暗色已有珊瑚，亮色对齐可减少主题翻转违和。
- **备选：** 冷石板 + 墨绿强调——更「工程文档」，与现有 Hero 情绪衔接更弱，故不取。

实现落点：`luyu-blog/src/styles/theme.scss` 的 `--brand-*`；同步映射 Element Plus 主色变量；管理端 `--workspace-*` 与 Ant Design `colorPrimary` 指向同源 accent。

### 2. 字体：一套 UI 字 + 有限 mono，去掉冲突展示衬线

- **选择：** 公开 UI 以现有自托管「阿里妈妈方圆体」或项目现用无衬线栈为唯一正文字族；Hero 姓名可用同族字重/字号拉开，不引入第二展示衬线；`Share Tech Mono` 仅用于真正的技术索引/代码感标签；删除或覆盖残留 `Georgia` 等冲突规则。
- **理由：** 多字族混用是「模板感」来源；目标是大气而非花哨。
- **备选：** 新加 Geist/Outfit——提升现代感但增加字体工程与许可成本，本变更不做除非现栈对比度不足。

### 3. Hero → 正文过渡带

- **选择：** 在 Brand/Hero 底部与 `home-content` 顶部之间增加短过渡（渐隐遮罩落入 `--brand-canvas`，或首个内容区顶部柔和分隔），正文首块（数据条/首 section）背景与边线改用新 token，避免 Hero 结束后立刻「白底蓝链」硬切。
- **理由：** 气质统一的关键不在换图，而在第一屏滚入第二屏的连续感。
- **备选：** 全文暗色——与长文阅读习惯冲突，且改动面过大。

### 4. Header 视觉层级（不改 IA）

- **选择：** 桌面顶栏保留现有链接目的地；降低或隐藏装饰性图标权重（可改为更细描边或仅文字）；品牌标题字重/字号优先；搜索与登录用中性色与次级按钮样式，去掉异色（如绿色搜索）。
- **理由：** 审计指出「像系统不像人」；收缩视觉噪音即可，不必本变更砍菜单项（菜单精简可后续单独做）。
- **备选：** 立刻收到 4–5 项——信息架构变更，超出「统一气质」范围。

### 5. 遗留装饰清理范围

- **选择：** 将仍暴露在公开页的粉紫 footer 渐变、彩虹滚动条、粉红分类渐变等改为中性/`--brand-*` 派生；保留功能，不删区块。
- **理由：** 这些是模板口音残留，直接破坏「不花哨」。

### 6. 管理端对齐方式

- **选择：** 只改 token 与登录页表面（标题、背景、主按钮、侧栏选中条）；不重做布局组件。
- **理由：** 后台要稳；口音对齐即可传达同一品牌。

## Risks / Trade-offs

- [Risk] 强调色从蓝改 ember，老用户短暂不适应 → Mitigation：明暗同一语义；按钮/链接对比度按 WCAG AA 验收。
- [Risk] 大范围替换 `--mao-*` 遗留变量遗漏角落页 → Mitigation：tasks 按「全局 token → 公开壳层 → 高频页 spot-check」分层；验收清单列关键路由。
- [Risk] 字体栈若仅系统回退在部分 Windows 上偏软 → Mitigation：确认现有 woff 加载路径；失败时用中性系统栈，不临时外链 Google Fonts。
- [Trade-off] 本变更不精简导航项，大气感提升有上限 → 接受；后续可用独立 change 收 IA。

## Migration Plan

1. 先改 blog `theme.scss` token 与管理端 `workspace` / 主题色映射。
2. 再改 Header / Hero 过渡 / 遗留杂色。
3. 本地与现网关键路由目视验收（首页、博客列表、文章、经历、登录、管理登录）。
4. 回滚：还原 token 文件与相关样式提交即可，无数据迁移。
