## Why

前台导航当前把“个人博客”指向语义模糊的 `/category`，文章、分类、标签、登录和后台管理页面的路径也缺少统一的信息架构。相同页面存在被不同入口或参数形式访问的风险，既影响用户理解、SEO 收录和链接维护，也增加前端路由与后台菜单配置的维护成本。

## What Changes

- **BREAKING**：重构前台页面路由，使博客内容统一归入 `/blog`，文章详情使用唯一规范路径，分类、标签、归档等页面具有清晰的资源层级。
- **BREAKING**：重构管理员后台页面路由，使网站管理和系统管理的路径命名一致，并移除同一页面的别名、重复入口及通过查询参数表达详情页身份的方式。
- 将所有页面路由限制为最多三级路径（动态 ID 计作一级）；若实施审计发现确实无法压缩到三级的页面，必须暂停该页面的变更并向用户报告。
- 不为旧页面路径提供重定向、别名或兼容入口；旧路径应进入现有的未找到页面处理，不得悄悄跳转到新页面。
- 更新前台导航、页面内链接、后台菜单数据、动态路由解析和相关 TDK 绑定，使所有入口只生成规范路径。
- 保持后端 API 路径及接口契约不变；本变更只调整前端页面地址与后台菜单中的页面路由配置。

## Capabilities

### New Capabilities

- `canonical-page-routing`: 定义前台与管理员后台的规范页面路由、唯一性、三级深度上限、无旧路由兼容和未找到页面行为。

### Modified Capabilities

- `dynamic-blog-navigation`: 将“个人博客”及动态分类子导航从 `/category` 体系迁移到规范的 `/blog` 路由体系，确保导航只生成唯一页面地址。

## Impact

- 前台：`blog-frontend/kuailemao-blog` 的路由表、导航组件、页面跳转、面包屑、分享链接及 TDK 路由匹配。
- 管理后台：`ruyu-blog-admin` 的动态路由解析、菜单跳转、详情/编辑页入口及默认落地页。
- 数据与部署脚本：菜单初始化 SQL、现有菜单路由迁移脚本和部署后的菜单缓存刷新流程；不变更业务表结构。
- 外部影响：旧书签和旧搜索结果不会被兼容，访问旧路径将失败；上线前需一次性完成所有内部链接与菜单数据迁移。
