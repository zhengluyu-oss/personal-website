## Context

当前首页使用 Vue 3 组件组合站点配置、Banner、文章和工作经历数据，已具备浅色品牌基础、后台可配置 Hero 文案、推荐文章及唯一文章详情路由。线上审查发现，首屏仍以泛化欢迎语和风景图为视觉中心，姓名与职业方向不够明确；推荐内容偏重封面，后续区块缺少可验证的专业叙事；390px 视口存在媒体和文本越界。

本次改动跨越首页 Hero、文章展示、经历摘要、关于入口及响应式样式，但不需要新增数据源。实现必须复用现有网站信息、Banner、文章、推荐文章和工作经历接口，保持后台配置优先、公开 URL、导航、TDK、备案信息和全站品牌规则不变。

## Goals / Non-Goals

**Goals:**

- 让首次访问者在首屏识别郑陆宇的姓名、后端与全栈方向、技术内容价值和主要访问入口。
- 使用现有公开文章与经历构成可点击、可追溯的专业证明，不虚构项目、指标或职责。
- 修复 360px、390px、430px 窄屏的横向溢出，并为所有异步区块保留稳定的加载、空和错误状态。
- 建立清晰的首页阅读顺序，降低 Banner 和推荐封面的视觉重量，提升文字层级与内容密度。
- 保留现有后台 Hero 和 Banner 配置能力，同时让未完整配置时仍有可用的默认内容与行动入口。

**Non-Goals:**

- 不修改后端 API、数据库字段、管理后台数据模型或权限机制。
- 不新增项目管理模块，不把文章或经历包装成不存在的项目案例。
- 不修改路由层级、文章详情路由、导航名称、登录入口或公开页面的信息架构。
- 不引入新的 UI、动画或图片处理依赖，不重做文章详情页和工作经历详情页。

## Decisions

### 1. 使用“身份与行动 + 辅助媒体”的编辑式首屏

Hero 保持单张 Banner，但主信息顺序固定为身份眉题、姓名与职业定位、价值说明、主要行动入口，Banner 作为辅助媒体而非主叙事。后台配置内容始终优先；核心字段为空时，前端从现有站点名称、关于介绍和既有路由生成稳定默认值。

选择该方案是因为它能保留现有配置能力和真实图片，同时让招聘者无需向下滚动即可判断站点归属与用途。备选方案是继续以大图或欢迎口号为中心，但这会延续身份模糊和模板化问题；另一备选是增加新的个人资料接口，但超出本次范围。

### 2. 默认行动入口只指向既有一级页面

若后台没有完整配置按钮，前端显示“阅读博客”和“查看工作经历”两个默认入口，分别使用现有博客与经历路由。若管理员配置了完整按钮，则按配置替换对应默认入口；不完整配置不生成空按钮或无效链接。

该决策避免新增路由，并保证首屏在任何配置状态下都有明确下一步。所有文章仍只使用既有唯一详情路由，路由层级不超过现有约束。

### 3. 专业证明由现有真实数据派生

新增的专业证明区不建立新数据模型。它从当前有效的推荐文章、最新文章和启用的工作经历中按确定性规则选择内容，并保留原始标题、摘要、分类、公司、职位、时间和详情链接。数据不足时缩减卡片数量并展示上下文相关的空状态，不填充虚构内容。

相比手写静态项目卡片，该方案能随后台内容更新并保持可追溯；相比新增项目表，它更符合不触及后端 API 的限制。

### 4. 通过层级而非更多装饰区分内容

首页采用单一浅色冷灰背景、蓝色强调色、统一圆角和克制阴影。推荐文章缩小媒体占比，标题、摘要和推荐语承担主要层级；最新文章使用更紧凑的列表或网格；工作经历统一展示公司、职位、时间和成果摘要；关于尾区只保留有信息价值的介绍与联系入口。中英文装饰标签仅在有语义时保留，并统一语气。

这样可减少模板感和大卡片争夺视觉中心。不会通过轮播、视差、粒子或额外营销区制造层级。

### 5. 响应式约束从页面容器向子项传递

首页外层容器统一使用受控最大宽度和窄屏安全边距；Grid/Flex 子项设置可收缩边界；媒体使用容器宽度、稳定比例和明确的 `object-fit`；长标题、链接和英文文本允许换行。桌面保持图文节奏，768px 以下切换为单列，并在 360、390、430px 验证无横向滚动。

仅在外层隐藏溢出会掩盖布局错误，因此不作为修复方案。实现应定位具体的固定宽度、最小宽度、负边距或媒体尺寸来源。

### 6. 延续现有异步数据与可访问性模式

各区块独立处理加载、空数据和错误状态，单个接口失败不使整个首页空白。按钮、文章与经历入口保持语义化链接和可见焦点；非必要动效遵循 `prefers-reduced-motion`。图片延续现有懒加载和占位策略，首屏主图保持尺寸预留以降低布局跳动。

## Risks / Trade-offs

- [后台文案可能过长，破坏首屏层级] → 对布局设置可换行、合理行宽和尺寸边界，并在管理配置优先的前提下避免强制截断正文含义。
- [现有 Banner 仍可能是与职业定位关联较弱的风景图] → 降低其视觉权重并保证无图占位可用；是否替换图片由管理员通过现有 Banner 能力决定。
- [现有文章或经历数据不足，专业证明区显得稀疏] → 使用确定性降级顺序和紧凑空状态，隐藏无数据的小节而非制造内容。
- [首页信息增加后影响 3M 带宽下的首屏速度] → 不新增图片请求和依赖，复用既有数据，限制首屏媒体数量并保留懒加载与固定尺寸。
- [调整共享品牌样式可能影响其他公开页面] → 优先使用首页作用域类和既有设计变量，只在确有共用语义时修改共享变量，并运行公开路由回归检查。

## Migration Plan

1. 先补齐 Hero 解析、专业证明选择和响应式布局的自动化测试。
2. 在现有首页组件内逐区调整 Hero、推荐文章、最新文章、经历和关于尾区，不改变接口请求与路由。
3. 完成桌面 1440px 及移动 360px、390px、430px 的视觉和横向溢出验证，并检查加载、空、错误及减少动画状态。
4. 构建通过后按现有前端发布流程部署静态资源，无数据库迁移。
5. 若线上出现布局或内容回归，回滚本次前端构建产物；后台配置和数据无需回滚。

## Open Questions
