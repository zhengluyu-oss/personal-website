## Context

博客采用 Vue 3、Element Plus 与 SCSS，公开页面由多个年代和风格不同的组件组成。现有单图 Banner 是品牌识别资产，文章、经历、分类及互动数据均由后台提供。服务器带宽为 3M，现有依赖包已经偏大，因此视觉升级必须优先依赖 CSS 与现有图像，避免新增运行时依赖。

## Goals / Non-Goals

**Goals:**

- 形成“程序员作品集式博客”的统一品牌体验，让招聘者能快速理解身份、能力、经历和持续输出。
- 以深靛黑、暖白和低饱和珊瑚橙为单一强调色，建立统一语义变量并兼容明暗主题。
- 桌面采用克制的不对称编辑式布局，移动端明确折叠为单列。
- 保留全部路由、动态内容、后台字段与 SEO 行为。
- 使用现有 Vue 与 CSS 能力实现轻量动画，并完整支持减少动态效果偏好。

**Non-Goals:**

- 不改变后端 API、数据库模型、文章内容或后台业务流程。
- 不重命名既有路由和主要导航语义。
- 不为管理后台、数据表格或复杂表单套用展示型页面结构。
- 不新增 GSAP、Three.js 等依赖，也不增加大型首屏媒体资源。

## Decisions

1. 采用自定义 CSS 语义变量而非引入新设计系统。现有项目已有 Element Plus 与主题切换，变量层可以低风险覆盖全部页面并控制包体。
2. 视觉方向为“深色技术感 + 编辑式排版 + 克制实验性”，设计变化 7、动效 5、信息密度 4。招聘阅读需要清晰层级，因此不采用高密度终端风或过强滚动叙事。
3. 首页保留现有单张 Banner 与后台可配置文字，但移除滚动提示、无语义装饰点和重复英文口号。内容区使用更强的文章封面、经历入口和个人能力线索形成招聘路径。
4. 页面统一通过共享容器、Banner、卡片、状态与表单变量升级。首页、文章、经历等核心模板单独重构，其余页面通过共享组件和少量页面级覆盖统一。
5. 动效只使用 transform 与 opacity，进入动画采用现有指令或 CSS，所有连续效果由 `prefers-reduced-motion` 关闭。移除以窗口滚动监听驱动视觉状态的实现，改用 IntersectionObserver 或 CSS。
6. 保留现有图片与图标，不生成新的大尺寸资产。文章封面、相册和 Banner 继续承担视觉内容，避免加重 3M 带宽负担。

## Risks / Trade-offs

- [旧页面局部样式优先级较高] → 使用语义变量与明确的共享组件重构，页面级覆盖保持最小并逐页验证。
- [大范围改动可能影响交互] → 保留模板数据绑定和事件，只调整结构层级与样式，并按路由进行回归测试。
- [亮暗主题视觉不一致] → 所有新颜色必须来自同一组语义变量，在两种主题和系统偏好下检查对比度。
- [视觉效果增加渲染成本] → 不新增依赖，限制模糊面积，关闭移动端非必要特效，构建后检查包体与首屏。

## Migration Plan

1. 先落地语义变量和共享布局，再逐个迁移页面模板。
2. 本地构建并用桌面与手机视口审查全部公开路由。
3. 部署时复用现有构建与 Nginx 流程，验证首页、文章和经历 API。
4. 若出现回归，可回滚前端构建产物；后端与数据无需回滚。

## Open Questions

无。现有内容、路由和后台配置能力足以完成本轮改版。
