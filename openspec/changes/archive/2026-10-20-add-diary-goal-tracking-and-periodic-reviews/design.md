## Context

此前三步安排是：私密日记与可靠保存 → 带原文引用的 AI 复盘及 RAG 问答 → 目标跟踪和周／月回顾。第一阶段32项已完成并按用户授权同步规格归档；第二阶段存在本地实现与部分测试，但供应商、模型、实际效果、最终回归和上线验收未完成。用户明确暂未选择模型。本次完成第三阶段规划，不将第二阶段现状视为稳定上线基线。

沿用 Vue／Element Plus、Spring Boot、PG16 JDBC、最多3个日记连接、本人授权、FORCE RLS、版本化写入与加密备份。现有博客及账号保留 MySQL。日记可同日多篇、跨多日或不填内容日期，不能建立“每天都有数据”的假设。源码核实发现原001和第二阶段002分别对整个 diary／diary_ai schema计算结构指纹；新增表或直接扩充 job.kind CHECK会破坏既有迁移重复验证。

GitNexus目前不能完整解析第二阶段新增处理类；规划的复用判断来自对应源码及迁移复核，不以空查询证明不存在调用。实施前须刷新图谱并逐个符号 impact。本次只编辑本变更规划及另行授权的第一阶段归档，不修改未提交实现、OpenWiki或生产。

## Goals / Non-Goals

**Goals:**
- 站主可以明确目标、确认行动、记录真实尝试及效果，跨周／月回顾是否值得继续或调整。
- 手动记录和确定性期间摘要不依赖云端服务；有模型后再按明确范围生成有多类型依据的回顾。
- 分开显示目标标准、当前状态、实际反馈、模型解释和资料缺失，不把建议自动变为事实或任务。
- 复用既有身份、保存约定和AI处理能力，保持原文可靠保存和公开博客独立可用。

**Non-Goals:**
- 定时AI周报、通知、邮件或跨平台任务同步；首版仅本人手动触发回顾。
- 自动达成判定、从正文猜测数字、连续打卡、人格或健康评分、医学诊断、因果效果承诺。
- 新模型供应商、独立AI进程、消息队列、重型编排框架、附件、公开分享、多人访问或日记永久销毁。

## Decisions

### 1. 从确认过的目标和行动开始

在本人日记工作区提供“日记／目标与行动／周月回顾”局部导航，保留现有编辑器和离开保护。目标包含标题（1～120码点）、期望变化和成功标准（各最多2000码点）、可选开始／目标日期，以及 ACTIVE、PAUSED、COMPLETED、ARCHIVED 状态。日期可独立留空；两者都填时开始不得晚于目标日期。活动目标最多20个，总目标最多1000个，列表默认20条、最多100条。完成仅由本人显式确认，不根据到期时间或模型文字变更。

行动必须属于一个本人目标，包含具体做法（最多2000码点）、可选计划日期及 PLANNED、IN_PROGRESS、COMPLETED、SKIPPED、ARCHIVED 状态，未结束行动总计最多100个。允许手工创建，也允许从仍有效的建议中打开采纳草稿：展示原建议、依据、所选目标及可编辑行动，最终确认才写入。重试沿用相同mutationId；同一建议可被有意再次尝试，但重复点击同一次确认不能创建重复行动。

采纳后行动是本人确认的独立记录。原报告删除或日记修改令来源链接失效，显示“原依据已变化／移除”，不级联删除目标或执行反馈，也不继续展示被撤回的原引文。来源记录保留类型、非正文标识、版本／摘要和有效性，不把整份AI报告复制到行动表。

不把目标混入文章、日记正文或公共ChatGpt数据：它们有独立身份、生命周期和访问边界。

### 2. 执行与效果分开，允许真实的不确定性

每条反馈属于本人行动，记录执行情况 TRIED／COMPLETED／SKIPPED、效果 HELPFUL／NOT_HELPFUL／UNSURE／NOT_EVALUATED、可选实际发生日期和最多2000码点说明。发生日期与录入／修正时间分开；不填发生日期时不自动采用录入日或日记覆盖范围。不得填未来实际发生日期；跨时区按 Asia/Shanghai 的“今天”校验。

反馈可以补录、修正和软删除，修正保持同一ID并形成新版本；只汇总当前未删除版本。反馈默认不改变行动状态，用户可在同一确认事务中明确选择完成行动，并提供行动expectedRevision；任一条件冲突整体回滚。一次尝试不是每天打卡，跨日经历也不拆成多条反馈。

首版只做确定性计数：期间内已明确发生日期的尝试／完成／跳过反馈数、效果选项分布、未填发生日期的反馈数，以及“截至本次查看”的目标／行动当前状态。没有反馈显示“未记录”，不等于失败；没有可评价记录显示“暂无可评价反馈”，不显示0%有效。若展示帮助比例，分母仅为 HELPFUL＋NOT_HELPFUL，UNSURE／未评价单列，显示分子分母及样本有限说明，不解释成因果或成功概率。反馈数量不直接等于投入时长、次数或目标完成率。

### 3. PG新增独立schema，不破坏既有指纹

新增显式版本化003迁移，在 diary_coaching 中保存 goal／goal_revision、action／action_revision、feedback／feedback_revision、mutation、origin_link、period_job、period_report／period_source及本schema版本信息。保持原diary和diary_ai对象不变；不得修改旧schema_version指纹绕过校验。选择独立schema而非在原entry、job.kind或report_source上直接加字段，是为了保留原迁移和旧客户端兼容。

core关联使用含owner的复合外键；当前实体、历史、幂等、来源和报告均FORCE RLS，运行角色仍非所有者、无DDL和BYPASSRLS。历史及幂等结果按原保存约定不可被运行角色任意更新／删除。每次事务从已验证身份设置事务局部owner，不接受客户端owner。

可选的原日记／第二阶段报告来源作为非授权性链接记录：由服务端在同一PG快照中用owner＋ID＋版本检查，读取、采纳和分析时重新解析；无法解析的来源不能成为证据。不能仅凭客户端提供的来源ID、文字或哈希建立可信引用。内部goal/action/feedback关系必须由组合外键兜底；涉及外部派生报告的链接不阻止其正常删除，不发生级联删除人工记录。覆盖直接SQL、跨owner伪造和删除后解析的实际测试。

写入沿用 UUID、mutationId、完整动作摘要、expectedRevision、CAS和历史同事务提交。丢ACK先重放原请求，摘要不同返回409；无变化不增加空版本。goal/action/feedback支持独立私密导出：有界JSON，最多1000实体／20MiB，超限分段，不改变原日记导出格式或上传OSS。

### 4. 周／月回顾先给出确定性资料清单

自然周按北京时间周一至周日，自然月按公历首日至末日。接口接收 WEEK＋某一天或 MONTH＋YYYY-MM，由服务端规范化 periodStart／periodEndExclusive；午夜和闰日测试不可缺。允许当前未结束期间，明确标“截至本次生成，期间尚未结束”。未来期间不能作为已有行为回顾。

日记默认按covered闭区间重叠纳入，也可选created半开日界。一篇跨边界日记完整纳入且只计一篇，显示它还涉及期间外日期；未填covered的记录不混入该轴，但明确显示排除数量和切换入口。执行反馈只按明确的occurredOn归期，与日记筛选轴无关；补录的历史反馈进入发生期间，修正时间不改变发生日期。无发生日期的反馈独立列出，不归入录入所在周／月。

预览在一致快照中获取完整日记、选定目标（最多20个）及其相关行动／当前反馈版本，分别展示覆盖、实际条数、未知日期和当前状态。目标当前状态不冒充过去周末的历史状态；没有足够历史事件时不声称“上周已完成几个目标”。期间内仅将有发生日期的反馈计入行为统计，未填日期的说明作为显式选择的补充资料，标为日期未知。

确定性摘要可在AI关闭时使用。AI输入另有上限：完整日记最多40篇；目标／行动／反馈合计最多200条；所有实际序列化来源文本及元数据合计24000码点，并受整体提示32000码点及供应商更严限制约束。先计算真实序列化预算，超限明确缩小目标／资料选择或改用较短自定义范围，不静默截断，也不用Top-K替代整月记录。自定义范围标为“所选范围”，不能继续称为完整月报。

### 5. AI回顾用有类型的来源，不凭关联编造事实

预览返回规范化范围、时间轴、目标集合、来源计数、预算和snapshotDigest。摘要包含完整匹配ID集合、各当前revision／删除状态、目标和行动状态、反馈occurredOn／效果及渲染版本；期间内新增符合记录、补录反馈或修正目标均可检出。排队、发送意图、发布和报告读取重新计算，不只复核最初的引用列表。

证据类型为 D（日记原文）、G（本人目标／标准）、A（本人确认行动）、F（本人执行反馈）。每个服务端ID绑定owner、实体ID、revision、字段／码点偏移和摘要。模型不得把G目标或A计划作为F已执行事实。关于实际效果的个性化结论需引用F及必要D；没有反馈只能建议下一次如何验证，不能声称行动已有效。

输出含期间覆盖、目标当前状态、原文观察、明确反馈、谨慎的可能模式、建议及资料限制。每条个人化陈述提供已发送来源白名单和逐字短引文；建议包括做法、依据、预计投入和复查方式，可由本人另行采纳为下一行动。仅文本安全展示，引用可跳回对应私密实体当前版本。类型、归属、版本、文本不匹配时不发布成功结果；合法引用本身不证明解释正确，真实模型人工验收仍必需。

报告读取发现任何选定来源集合变化即标STALE、隐藏旧分析正文与引文并提示重新预览；人工目标和反馈不因此删除。报告删除清理派生正文及任务私密载荷、保留最小幂等凭据；不撤销本人已采纳的行动、不承诺撤回云端数据或擦除已有备份。

### 6. 共享处理设施，分清同步摘要与异步分析

接口位于 /diary/auth/coaching，按原安全链和DiaryService本人校验。示意契约：

| 接口 | 行为 |
| --- | --- |
| GET /capabilities | 分别返回目标存储与期间AI可用性，不返回秘密 |
| POST /goals/search、GET /goals/{id} | 有界本人查询及明确的不存在／冲突状态 |
| POST /goals、PUT /goals/{id} | 带mutationId和expectedRevision的目标写入／状态确认 |
| POST /actions、PUT /actions/{id} | 手动行动，或本人确认有效来源后采纳 |
| POST /feedback、PUT /feedback/{id}、DELETE /feedback/{id} | 有版本反馈、修正和可追溯软删除 |
| POST /periods/preview | 无模型完整范围预览及确定性摘要 |
| POST /periods/reviews | 手动提交requestId＋预览摘要，HTTP202返回任务 |
| GET /jobs/{id}、POST /jobs/{id}/cancel | 状态查询和取消，不重新调用模型 |
| GET /reports、GET／DELETE /reports/{id} | 有界私密回看、来源核验和删除 |
| POST /export | 本人目标／行动／反馈有界导出 |

diary.coaching.enabled默认false；目标模块只依赖原日记PG及003，不依赖向量扩展、模型配置或AI表存在。diary.coaching.ai-enabled默认false，并与diary.ai.enabled及经过核实的第二阶段能力共同控制期间AI；依赖未就绪时只拒绝AI，目标保存继续。第三阶段不补完第二阶段任务或填写供应商。

period_job／period_report保存在新schema以保留旧表CHECK及指纹，处理逻辑复用第二阶段的客户端、状态枚举、证据校验公共部分和工作线程。通过显式任务处理适配接口接入同一worker，不新开定时线程／消费者。原问答／复盘与期间回顾按统一可观测队列、公平顺序和同一全局租约认领；任何表不能独立绕过共享预算。两套任务的未结束总量上限5、报告总量1000，每日生成尝试合计20次、embedding合计200块，沿用上海日期原子预留；无法确认跨来源额度时拒绝AI，不分别放大限额。

不能只在应用中检查队列长度。所有提交在同一owner控制行锁下统计两类任务并插入；worker持有原全局租约一次只处理一个任务或索引批次，不在HTTP期间占PG事务／连接。重启恢复两类未确定的RUNNING均为UNCERTAIN；取消、租约失效或账号变化后的迟到结果不能发布。终态／未知用量和可能收费提示复用第二阶段语义。

### 7. 交互、验证与交付边界

人工目标／反馈编辑使用明确保存按钮和未确认离开保护，复用幂等与版本处理工具的可用部分，不把所有表单硬接到只接受DiaryContent的保存器。页面及请求身份变化清空内存、停止轮询并丢弃晚到响应；正文、问题、反馈不进入URL或持久浏览器缓存。

测试全部使用虚构资料：一篇跨十几天、同日多篇、闰日、当前未结束月、周月边界、无日期和补录反馈、目标状态修订、重复采纳、两个标签页、源报告删除、排队及生成中新增匹配记录。验证完整期间汇总、引用类型和无反馈时拒绝推断。用真实PG和受控HTTP证明共享单并发、全局额度、崩溃恢复和网络期间释放连接，并验证原MySQL博客及保存不回归。

生产仍需实际模型语料评测、既有PG512MiB上限下的容量／同时保存测量、全量加密备份及新库恢复。恢复须比较三个schema（若AI未安装则按实际对象清单）与行级策略、历史／幂等和多类型引用，不因生成dump而宣布成功。本次没有生产迁移、模型费用或代码提交。

## Risks / Trade-offs

- [把建议自动当成事实] → 本人确认采纳和实际反馈独立，计划／执行来源类型不同，模型无写权限。
- [跨日记录产生假统计] → 只计篇目和明确反馈，展示缺失及期间外内容，不推算逐日行为或完成率。
- [第二阶段未完成导致依赖漂移] → 实施前复核源码、契约和测试；核心目标独立可用，期间AI依赖单独验收。
- [迁移破坏旧结构指纹] → 新schema保存本阶段对象，原001／002再次验证；不篡改既有版本凭据。
- [新任务绕过额度或并发] → 共享控制锁、原子预算和全局worker租约，真实跨类型争抢最后额度测试。
- [来源更新或删除后仍展示旧观点] → 范围摘要、多类型当前版本核对、STALE正文清理；人工记录保留。
- [完整月报超过模型或小服务器预算] → 明确拒绝／缩小范围，真实序列化计量，不静默采样或扩容。
- [周月回顾让人误以为因果证明] → 显示自述反馈、样本数、无数据和推测，人工核对真实模型表现。

## Migration Plan

1. 记录当前分支、第二阶段未完成项及无关改动；刷新GitNexus、逐符号impact并建立已有保存／权限／双库基线。
2. 在隔离PG执行003首次／重复／失败／漂移测试；重新运行原001，并在安装AI时运行002，验证core不依赖AI表。
3. 完成本人目标、行动、反馈及确定性期间摘要，先验证AI关闭、缺扩展、缺供应商仍可可靠保存。
4. 在第二阶段真实能力完成验收后，接入共享worker和多类型证据，运行并发／故障／真实浏览器及实际模型虚构语料验证；未选模型时保留相关项未完成。
5. 发布前说明新增schema、共享资源及供应商隐私费用；得到独立部署授权后备份、迁移并在目标和AI开关关闭状态部署，再分别启用。
6. 回退关闭coaching AI或整个coaching开关，保留所有人工记录、历史及备份；原日记和公开博客继续，禁止drop schema或清理原文。
