## Context

已实际浏览线上首页：全屏夕阳海报、分行过大的欢迎语、右侧低对比简介，正文多处口号高达一屏。首次请求失败显示 0/0，刷新后恢复 30/2；推荐封面破图。当前 Vue 3 + SCSS 已有浅色品牌变量，首页使用 Promise.all 统一赋值，Banner catch 引用不存在的变量。旧规范保留轮播和电影化全屏要求，与当前实现及本次批准方向不符，本变更同步更新。

## Goals / Non-Goals

**Goals:** 紧凑介绍、优先文章、真实经历、完整封面、独立可恢复的数据加载、窄屏和键盘可用，最后验证前台部署。

**Non-Goals:** 不改后台编辑界面、配置内容、数据表、API、导航或详情路由；不安装新界面库，不重启后端，不进行 Git 提交/推送。

## Decisions

1. 阅读方向：面向技术读者与招聘者的个人博客，浅色编辑式布局。DESIGN_VARIANCE=5、MOTION_INTENSITY=3、VISUAL_DENSITY=5。沿用蓝色 accent、现有中文 sans 字体与圆角变量，只做交互反馈，不做自动动画。保留真实 Banner 和封面，不生成替换图，遵循既有品牌素材优先原则。
2. Hero 用左侧可配置标题/说明/按钮、右侧有限高度的静态 Banner。主标题约 32-52px，正常配置在桌面最多两行；长配置允许自然增高不截字。简介放在图片下方，统计放在紧邻 Hero 的紧凑摘要行。相比暗色蒙版海报，浅色文字区更稳定可读；不硬改后台文案。
3. Main 顺序为统计、近期写作、经历、简短关于入口。推荐封面 contain，文字放图片外；最新列表排除已展示的推荐，不漏掉其他最新文章；无推荐时仅选择最新首篇作后备。经历保留既有可用字段并去重重复成果，技术栈作为附属信息而非大型区块。
4. 用可单测的小型异步资源工具管理 loading/success/error，各请求独立更新，不等待整组 settled。保留成功数据、错误局部显示、重试不清空其他模块、同资源并发受控、组件销毁后忽略结果。未知计数显示“加载中/暂不可用”，成功 0 才显示 0。
5. Banner 改原生 img + 固定比例容器、高优先级提示，移除 Canvas resize 与多层装饰，保留第一张有效图和失败占位。推荐图片故障只影响图片区，不遮盖文章入口，提供一次用户触发的重新加载。
6. 首帧 HTML 使用浅色相似结构骨架，避免先显示另一套完整口号；保留标题、favicon、脚本入口和可用 noscript 提示。

## Risks / Trade-offs

- 图片源本身不可达 → 前端不能修复 OSS 权限，仅提供明确占位、重试与可读文章入口，不暗中改变存储访问权限。
- 异步模块仍可能因不同返回时间产生位移 → 预留主要媒体与加载区域，局部填充；不把结果归因于固定 3Mbps 而不测量。
- 旧部署脚本会覆盖 Nginx 并重启后端 → 本次单独打包前台，核验远端路径/配置，只发布新资源和原子替换入口，保留旧哈希文件与完整备份，验收失败恢复入口。
- 动态超长标题 → 减小基础字号、允许换行和增高，360/768/1440 视口验证，不截断后台文字。

## Migration Plan

完成测试、构建预算与浏览器检查；比较并同步本次四项 delta specs，归档本次变更。部署前记录线上目录、入口散列及备份位置，上传验证过的 dist，仅切换前台入口，不删除旧资源。验证首页/文章/经历路由、关键接口、gzip/缓存头和线上新布局；记录结果及回滚命令。
