## Context

当前管理端采用 Vue 3、Ant Design Vue、Pinia、UnoCSS 和 md-editor-v3。`workspace.scss` 使用暖灰和陶土色，`stores/app.ts`、工作台及列表组件仍保留冷灰硬编码。公共 PageContainer 标题被注释，列表与编辑页共同使用 inline 筛选表单容器。文章列表有 12 列、1540px 横向滚动；编辑页把 SEO 等元数据放在正文前。

本设计依据当前源码审查，尚无已登录页面的视觉基线。现有工作区包含用户未提交修改，不能覆盖或回退。GitNexus personal-website 索引在审查时落后 7 次提交，实施前须复核；修改函数前执行 impact，UNKNOWN 须补充源码确认，HIGH/CRITICAL 须报告。

## Goals / Non-Goals

**Goals:**
- 统一浅色管理端视觉，沿用现有 Ink and Ember 品牌。
- 让页面标题、主要动作、筛选、数据内容层级稳定。
- 以文章管理和写作为核心，改善桌面及窄屏操作体验。
- 保持业务接口、权限及既有文章发布契约。

**Non-Goals:**
- 不替换框架、组件库、编辑器，不安装依赖。
- 不修改公开博客、登录页、数据库、后台 API、权限或菜单数据结构。
- 不增加自动保存、数据导出、统计接口、列配置持久化或新仪表盘图表。
- 不恢复深色模式，不重做全后台每个业务页面。

## Decisions

### 1. 沿用现有品牌，以语义主题统一组件
以现有暖灰 canvas、白色 surface、深色 ink、陶土 accent 为基准，使 Ant Design token 与 CSS 变量采用同一组值；菜单 hover/selected 由同一 accent 衍生。语义状态色仅用于成功、警告和危险，不用于强调普通编辑或关闭操作。减少全局网格、模糊和大阴影，以轻边框分组。

选择复用现有配置与工具，不新增主题框架；逐页覆盖 CSS 会继续造成漂移。基础间距采用 4/8/12/16/24/32px，桌面页边距 24px、窄屏 12px，表面圆角统一为 8px，弹窗可保留 10px。标题建议 22px、正文/控件 14px、辅助信息 12px。

### 2. 公共页面容器承载页面身份
恢复 PageContainer 标题及 extra 操作插槽，默认取当前菜单标题，允许页面覆盖。面包屑降为辅助，多标签保留切换、关闭与刷新行为，采用较轻外观。修正负 margin 与内容边距不匹配，避免标题重复。公共列表继续复用 `components/layout`，但筛选及工具栏与页面标题分层；页面专属结构不全部塞入公共组件。

### 3. 列表围绕文章标题组织
默认展示文章（封面+左对齐标题）、分类、状态、访问量、发布时间、操作；编号、作者、类型、标签、置顶信息在文章单元辅助区或“更多信息”弹层查看，不丢失信息。访问量右对齐，日期直接呈现年月日，完整时间可辅助查看。状态和置顶保留原更新能力，放在明确的“更多”动作/设置弹层中，避免每行常驻多个输入控件。

页面主操作为“新建文章”，普通编辑使用中性文字动作，危险删除使用 danger 语义与中文确认。批量选择、删除、单选编辑和分页保持可用；保留原筛选字段，将低频置顶条件放到可展开区。小屏允许表格内部横向滚动，主要动作不可依赖 hover。

### 4. 编辑页采用写作主体与发布设置
编辑页使用 PageContainer 和现有表单控件，不再复用列表筛选布局。标题和正文构成主体；桌面宽度达到 1200px 时在右侧呈现约 300px 设置栏，否则上下排列。封面、分类、标签、类型、状态和置顶集中在设置区，SEO 默认折叠。发布/更新操作放在可达的操作区，可采用容器内 sticky，需预留空间且不遮挡正文、弹层或移动键盘。

编辑器保留已有工具栏及上传处理，按可用高度设最小高度，取消表单加固定 80vh 造成的无意义长页面。按钮按“发布文章 / 保存修改 / 保存草稿”的已有提交语义呈现：草稿仍使用现有 status=3 流程，不新增保存协议。上传清理、防重复提交、失败保留内容、成功返回列表的逻辑保持原契约。

### 5. 工作台聚焦现有数据与快捷任务
保留文章、评论、留言、经历指标与现有快捷路由，突出新建文章、管理文章、处理互动。移除面向实现的“高密度内容运营入口”等说明。每个指标区分 loading、成功零值和失败，提供失败重试；使用现有接口，不虚构待审核数量或趋势。隐藏评论页未实现的导出按钮，统一“置顶”、中文确认及查看前台等文案。

## Risks / Trade-offs

- [全局样式影响已有页面] → 管理端范围内调整，抽查文章、评论、站点信息、用户与角色页面；避免对公开端和登录页新增全局影响。
- [标题恢复出现重复] → 检查 PageContainer 的 content/title 插槽消费者，逐处处理重复标题，不顺带重构业务逻辑。
- [列表信息降级影响熟练操作] → 信息仍可从辅助区或显式更多入口访问，保留状态、置顶与批量操作。
- [编辑页重排影响校验、上传和导航] → 沿用数据和提交方法，执行发布成功、失败、封面异常与重复提交场景。
- [无可用登录态或后台服务] → 如实记录视觉验收阻碍，不以源码检查替代浏览器验收，不伪造运行结果。
- [现有未提交修改和过期图索引] → 记录实施前差异，增量修改；图索引无法更新时明确不确定范围并结合当前源码复核。

## Migration Plan

按基础主题与公共布局、文章列表、编辑页、工作台与文案顺序实施。运行管理端类型检查、构建、分页和路由检查；检查 1440、1280、768、390px 视口以及键盘操作。无需数据迁移。部署属于后续独立操作；回滚仅恢复本变更的前端修改，不覆盖其他工作区成果。提交前执行完整 GitNexus detect_changes，partial/truncated 不作为通过证据。
