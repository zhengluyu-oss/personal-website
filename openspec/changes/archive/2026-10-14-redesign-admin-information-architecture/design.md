## Context

管理后台位于 `blog-frontend/luyu-admin`，使用 Vue 3、Ant Design Vue、动态路由和后端返回的菜单/角色权限数据。已有用户、角色、菜单和权限管理页面；菜单项和授权能力存在，但入口分散且信息层级不足。后台重构必须保留现有路由和授权数据语义，不能仅靠前端隐藏菜单来替代访问控制。

## Goals / Non-Goals

**Goals:**
- 让管理员能从清晰的业务分区快速定位后台功能，尤其能直接找到修改用户可见模块的角色/菜单权限设置。
- 统一导航、页面标题、内容分组、表格和表单的视觉层级，并保持窄屏可用。
- 保持服务端动态菜单、权限指令、路由守卫与现有 API 的授权结果一致。

**Non-Goals:**
- 不重写后台业务页面，不改变用户、角色、权限的数据模型和服务端授权规则。
- 不引入新的 UI 框架或依赖，不更改公开博客前台。
- 不在此变更中修改任何用户角色的实际授权配置。

## Decisions

- **沿用现有组件体系并建立一致的后台视觉规则。** 在 Ant Design Vue 和项目现有主题/布局设置上统一侧栏分组、页面标题与说明、内容宽度、区块间距、表格/表单密度和状态反馈；不引入新设计系统，避免重复组件和风格冲突。
- **以业务领域组织导航，系统授权集中在“用户与权限”。** 先盘点动态菜单和现有路由，再将现有菜单以明确的业务组呈现。用户、角色、菜单和权限入口在同一区域；保留菜单配置中的角色控制能力，并从角色/菜单页面提供到相关配置的直达路径。分组为展示层组织，不新建菜单数据或授权关系。
- **在不改权限语义的前提下优化可发现性。** 角色页面用清楚的“菜单权限”入口和说明指出权限影响范围；菜单配置继续按角色指定模块可访问范围。所有页面仍经现有后端权限和路由守卫校验。
- **响应式适配以可操作优先。** 桌面端采用分组侧栏和稳定的页面内容区；窄屏时收纳导航并保留当前分组/页面上下文，表格可横向滚动，表单控件保持可读与可点。
- **按现有动态菜单兼容边界实现。** 对已知系统管理路由做展示映射；未知、后续新增或第三方菜单仍沿用后端原始名称和可见性，避免菜单丢失。

## Risks / Trade-offs

- [动态菜单数据存在命名或层级差异] → 实施前检查线上/本地菜单结构；分组映射缺省回退至现有动态菜单，不过滤未知项。
- [视觉统一可能影响大量管理页面] → 优先抽取布局级样式与共享区块规范；仅对必要页面做有界调整，并验证内容管理、用户权限及系统页面。
- [入口移动会改变管理员的使用习惯] → 保留功能名称，增加明确的业务组标题和权限入口说明，不改路由地址。
- [仅展示权限状态容易被误认为已控制 API] → 明确界面文案；服务端鉴权仍是实际访问控制的依据。

## Migration Plan

1. 盘点现有菜单、路由和组件，确定展示分组与页面清单，不迁移或重写数据库权限记录。
2. 调整管理布局与权限入口，使用现有 API/权限校验。
3. 构建并验证导航可达性、角色/菜单权限操作流程、关键状态和窄屏显示。
4. 部署前保存当前后台静态资源；如导航或权限入口回归，可回滚静态资源版本，不涉及数据库迁移。

## Open Questions

- 具体菜单分组名称和每个页面归属应在实施前依据现有菜单数据清单最终确认；默认采用“内容管理、网站配置、用户与权限、系统运维”等直观分组。
