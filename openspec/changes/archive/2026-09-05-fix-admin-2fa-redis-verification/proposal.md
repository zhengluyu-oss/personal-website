## Why

管理员密码验证和验证码邮件发送均已成功，但提交邮箱验证码时，Redis Lua 脚本因当前 `RedisTemplate` 的 JSON 序列化结果无法被 `tonumber` 正确解析而抛出异常，最终向管理后台返回 HTTP 500。该缺陷会稳定阻断管理员二次验证登录，需要立即修复，同时避免把可预期的验证码失败显示成服务器异常或密码错误。

## What Changes

- 修正管理员二次验证挑战在 Redis 中的读写与 Lua 参数序列化方式，确保尝试次数、最大次数和验证码摘要均按脚本预期的字符串格式处理。
- 保持验证码挑战的五分钟有效期、五次尝试上限、单次消费和重发冷却规则不变。
- 将验证码错误、过期、挑战不存在和尝试次数耗尽转换为受控的认证失败响应，不再返回 HTTP 500。
- 调整管理后台验证码阶段的错误呈现，明确区分首次密码登录失败与二次验证码验证失败。
- 增加覆盖正确验证码、错误验证码、尝试耗尽、过期挑战和 Redis 序列化边界的自动化测试。

## Capabilities

### New Capabilities

- `admin-second-factor-verification-reliability`: 管理员邮箱二次验证的原子校验、错误响应和前端错误反馈可靠性。

## Impact

- 后端：`AdminLoginChallengeServiceImpl` 的 Redis 挑战存储与原子消费逻辑，以及相关认证异常处理和测试。
- 管理后台：登录页验证码阶段的错误状态与提示文案。
- 生产环境：需要重新部署后端；若包含前端提示修正，则同时部署管理后台静态资源。
- 不修改管理员密码、管理员邮箱、数据库结构、后端路由或验证码有效期规则，也不新增第三方依赖。
