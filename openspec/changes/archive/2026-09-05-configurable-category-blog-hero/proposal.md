## Why

博客聚合页切换文章分类后，右侧文章数量会变化，但左侧 Hero 眉题、主标题和简介始终使用同一套硬编码文案，无法体现各分类的内容定位。需要让站长在分类管理中维护每个分类独立的 Hero 文案，使分类页在视觉不变的前提下拥有清晰、准确的主题表达。

## What Changes

- 为文章分类增加可空的 Hero 眉题、主标题强调段、主标题后半段和简介字段，并提供向前迁移与回滚方案。
- 扩展分类管理 DTO、公开 VO 和保存逻辑，使后台分类新增与编辑表单可以填写、修改和清空 Hero 文案。
- 博客进入 `/blog/:slug` 时使用当前分类的 Hero 文案；未配置的字段逐项回退到现有默认文案。
- `/blog` 全部文章页继续使用当前默认 Hero 文案，不改变文章数量、分类路由、推荐文章和文章列表行为。
- 为字段长度、空白输入、移动端换行和旧分类数据补充校验与稳定降级测试。

## Capabilities

### New Capabilities

- `category-blog-hero-copy`: 定义分类级博客 Hero 文案的数据配置、后台维护、公开读取和前端回退行为。

### Modified Capabilities

- 无。

## Impact

- 数据库：`t_category` 新增 4 个可空文本字段及相应迁移、备份和回滚说明。
- 后端：分类实体、DTO、VO、分类新增/更新及公开分类查询响应。
- 管理端：网站管理下的分类新增/编辑表单和输入校验提示。
- 博客前端：`Pigeonhole/Category` Hero 文案计算与分类切换渲染。
- 不新增第三方依赖，不修改后端 API 路径，不改变现有分类 slug、文章详情路由或推荐文章规则。
