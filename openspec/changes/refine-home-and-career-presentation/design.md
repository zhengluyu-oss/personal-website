## Context

线上审查观察到：首页姓名与入口清楚，但介绍层次较多，当前实习卡片无摘要而保留双栏；经历列表标题在约 1000px 视口拆开“交付”，第一段展示通用职责，第二段摘要重复主要工作。首页有不同 ID 的同名 Redis 文章，精选摘要残留代码标记。手机端尚需实际验收，不能将桌面观察当作移动端结论。

现有技术栈为 Vue 3、TypeScript、SCSS，使用 brand 变量、后台首页文案与 Banner、公开经历与项目 API。本设计以现有页面为基础，面向招聘者与技术同行，也保留个人博客入口与生活气息。已有 `add-experience-project-showcase` 的公开项目能力是依赖，剩余后台/端到端任务独立保留。

## Goals / Non-Goals

**Goals:**
- 首屏快速识别姓名、职业方向和入口；工作经历首屏更早出现第一段真实经历。
- 缺少资料仍保持可信、紧凑；已有真实职责和成果更容易找到。
- 首页、经历列表和公司详情的摘要规则一致；保持路由、配置和品牌兼容。

**Non-Goals:**
- 不编写未经证实的履历或指标，不替用户修改生产内容，不删除或合并文章。
- 不新增 CMS 字段、数据库、API 或依赖；不重做导航、Banner、登录、项目详情页和主题机制。
- 不将所有同名文章判为重复，不新增基于标题的过滤。

## Decisions

### 1. 保留配置，减少视觉竞争

首页保留姓名、职业方向、主说明、辅助介绍、媒体与两组入口，但辅助说明采用较小字号和紧凑间距；首要按钮继续服从已保存的顺序。保持所有有效配置可读，不使用简单关键词过滤隐藏用户文案，不覆盖欢迎语或替换照片。替代方案是直接改写后台文案/强行交换按钮，但会改变用户内容意图，且不属于展示层修正。

### 2. 共用可预测的经历摘要规则

在现有 utils 范围内复用或增加小型纯函数：清理首尾与连续空白，摘要优先 projectSummary，其次第一条非空 highlights；剩余亮点按标准化文本精确去重并排除摘要。空值不补职责。首页/列表使用同一规则与各自条数上限，详情保留完整职责，不把相似但不同的句子语义合并。

首页没有摘要、亮点和技术时改为紧凑单行/单列身份区，将详情入口与公司岗位相邻放置；不得保留空证据列或空卡片最小高度。详情摘要不存在则省略概述框，正文全空时显示中性“暂无更多公开内容”。替代方案是生成通用职责，容易让人误认为真实记录，因此弃用。

### 3. 经历列表以扫描效率组织

保留时间线和倒序，删除 CASE、CURRENT 等装饰标签，当前状态用“在职”。仅保留“工作经历”页头与一个简短列表标题，缩小顶部和分区间距。固定标语在逗号处提供自然断点，对“交付”等词组保持完整；动态公司/岗位长文本允许换行，不使用整段 nowrap。

桌面岗位约 28–36px、年份约 24–32px，正文约 15–17px，日期/入口不低于 13px；手机正文不低于 14px，交互目标至少 44px。对当前线上数据，在 1440×900、1024×768 首屏内可见首条公司的名称、岗位与时间；360/390px 不横向滚动。用紧凑排版而非删减有效数据达成目标。

### 4. 公司详情突出个人贡献

顶部保留公司、岗位、时间和可选真实摘要。正文主栏按主要职责、公开项目、工作成果、公司背景（介绍与业务）、旧 Markdown 补充排列；各空区块隐藏。桌面辅助区保留必要元信息，手机避免重复资料面板先占满多屏。保持现有项目链接、公开可见性、安全 Markdown 和返回路径，项目空态为次级提示。相比另造新项目聚合页面，此方案复用现有 API 且不增加首页逐条查询。

### 5. 首页文章导读与重复边界

改进 homeExcerpt：移除 fenced code（含语言名）、图片、HTML 标签与独立箭头分隔行，保留链接文字与正常行内技术词，清理开头重复标题和独立“前言”等结构标签，再沿用长度限制；清理后为空不显示摘要，不生成正文外结论。继续作为纯文本插值输出。

推荐接口选中的文章显示“精选文章”上下文，最新降级显示“最近发布”；分类保持独立。文章仍按 ID 去重、按现有推荐/最新规则选择。同名不同 ID 保留，在交付记录中标出待站主核对项，不能以算法隐藏真实文章。新增摘要字段虽更理想，但涉及后台和数据契约，本轮不采用。

### 6. 验收与样式维护

只整理本次触及的重复 SCSS 声明，避免再叠一层覆盖，保留既有品牌、焦点与减少动画策略。针对纯函数行为补测试；视觉使用现有浏览器工具验收，测试夹具与请求替身限定本地，不向生产写演示履历。

## Risks / Trade-offs

- [真实资料不足仍影响说服力] → 布局自适应，并交付资料清单：系统背景、本人负责部分、可公开结果、可用截图；不把补资料作为本次实现阻塞项。
- [精简辅助介绍不能消除已保存文案的重复语义] → 完整保留配置，仅调整层级；文案编辑作为可选后续内容工作。
- [摘要清理误删技术信息] → 只删除结构性块/标记，测试行内代码、链接、中文与空内容，不泛化删除英文单词。
- [两项变更触及同一经历文件] → 实施前核对工作区和原变更任务，以当前实现为基线，不覆写已有功能或勾选未验收项。
- [紧凑排版降低可读性] → 保持字号/触控下限，对长公司名和 900px 附近断点实测。

## Migration Plan

无需数据迁移。完成本地行为测试、路由检查、博客构建和截图验收后交付 diff；后续发布仅需要博客静态资源，生产部署需后续明确指令。回退恢复上一版博客构建产物即可，数据库和后台配置保持不变。

## Open Questions

无阻塞设计问题。当前实习的具体项目、贡献与成果以及同名文章是否重复，需要站主后续提供/核对；本实现对资料缺失有完整处理方案。
