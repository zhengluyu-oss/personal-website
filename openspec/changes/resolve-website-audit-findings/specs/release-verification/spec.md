## ADDED Requirements

### Requirement: 前台测试与类型检查是正式构建门槛
公开前台 SHALL 在正式构建前完成现有单元测试和 TypeScript/Vue 类型检查；SEO 测试 MUST 能在项目声明的测试命令中正确加载模块，现有类型错误 MUST 被修复而非整体跳过。

#### Scenario: 运行前台单元测试
- **WHEN** 开发者或 CI 运行前台声明的测试命令
- **THEN** 全部启用的测试通过，SEO 用例不会因 `@` 别名解析失败而中断

#### Scenario: 运行前台正式构建
- **WHEN** 前台代码存在 TypeScript/Vue 类型错误
- **THEN** 正式构建失败并显示对应错误

#### Scenario: 前台代码通过检查
- **WHEN** 测试、类型检查与资源预算都满足要求
- **THEN** 前台正式构建成功并产出可部署文件

### Requirement: 后端关键测试可重复运行
后端默认测试命令 SHALL 在文档声明的 JDK 与支持环境下运行启用的业务断言；日记 AI 的本地 HTTP 测试夹具 MUST 不因无法建立临时回环连接而使关键用例整体报错，且不得通过禁用这些用例掩盖失败。

#### Scenario: 运行后端默认测试
- **WHEN** 在受支持的开发环境或 CI 中执行后端默认测试命令
- **THEN** 启用的测试没有测试夹具初始化错误，失败时能定位到实际业务断言或明确的环境前置条件

#### Scenario: 回环测试环境不可用
- **WHEN** 测试运行环境不能创建所需本地 HTTP 连接
- **THEN** 测试给出可操作的环境诊断或使用等价的进程内夹具，关键业务断言仍被执行

### Requirement: 路由规则检查独立于无关代码改动
通用路由检查 SHALL 只根据路由定义和页面引用判断路由规则，不得因日记等无关模块存在未提交改动而失败。

#### Scenario: 日记模块存在改动
- **WHEN** 工作区仅有与路由无关的日记后端改动且路由规则正确
- **THEN** 通用路由检查通过

#### Scenario: 路由规则被破坏
- **WHEN** 页面路径出现重复、旧路径引用或违反既有层级规则
- **THEN** 通用路由检查失败并指出对应路径或文件

### Requirement: 自动化验证与环境说明一致
仓库 SHALL 提供持续验证工作流，运行前后台测试、类型检查、路由检查、构建与资源检查，以及后端默认测试；README SHALL 写明与包声明一致的 Node.js、pnpm、JDK 版本和本地复现命令。

#### Scenario: 提交变更后自动检查
- **WHEN** CI 对代码变更运行
- **THEN** 各检查给出独立结果，任何必需检查失败都会使验证失败

#### Scenario: 开发者按文档准备环境
- **WHEN** 开发者使用 README 所列版本和命令安装并验证项目
- **THEN** 版本要求与前后台包配置一致，且能复现 CI 的必需检查
