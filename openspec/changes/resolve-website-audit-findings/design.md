## Context

这项变更横跨公开前台、管理后台、Spring Boot 后端和工程检查。当前管理后台的 `vite-plugin-preload` 把所有异步资源写入入口 HTML；前台 `pnpm test` 的 SEO 用例无法解析 Vite 别名，`vue-tsc` 存在错误但正式构建不运行它；主安全链对未匹配请求默认放行；网站分享仅验证标题、网址、简介与正文；路由检查脚本包含某次经历展示需求的范围限制；当前 Windows JDK 下 15 个日记 AI 用例在创建本地 HTTP 夹具时失败。既有日记和知识库专用安全链，以及工作区内正在进行的日记 AI 改动，必须保留并避免覆盖。

## Goals / Non-Goals

**Goals:**

- 降低管理后台入口请求数，并建立可重复检查的入口资源预算；保持现有路由和按需加载行为。
- 让前台测试、类型检查、前后台构建、后端测试和路由检查形成可信的发布门槛。
- 让公共接口显式公开、其他接口默认拒绝，并保持已授权用户的现有业务权限。
- 保证公开的网站分享有封面，草稿编辑不受此限制。
- 修正文档版本要求、后台页面语言及缺失的自动化验证入口。

**Non-Goals:**

- 不重做页面视觉设计，不引入新的前端框架或后端认证体系。
- 不更改日记、知识库的专用权限模型或数据库表结构。
- 不把这次审查之外的功能需求和当前未完成的日记 AI 功能并入修复。

## Decisions

### 1. 管理后台资源按页面加载

移除或严格限制 `VitePluginPreloadAll()`，保留现有动态路由和编辑器按需导入。构建产物检查基于最终 `dist/index.html`，统计入口脚本、样式与 `modulepreload` 的数量和 gzip 体积；预算阈值先以移除全量预加载后的可重复基线确定，再设置显著低于当前 196 个预加载项的上限。保留 Vite 的正常入口依赖预加载，不以单纯调高 `chunkSizeWarningLimit` 作为优化。备选方案是仅拆分 `antd` 大包；它无法解决全量预加载语言包的问题，因此先处理预加载策略。后台入口 `<html lang>` 设为 `zh-CN`。

### 2. 统一可执行的验证顺序

前台测试使用与 Vite 路径别名一致的运行方式，或将 SEO 依赖改为可被 Node 原生测试解析的相对导入；选用改动更小且不影响运行时代码的方案。修复现有 `vue-tsc` 报错，再把类型检查放进前台正式构建。管理端维持现有类型检查与构建。通用路由检查仅检查路由规则；旧经历展示范围限制移至对应需求的专用检查或移除过期限制。新增 CI 工作流，分别安装两个前端声明的 pnpm 版本，使用满足管理端要求的 Node.js 版本、JDK 17 和可重复的 Maven 命令，执行类型检查、测试、路由检查、资源预算和构建。备选方案是仅更新 README；它不能阻止回归，因此保留自动化门槛。

后端日记 AI 的本地 HTTP 夹具先在受支持的 JDK/Windows 与 Linux CI 中复现和定位；抽取共用的测试夹具或改用进程内替身，避免仅因本地临时端口初始化失败而掩盖业务断言。需要真实 HTTP 协议的用例继续覆盖请求/响应行为；不通过禁用用例或忽略失败获得绿色结果。README 明确支持的 Node.js、pnpm、JDK 版本和完整验证命令。

### 3. 主安全链采用显式公开、默认拒绝

先从控制器映射、登录/注册/OAuth 回调、静态资源和现有前台请求整理按 HTTP 方法区分的公开接口清单。主安全链只对该清单 `permitAll`；需要登录的普通接口要求认证，业务操作继续由现有 `@PreAuthorize` 控制；未列入清单的请求 `denyAll`。日记与知识库的高优先级安全链不改变。以匿名、普通用户、管理员三类请求的契约测试覆盖公共读、登录流程、后台写入、未知新路径和跨链路边界。备选方案是继续默认放行并扩大注解扫描；它仍依赖每个新增接口都正确标注，不能形成默认安全边界。

### 4. 网站分享在发布边界校验封面

管理表单在状态为“公开”时要求封面地址非空并提示具体原因；后端 `saveShare` 在默认状态归一化后执行相同条件校验，避免绕过页面直接调用 API。草稿继续允许空封面。对已公开且缺少封面的记录先生成只读盘点，逐条补图或转草稿，不自动删除或伪造图片；发布迁移前确认前台列表和详情对已有记录的行为。备选方案是前台生成统一占位图；它可以缓解布局，但无法满足网站分享“每条公开内容有真实封面”的编辑要求。

## Risks / Trade-offs

- [默认拒绝误拦公开接口] → 先形成请求清单与自动化回归测试，按方法精确匹配；上线前对关键公开页面和登录流程做联调，并准备回退安全配置。
- [已有无封面的公开内容在新规则下无法继续保存] → 先盘点并补图或转草稿；保存时只按最终发布状态校验。
- [新增类型检查暴露大量历史错误，影响构建] → 按模块修复现有错误后接入构建，不以关闭规则、扩大 `any` 或跳过检查代替修复。
- [移除全量预加载导致首次打开重功能页面稍慢] → 对文章编辑器等页面做按需加载验证，必要时仅在进入相应页面后预取其依赖。
- [Windows JDK 本地通信失败与代码缺陷混淆] → 保留失败原始信息，检查 JDK/套接字前置条件，并在 Windows 与 Linux 运行同一业务断言。
- [CI 运行时间与依赖成本增加] → 将前后台和后端任务分开执行，缓存依赖，但不跳过关键验证。

## Migration Plan

1. 固定当前测试、构建和资源检查基线；列出全部公开路由及已有无封面的公开分享。
2. 先修测试与类型检查、路由检查和管理端预加载，建立可运行的 CI；更新文档和页面语言。
3. 完成网站分享发布校验及现有数据处理，再运行前后台联调。
4. 最后切换主安全链为显式公开与默认拒绝，验证匿名、普通用户、管理员及专用安全链。
5. 若生产出现公开接口误拦，回退该安全规则改动并依据失败的路由用例补齐清单；不回退已通过验证的独立前端和文档修复。

## Open Questions

- 现有生产库是否有公开且无封面的分享，以及每条记录应补哪张真实图片；实施时先只读盘点，再按内容决定补图或转草稿。
- 当前 Windows JDK 的本地通信异常是否来自 JDK 发行版/环境限制；实施时需在可复现环境确认根因，验收以实际业务断言通过为准。
