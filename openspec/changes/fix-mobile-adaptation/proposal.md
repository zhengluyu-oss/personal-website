## Why

生产站在手机浏览器（约 390px / 320px）上，前台与后台登录仍有定宽布局、空嵌入资源、触控目标过小和导航过载等问题，导致部分页面横向溢出或几乎不可用。移动端审计已定位高优先级缺陷，需要按页面修复，而不是再做一次全站重设计。

## What Changes

- 修复前台音乐页空 iframe：无有效地址时展示明确空态，避免占满视口的空白页
- 修复树洞发帖行定宽导致的小屏横向溢出，输入与提交改为可换行/弹性宽度
- 压缩移动顶栏：日记与知识库入口收进抽屉导航；品牌与登录触控区达到可用尺寸
- 改进博客分类条横滑可发现性（保留横滑或改为可换行芯片，并避免整页被轻微撑宽）
- 修复相册标题截断与脆弱的 `min-width` 约束
- 改进前台登录页小屏表单字号/触控高度，并理顺欢迎文案与顶栏叠层
- 修复后台登录卡片在 ≤320px 下的横向滚动与过矮输入框
- 网站分享详情 metadata 行改为可换行，避免长外链顶破布局
- 明确管理端宽表在手机上的可用策略（横向滚动可见性或桌面优先提示），不做整站后台移动端重写
- 知识库上线前补齐 Connections 等偏桌面布局的小屏断点（若本变更实施时该路由已存在）

## Capabilities

### New Capabilities
- `mobile-layout`: 前台与后台登录在常见手机视口下的布局、触控目标、横滑发现性与空态行为要求

### Modified Capabilities
- `blog-header-layout`: 强化窄屏顶栏触控尺寸，并将日记/知识库等次要入口从移动顶栏条移入抽屉，避免拥挤与未授权误入

## Impact

- 前台：`Header`、树洞、音乐、博客分类、相册、登录欢迎页、网站分享详情
- 后台：`admin` 登录页；管理表格页仅做有限可用性改进，不重做后台信息架构
- 配置：音乐前端 URL 缺失时的降级展示（不强制改生产密钥配置方式）
- 无 API **BREAKING** 变更；无数据库迁移
