## Context

生产站 `www.zhengluyu.com` 在 390×844 / 320×700 视口下的 Playwright 审查表明：首页、文章详情、网站分享列表已有可用断点；真正破坏体验的是少数定宽组件、空嵌入、移动顶栏过载，以及后台登录卡片。后端 API 无独立“手机布局层”；问题集中在 `kuailemao-blog` 与 `kuailemao-admin` 登录页。

现有 `blog-header-layout` 已要求窄屏不横溢且触控可用，但实现上顶栏仍塞入日记/知识库链接，品牌与登录触控区小于约 44px。`experience-mobile-layout` 仅覆盖工作经历，不覆盖树洞/音乐/相册/登录等。

## Goals / Non-Goals

**Goals:**

- 在常见手机宽度（至少 320–390px）消除 P0 级横向溢出与空白功能页
- 移动顶栏只保留：打开导航、品牌、搜索、登录/头像；次要入口进抽屉
- 博客分类条在保留可发现性的前提下，不因横滑容器撑破整页
- 后台登录在 ≤320px 可用；表格页给出明确的小屏可用策略（不重做后台）

**Non-Goals:**

- 不重做管理后台信息架构或把所有 `a-table` 改成手机卡片列表
- 不改变站点模块权限策略本身（日记/经历仍可受角色门控）；仅调整导航暴露方式
- 不强制在仓库写入生产音乐 URL；只做缺失配置时的空态
- 不把本次审计中的知识库生产 404 当作本变更的发布任务（仅当路由已存在时补 Connections 断点）

## Decisions

### 1. 按缺陷面修局部 CSS/结构，不做全站 layout 重构
- **选择**：逐页修 Header / TreeHole / Music / Category topic-nav / Photo / Welcome / admin login / WebsiteShare Detail
- **替代**：统一引入移动 layout 框架或重写组件库
- **理由**：多数页面已有断点；P0 集中在定宽与空资源，局部修风险更低

### 2. 移动顶栏减载 + 强化触控区
- **选择**：`move_nav` 去掉日记/知识库直链，保留抽屉内入口；品牌与登录外层点击区域 ≥44×44（可用 padding 扩大 hit area）
- **替代**：缩小图标或横向滚动顶栏
- **理由**：符合已有 `blog-header-layout` 窄屏要求，并减少未授权用户误进日记权限墙

### 3. 博客分类：保留横滑，补发现性，约束外壳宽度
- **选择**：继续 `overflow-x: auto` 的 chip 行；增加边缘渐隐或“滑动查看更多”提示；确保 `topic-nav-shell` 不把 `document` 撑宽
- **替代**：强制 `flex-wrap` 多行（分类多时占高）
- **理由**：16 个主题单行横滑更省纵向空间；问题主要是滚动条被隐藏导致不可发现

### 4. 音乐页：配置缺失时显式空态
- **选择**：`VITE_MUSIC_FRONTEND_URL` 为空则不渲染无 src 的 iframe，展示说明文案
- **替代**：在前端硬编码默认音乐站地址
- **理由**：避免空白全屏 iframe；配置仍由部署环境负责

### 5. 树洞输入行：弹性宽度 + 换行
- **选择**：去掉固定 `16rem`/`5rem`；`flex-wrap` 或纵向堆叠；去掉多余 `min-width: 100vw` 导致的滚动条抖动
- **理由**：直接对应 320px 聚焦后横溢的实测

### 6. 后台登录：流体宽度
- **选择**：小屏 `max-width: min(350px, 100%)` 或 `width: calc(100% - 2rem)`；输入高度抬到触控友好
- **替代**：单独做移动登录 UI
- **理由**：最小改动即可消除 320px 横滚

### 7. 管理表格：声明桌面优先，仅补可见横滑
- **选择**：保持 `scroll.x`；必要时加提示文案或确保表格外层可滚动提示；不重写列
- **理由**：后台主要桌面使用；本变更聚焦访客前台与登录可用性

## Risks / Trade-offs

- [顶栏减载后日记入口变少一层] → 抽屉菜单保留「我的日记」；登录后仍可从抽屉进入
- [分类横滑仍不如桌面一目了然] → 用渐隐/提示补偿；若验收不足再改 wrap
- [音乐空态暴露未配置] → 文案中性说明“暂未开放”，不泄露环境变量细节
- [仅修登录不够覆盖后台业务页] → 在 Non-Goals 与 tasks 中写明；后续可另开 change

## Migration Plan

1. 仅前端/后台登录静态资源发布，无 DB 迁移
2. 若生产需音乐功能，部署侧补齐 `VITE_MUSIC_FRONTEND_URL` 后重建前台
3. 回滚：回退前台/后台构建产物即可

## Open Questions

- 知识库 Connections 是否纳入本变更验收：仅当 `/knowledge` 已在生产路由中时必测；否则标为可选 follow-up
- 博客分类最终采用「横滑+提示」还是「换行芯片」：默认横滑+提示，实施时以 390px 验收为准可微调
