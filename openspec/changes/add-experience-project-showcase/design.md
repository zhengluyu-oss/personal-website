## Context

现有 Vue 3 博客提供 Experience/index.vue 和 Detail.vue，后台已有工作经历表单、Markdown 编辑及图片上传，Spring Boot/MyBatis-Plus 提供经历 CRUD。WorkExperience 中的 projectSummary 是经历摘要，并不是项目实体。当前公司、职责、成果及正文都属于单段经历。

保留既有技术栈和品牌变量。用户定位是个人开发实践与能力展示，不使用招聘导向文案。现有蓝色、浅底可复用，但大幅口号、装饰圆环、CASE 水印与多层阴影挤占内容，应在本模块内收敛。

## Goals / Non-Goals

**Goals:**
- 建立经历到多个独立项目的一对多关系，前后台均可维护和浏览。
- 三级内容清楚分工：经历概览、业务背景与项目目录、具体项目案例。
- 保留旧网址、旧内容、现有权限和安全渲染方式。
- 设计清晰美观，图片与真实贡献优先，可访问且适合移动阅读。

**Non-Goals:**
- 不增加独立公司管理实体，不处理跨公司共享同一项目或跨经历转移项目。
- 不自动拆分旧正文、不编写虚构案例，不增加评论、点赞、项目搜索或复杂统计。
- 不改变全站设计系统、文章模块或邮件；不新增 UI 框架或动效库。

## Decisions

### 1. 扩展经历并增加独立项目表

给 t_work_experience 增加 companyIntroduction、mainBusiness 对应的可空 TEXT 字段；它们是普通文本，支持换行。旧 content 保留为经历补充说明，projectSummary 保留为该经历摘要。

新增 t_experience_project：id、experience_id（必填）、project_name（必填，最多 150 字）、summary（必填，最多 500 字）、cover_image（可空 URL）、start_date/end_date（可空，结束不早于开始）、role_title（可空，最多 100 字）、tech_stack、contributions、outcomes（可空 TEXT，每行一项）、content（可空 MEDIUMTEXT Markdown）、order_num（默认 1）、status（0 草稿/未公开，1 已发布，默认 0）、is_deleted、create_time/update_time。索引覆盖 experience_id/is_deleted/status/order_num/id。

按现有软删除惯例采用逻辑关联，写入时验证父经历存在且未删除；禁用父经历仍允许后台维护项目。创建后 experience_id 不可修改，服务拒绝跨父级更新。新表比把项目塞入经历 JSON 更便于独立发布、详情访问和排序；单独建公司表暂不必要。

### 2. 接口和可见性

保留 /experience/list、/experience/{id} 与现有管理接口，经历详情附加公司背景字段，不向汇总返回公司长文或项目正文。

新增前台接口：
- GET /experience/{experienceId}/projects：父经历公开时返回已发布未删除项目的摘要列表（不含 content），按 order_num ASC、id DESC 稳定排序。
- GET /experience/{experienceId}/projects/{projectId}：返回完整项目与简要父经历身份；必须同时满足父经历启用且未删除、项目发布且未删除、归属匹配。

后台以 /experience/{experienceId}/projects/back 为前缀，提供 GET /list、GET /get/{projectId}、PUT /add、POST /update、DELETE /delete（id 数组），匹配现有 CRUD 习惯。修改表单中的 orderNum 和 status 即可排序/发布，不新增拖拽排序接口。

复用 blog:experience:list/add/update/delete 对应权限，因为项目是工作经历模块的子内容；服务端必须逐请求校验，不能仅隐藏按钮。批量删除必须所有 id 均属于当前经历，任一不符整批失败。只有准确的公开 GET 路径可匿名，不扩大整个 /experience/** 的匿名放行。复用 ResponseResult、AccessLimit、审计日志和 DTO 校验。

禁用父经历只影响公共可见性，不改变子项目状态；恢复父经历后原发布项目重新可见。删除父经历保留子数据且由父可见性规则隐藏，不提供孤儿项目公开入口或级联硬删除。

### 3. 后台编辑路径

在现有经历表单增加公司介绍、主营业务输入；列表增加“管理项目”，进入带公司/岗位标题的项目管理页，返回原经历列表。项目表展示名称、角色、状态、排序与操作。

项目编辑使用宽抽屉或独立编辑区域（复用现有后台组件）分为基础信息、个人贡献与成果、案例正文。新项目默认草稿，父经历自动关联且不可编辑；状态和保存结果清楚可见。复用 md-editor-v3、现有图片压缩/上传和错误提示。正文提供可选写作提示：业务背景、职责范围、关键问题、方案取舍、成果证据、复盘；提示不自动写入或发布。

### 4. 前台布局与视觉约束

设计方向：清晰、克制的程序员作品集。DESIGN_VARIANCE 6 / MOTION_INTENSITY 3 / VISUAL_DENSITY 4。使用现有字体、--brand-* 变量、圆角和图标，单一蓝色强调色；不用新字体和依赖。标题中文优先，不使用大号英文装饰与招聘措辞。

**汇总 /experience**：紧凑页头“工作经历”与一句说明；保留时间线索引、日期、公司、岗位、一段摘要、最多两条贡献及少量技术标签，链接“查看经历”。删除大幅结尾口号和重复长内容；不要使用看似事实的通用职责填补空数据。

**公司 /experience/:id**：面包屑；公司名为主标题，岗位与时间次之；左侧窄栏为任职信息及核心技术，右侧先展示公司介绍/主营业务、我的职责，再展示项目卡片。旧正文放在其后“经历补充”。小屏以相同顺序改为单列。无公司背景时不显示空壳标题，无项目时用一行真实空状态。

**项目卡片**：项目名称、用途摘要、个人角色、首条贡献/成果、最多四个技术标签和“查看项目”。桌面可两列，只有一个项目时自然单列，移动端单列。可选封面 16:10、contain 完整显示，无封面用文字布局而非强制装饰图；不用 hover 放大图片，整卡使用语义链接且不嵌套按钮。

**项目 /experience/:id/projects/:projectId**：面包屑“工作经历 / 公司 / 项目”，标题、简介和时间/角色；可选完整封面；正文区展示“我的贡献”“成果”和 Markdown 案例。宽屏正文旁设置由实际 h2/h3 生成的粘性目录，无标题不显示；小屏改为顶部可展开目录。底部提供返回公司经历及其他已发布项目链接。正文宽度约 48rem，外框沿用 72–84rem；内容截图最大宽度受限且不裁切。

标题桌面约 36–48px、手机 28–34px，正文 16px 左右、行高 1.7–1.9；用排版与分隔线建立层次，卡片轻边框，避免每段都包多层卡片。动画仅短暂边框/颜色变化，遵循 reduced-motion。触控目标至少 44px，焦点清晰，支持键盘，无悬停专属信息。

```text
经历汇总             公司任职经历                   项目案例
标题 + 说明          公司 / 岗位 / 时间              面包屑 + 项目概览
时间线索引     →     公司背景 + 我的职责       →     贡献 / 成果
公司、角色、摘要     项目 A / 项目 B 卡片            正文 + 章节目录
查看经历             原有经历正文                   返回经历 / 其他项目
```

### 5. 状态、路由与安全

扩展集中路由常量和精确匿名接口规则；Nginx 继续 SPA fallback，新增深链接必须刷新可访问。项目与公司详情监听 route params，切换 id 时重新请求，使用请求序号防止旧响应覆盖新页面。加载、失败重试、不存在/未公开与真实空列表分开；无权限项目不显示旧内容。

复用 sanitizeRenderedHtml 和 MdPreview。普通字段按文本渲染，封面 URL 限制为现有可信上传支持的 HTTP(S) 形式；目录通过组件提供的标题信息生成，避免未经清洗的 HTML。项目设置独立 title/description/canonical，离开页面不残留旧 SEO。只使用真实填写内容，不生成指标。

## Risks / Trade-offs

- [三端加数据库需要协调] → 加法迁移优先、旧接口兼容，先数据库后服务再前端；提供上线与回退清单。
- [旧正文和新项目内容重复] → 保留旧正文并明确标记补充说明，由作者逐步整理，不自动搬运。
- [父级隐藏而项目仍泄露] → 公共列表和详情统一父子校验，覆盖匿名、直链、错配、禁用和删除测试。
- [少量真实内容撑不起丰富布局] → 空字段不渲染，无项目无封面不留巨大空框，先用真实一段经历做验收。
- [长文、长标题、代码影响手机布局] → 容器 min-width:0，代码/表格局部滚动，360px 起检查不出现整页横向滚动。

## Migration Plan

1. 编写幂等 SQL：可空公司字段、新项目表及索引；不更新既有正文，不插入演示项目。
2. 在本地/测试库验证初次与重复迁移及旧经历可读。
3. 实施前后端、运行权限和可见性测试、构建，完成浏览器视觉验收。
4. 部署前说明迁移影响并保存可还原的原表数据；用户明确部署后按数据库→后端→管理端/博客端顺序上线。
5. 验证旧网址、新详情深链接、后台草稿发布链路。回退时恢复旧应用/静态资源，保留新增字段和表以免丢失新内容，不自动删表。

## Open Questions

无阻塞性问题。视觉按上述方向实施，项目材料由用户在后台维护；本轮仅规划，不执行生产变更。
