## Why

当前工作经历只有汇总和经历详情两级，一篇正文同时承担公司背景与项目案例，无法独立维护、浏览多个项目。需要形成工作经历—公司任职经历—项目案例三级展示，让访客理解真实业务背景、个人职责与开发能力。

## What Changes

- 保留现有经历及网址，补充公司介绍、主营业务。
- 新增关联任职经历的项目，支持简介、封面、参与时间、角色、技术栈、贡献、成果及 Markdown 详情。
- 后台工作经历增加管理项目入口，支持项目增改、排序、草稿/发布和软删除，复用编辑器与图片上传。
- 公司经历页突出背景、个人职责及项目卡片；新增 `/experience/:id/projects/:projectId` 项目详情和面包屑导航。
- 汇总页保留时间线、精简重复长内容；三级页面统一为浅色、蓝色点缀的编辑式作品展示，兼顾手机与键盘操作。
- 父经历未公开时，子项目不得公开访问；旧数据无需自动拆分或迁移为项目。

## Capabilities

### New Capabilities

- `experience-projects`: 项目数据、管理接口、后台编辑、公开查询与父子可见性规则。
- `experience-project-showcase`: 项目详情、公司项目入口、导航、内容安全与响应式展示。

### Modified Capabilities

- `work-experience`: 增加公司背景字段及公司经历页项目列表，保留旧正文与原路由兼容性。
- `experience-editorial-layout`: 明确汇总、公司、项目三层阅读重点及统一视觉层次。

## Impact

- 数据库：给 `t_work_experience` 增加可空字段，新增 `t_experience_project` 及查询索引，提供可重复执行的迁移。
- 后端：扩展 WorkExperience DTO/VO 与服务，新增项目模块及权限保护；现有接口保持兼容。
- 管理端：扩展工作经历表单与项目管理界面。
- 博客端：调整 Experience 页面、新增项目详情、路由和 API 类型；复用现有品牌样式和 Markdown 安全渲染。
- 不引入框架或大型依赖，不改文章、邮件及其他模块，不生成虚构经历或成果。
- 上线顺序为数据库迁移、后端、管理端与博客端；提案阶段不执行迁移和部署。
