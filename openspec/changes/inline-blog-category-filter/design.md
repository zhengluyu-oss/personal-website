## Context

当前博客聚合页 `/blog` 与分类详情 `/blog/categories/:id` 共用一个 Vue 组件，但通过两套互斥模板渲染，因此分类点击会替换整个页面结构。分类 URL 使用数据库 ID，桌面菜单、移动菜单、文章详情和分类页各自拼接链接，容易产生不一致。

本变更仅调整前台页面路由与交互。现有 `categoryList`、`whereArticleList` 和 `getArticleList` API 继续使用分类 ID，后端与数据库不承担 slug 存储或解析职责。路由深度继续限制为不超过三级，并遵循不保留旧路由的既有要求。

## Goals / Non-Goals

**Goals:**

- 让所有分类都在 `/blog` 聚合页原有文章区域内筛选，不再出现独立分类详情版式。
- 以稳定、短小、可分享的 `/blog/:slug` 表达当前分类。
- 让直接访问、刷新、前进后退和站内点击得到相同筛选结果。
- 集中分类 slug 生成与链接构造，避免各组件重复拼接 URL。
- 保持现有后端 API、数据库和文章规范路由不变。

**Non-Goals:**

- 不为分类新增数据库 slug 字段或后台编辑能力。
- 不兼容或重定向 `/blog/categories`、`/blog/categories/:id`。
- 不改变标签、时间归档和文章详情页面的展示方式。
- 不重新设计聚合页刊头、文章卡片或分类按钮视觉。

## Decisions

### 1. 使用单一聚合页组件承载全部与分类状态

路由 `/blog` 和 `/blog/:slug` 均指向现有聚合页组件。组件始终渲染刊头、分类导航和同一文章内容区域，根据路由 slug 决定调用全量文章接口还是分类文章接口。分类变化只替换文章区域的数据状态。

选择该方案是因为它符合用户连续浏览预期，并能复用现有精选文章与文章网格。备选方案是在父路由中嵌套分类子组件，但仍会引入额外页面边界和重复布局，因此不采用。

### 2. 用纯前端工具集中生成与解析分类 slug

新增可测试的分类路由工具，输入完整分类列表后输出 `{categoryId, slug}` 映射，并提供按 slug 反查分类的能力。所有导航入口只调用该工具或共享 composable，不直接拼接分类 ID。

转换规则：

- 连续中文文本逐字转换为无声调拼音首字母，例如“技术笔记”为 `jsbj`。
- 英文文本只取第一个由字母或数字组成的单词并转为小写，例如“Network Security”为 `network`。
- 中英文混合名称按原始出现顺序组合有效片段并用连字符连接，例如“AI工具”为 `ai-gj`。
- 去除重复连字符及首尾连字符，最终只允许小写字母、数字和连字符。

项目目前没有拼音依赖。实现时先检查现有工具是否能够可靠覆盖中文；若不能，采用体积可控、支持按需构建的拼音能力，或建立项目内可测试的常用汉字首字母映射。不得把大型全量字典直接加入首屏同步包。

### 3. 以确定性 ID 后缀解决冲突和保留字

保留 slug 包括 `articles`、`tags`、`archive` 以及路由表中的其他 `/blog/*` 固定子路径。生成结果为空、与保留字冲突或与其他分类重复时，追加 `-<categoryId>`。同一分类列表无论刷新多少次都产生同一 URL。

备选方案是遇到冲突只取第一个分类，但会让其他分类不可访问；使用随机后缀则破坏 URL 稳定性，均不采用。

### 4. 路由状态驱动请求并防止过期响应覆盖

组件先加载分类列表并解析 slug，再以分类 ID 调用现有筛选接口。路由变化触发请求时使用请求序号或等效机制，只有最近一次请求可以写入视图，从而避免快速点击多个分类时旧响应覆盖新结果。

加载时保留刊头和分类导航，在文章区域显示与最终布局匹配的骨架；无文章时显示当前分类名称相关的空状态；解析不到 slug 时进入已有 404，而不是回退到全部文章。

### 5. 聚合页元数据与规范地址跟随筛选状态

`/blog` 保留固定博客 TDK。分类状态使用分类名称生成页面标题、描述和 canonical URL；浏览器前进后退时同步更新。文章页面仍使用 `/blog/articles/:id`，静态路由优先于动态 slug 路由。

## Risks / Trade-offs

- [中文首字母转换覆盖不完整] → 为转换工具建立代表性中英文、混合、符号和生僻字测试；无法转换的分类使用确定性 ID 后缀保证可访问。
- [动态 `/blog/:slug` 与固定子路由冲突] → 维护显式保留字集合，并在路由测试中验证静态文章、标签和归档路由优先匹配。
- [分类改名导致 URL 改变] → 当前 slug 由名称派生，这是不增加数据库字段的明确取舍；后续如需永久 slug 再单独引入后台可配置字段。
- [快速点击造成文章列表闪回] → 使用最新请求标识并为筛选区域提供稳定加载状态。
- [旧分类 URL 失效] → 按项目既有不兼容策略直接进入 404；发布前一次性审计全部内部链接。

## Migration Plan

1. 增加 slug 工具与测试，确认现有分类得到唯一且不冲突的结果。
2. 更新路由表和聚合页为 `/blog`、`/blog/:slug` 单页筛选结构。
3. 更新桌面菜单、移动菜单、文章详情分类入口及其他分类链接。
4. 扩展路由审计，验证旧路由不存在、路由不超过三级且后端 API 基线未变化。
5. 构建并部署前台；验证直接访问、刷新、前进后退和快速切换。
6. 回滚时恢复上一版前台静态产物；后端与数据库无需回滚。

## Open Questions

无。命名规则、旧路由兼容策略和后端边界均已由需求与现有规范确定。
