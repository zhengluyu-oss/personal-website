## Context

首页 `Home/Main/index.vue` 已以独立区块展示工作经历、博客、网站分享和知识库。模块查看权限由 `useSiteModuleAccess` 的状态提供；日记页复用该策略，并通过 `/diary/view/capabilities` 与 `/diary/view/entries/search` 提供只读访问。日记内容可能敏感，首页必须在权限未确认、撤销或切换账号时失败关闭。

## Goals / Non-Goals

**Goals:**

- 仅向当前具备日记查看权限的用户显示首页日记区块及最近记录。
- 以现有首页视觉语言呈现最近三篇未删除日记的标题和写作日期，并链接到现有日记页。
- 让空列表、加载、接口失败和权限变化都具有明确、安全的状态。

**Non-Goals:**

- 不在首页展示日记正文、AI 分析、历史版本或站主管理操作。
- 不新增权限规则、后端端点、数据库字段或依赖。

## Decisions

1. 首页通过现有 `canViewModule('diary')` 控制区块可见性；未授权时整个区块不渲染。相比展示受限卡片，这符合“只对有日记访问权限的用户显示”的要求。真正的数据访问仍由服务端每次判权，不依赖前端隐藏作为安全措施。
2. 获授权后先读取 `/diary/view/capabilities`，确认 `allowed` 与 `available`，再复用只读搜索接口读取第 1 页、每页 3 条、`deleted: false`，按写作时间的既有排序展示标题和日期。相比调用管理接口或新建首页接口，可保持既有数据边界。若接口返回拒绝或能力不可用，立即清空预览。
3. 预览仅保留并显示列表记录的标题与日期，不额外请求单篇详情来生成摘要。现有搜索接口会返回完整记录；客户端收到后立即映射为预览字段，不把正文放入首页状态。完整内容通过 `/diary` 阅读。
4. 首页区块放在博客文章之后、网站分享之前，沿用 `section-shell`、`section-header` 和卡片样式。小屏单列，链接可键盘操作。日记列表项统一链接到现有日记页，不引入该页面尚不支持的深链参数。
5. 权限状态或登录身份变化时清除本地预览，并防止旧请求回填。实现时复核模块权限刷新与 token 的现有响应机制；必要时只在首页增加局部监听与请求序号，不改变全站权限架构。

## Risks / Trade-offs

- [权限撤销与异步请求竞争] → 清空旧数据、取消过期结果的渲染，并由服务端对每次只读请求实时判权。
- [首次访问权限尚未加载] → 在访问确认前不渲染区块，避免短暂显示旧日记。
- [现有列表接口包含正文] → 仅在已获权限后请求，首页状态只保留标题与日期，不渲染或持久化正文；未来若要进一步减少传输可另行设计摘要接口。

## Migration Plan

仅发布博客前端。上线后分别用有权账号、无权账号、退出登录和窄屏验证；如需回滚，回退前端版本即可。
