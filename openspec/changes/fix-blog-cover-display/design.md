## Context

当前聚合页组件为 `src/views/Pigeonhole/Category/index.vue`。桌面推荐位使用 flex 两栏和 stretch，封面主图绝对定位，封面本身没有比例约束，高度由文字撑开；专属规则将主图覆盖为 `object-fit: cover`。下方卡片已用 16:10 和 contain，但两个区域都在 hover 时将主图放大 1.018 倍。

线上工作反思封面为 1586×992，接近 16:10；截图封面区域约 576×285，导致明显上下裁切。现有 `blog-featured-cover-layout` 已要求全断点 16:10，实施需修复该偏差，并更新其原先保留列表 hover 行为的要求。

## Goals / Non-Goals

**Goals:**
- 聚合页及分类页推荐封面在所有断点固定 16:10，与文字长度解耦。
- 主图完整等比展示，静止和悬停均不丢失边缘内容。
- 保留桌面左图右文、移动端上图下文以及现有视觉风格。

**Non-Goals:**
- 不改变文章内容、TDK、封面文件或数据库，不调整上传压缩和校验。
- 不改首页、归档页、文章详情等其他展示区域，不增加依赖或重构公共组件。
- 不在提案阶段实施或部署。

## Decisions

### 1. 用独立的封面比例约束布局

桌面推荐位采用两列等宽 CSS Grid（`minmax(0, 1fr)`），封面设置 `aspect-ratio: 16 / 10`、`align-self: start`，避免网格行被文字撑高时再次拉伸图片。文字区域保持垂直居中及现有标题/摘要行数限制；极端文字占高时允许整卡增高，但图片仍保持独立比例。900px 及以下改为单列，覆盖原 flex 断点规则，封面宽度充满所在列。

仅补 aspect-ratio 而保留默认 stretch 的方案容易再次受到文字高度影响；固定像素高度不能适应不同屏宽，因此采用上述独立比例布局。

### 2. 统一主图完整适配

移除推荐位专属 cover 覆盖，复用主图 `object-fit: contain`，保持居中。背景层仍可模糊铺满，它不承担内容阅读；主图必须完整。标准 16:10 图铺满，近似比例图允许极细背景边，其他比例图用现有柔和背景填充。

保留 cover 或要求用户重做更宽封面都不能满足已认可的 16:10 完整展示要求。

### 3. 移除主图 hover 缩放

仅删除聚合页推荐位和文章网格主图的 scale 规则，保留卡片阴影、边框、整体位移和焦点提示。背景层原有模糊放大不受影响。只缩小放大倍率仍会裁切靠边文字，不采用该方案。

## Risks / Trade-offs

- [桌面卡片更高] → 这是恢复 16:10 的预期结果，截图同等宽度下图片高度约由 285 增至 360 像素；检查下方列表间距。
- [非标准比例封面显示背景边] → 复用柔和背景并优先保证内容完整，验收横长图和竖图。
- [长标题、长摘要或窄桌面文字溢出] → 保留现有行数限制、最小宽度与内边距；在 901px 和长内容场景检查，封面不得随文字拉伸。
- [断点残留 flex 样式覆盖新布局] → 同步清理本组件受影响的断点规则，并检查 900px 两侧。

## Migration Plan

实施后运行项目已有构建检查，并在本地预览核对 `/blog` 和 `/blog/tdhz`。验收 1920、1280、901、900、390px 宽度，记录封面容器宽高及静止/悬停截图。使用现有封面或本地测试数据，不写生产文章。

发布沿用现有博客前端部署流程，部署前说明仅影响前端封面布局；本轮不发布。若上线后发现回归，可还原本次样式修改并重新构建发布，无数据迁移。
