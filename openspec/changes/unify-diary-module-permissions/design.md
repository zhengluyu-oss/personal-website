## Context

现有 SiteModuleAccessService 注册六个模块，使用MySQL策略及实时角色判断。日记独立使用PG，并在 DiarySecurityConfiguration、DiaryService.requireOwner、各业务服务及前台 capability 中重复限制站主。单改导航无法让授权用户阅读；直接删除owner限制则可能开放写操作或错误地把访问者ID当作数据归属。既有主规格仍描述仅站主访问，本变更显式覆盖相关要求。

## Goals / Non-Goals

**Goals:** 将日记作为第七个普通导航模块统一设置查看权限；让授权访客阅读同一站主内容及已有分析；保持可靠保存与管理权限边界。

**Non-Goals:** 多用户独立日记、跨站主共享体系、逐篇授权、新权限后台、自动公开历史记录、给访客开放付费模型调用。

## Decisions

1. 复用 `diary` 模块策略，后台沿用公开/指定角色、ADMIN及停用角色规则，不新增日记查看白名单。默认受限、不配置普通角色，沿用现有ADMIN访问语义；站主应具备现有管理员角色。策略缺失时只让日记失败关闭，不能使原六模块全部不可用。配置的owner只决定内容归属和管理操作资格，不再是查看资格。
2. 分离查看身份与数据归属。读取先判定当前访问者的模块权限，再从服务端配置取得站主ID，使用该ID进入既有PG事务/RLS。客户端不能指定owner，不能把当前访客自动当成owner。不放宽PG策略、不新增公共数据库账号。站主仍须通过模块查看规则；管理操作额外校验本人。
3. 对接口逐项分类，不能按HTTP方法粗分：搜索是POST但只读，索引/问答/复盘POST会写入或计费。授权访客可读取当前未删除篇目、日历，以及关联当前有效篇目的已保存问答/复盘/期间报告、目标行动展示；无权访问历史快照、墓碑、批量导出、任务明细和索引控制。AI报告若引用已删除/不再可展示记录，访客整份不可读，避免引用回流；站主保留原历史能力。capabilities增加可读与可管理语义并兼容旧客户端，PG/AI关闭时返回明确可用状态。
4. 匿名公开访问需连通安全链、只读能力探测及前台路由，不能保留强制登录拦截。所有日记端点仍在服务端授权；公共策略不会开放管理或生成。其他账号ADMIN可按普通模块规则阅读，但不能借该角色改写站主日记。
5. 复用无权限框架和统一模块数据源。导航保持可见、路由受限提示；授权后呈现只读日记及已有分析，隐藏编辑/导出/生成入口。写入组件与自动保存不在访客模式挂载，身份变化立即清除已读正文和查询缓存，不能因旧capability保留访问。
   日记路由的公共Header由工作区外壳单次挂载，站主管理组件不重复挂载Header，避免身份探测触发子组件卸载/重建循环；外壳同时管理只读页面的noindex标记。
6. 原有 no-store/noindex、不进公共全文搜索/推荐/站点地图、不持久化正文、不记录正文的约束继续适用。即便管理员选择公开也不自动建立SEO入口。后台公开选项明确说明将开放站主现有日记和可展示的分析结果；使用现有策略保存与确认交互。

## Risks / Trade-offs

- [公开授权覆盖所有当前日记] → 默认受限，后台清晰说明范围，发布不修改已有授权、不自动勾选公开。
- [共享读取被误用为写入身份] → 只读/管理服务入口分离，覆盖伪造owner、非站主ADMIN、POST搜索及付费POST的测试。
- [报告带回已删除原文] → 读取报告时检查关联当前记录；访客不读取旧版本和任务载荷。
- [六模块硬编码与部署探针失效] → 同步类型、夹具、测试与探针，兼容迁移顺序；不将缺失日记策略变成全站故障。
- [公开阅读后撤权无法撤回别人已复制内容] → 设置页直述公开影响；每次服务端读取实时检查，浏览器清除界面数据，不宣称能召回已传播内容。

## Migration Plan

先盘点读取/写入/计费/历史接口与所有owner调用，执行GitNexus影响分析。实现后在隔离数据库验证默认策略及幂等初始化；只新增MySQL日记模块策略，不迁移PG归属。上线前备份应用和策略，先受限初始化、发布兼容后端、更新前后台及健康探针，验证站主和未授权访问，再由管理员设置角色。生产验收使用合成记录，不自动调用真实模型。回退应用时保留PG数据和备份，恢复受限策略；多出的模块行可保留，避免破坏其他授权。

## Open Questions
