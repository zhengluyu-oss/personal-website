## Context

已确认问答取最多8片段、每篇2片段，完整复盘取已预览来源全文。首轮REVIEW禁止自定义question，追问统一QUESTION导致提示重新要求简短输出。发布前完整配置核对确认：日记未显式设置输出额度，沿用2000 token默认值；800属于知识库助手。旧代码默认/硬上限2000，正文20000字符、结果32000字符、字段数百字均会阻挡长回答。HTTP默认30秒与90秒租约绑定。

## Goals / Non-Goals

**Goals:** 完整范围自定义复盘、开放且分明的事实/假设/通用建议、可延续的追问、100000 token最大输出兼容、可靠取消及私密性。

**Non-Goals:** 不新增数据库结构、模型供应商、联网代理、自动行动或长期人物画像；本次不部署生产、不自动重放旧任务，不保证更长回答一定更有价值。

## Decisions

1. 保留QUESTION检索与REVIEW全文读取。REVIEW允许可选question，原请求null兼容。前端预览列出完整篇目及日期，允许带问题提交。用明确范围选择承担期间边界，不将自然语言“最近”猜作整个历史。
2. 复用Result及CoachingEvidence结构。QUESTION可使用观察/假设/建议；完整复盘追问调用深入提示但仍返回answer。个人事实只能来自当前日记；用户补充作为自述用于建议，不能伪造日记引文；假设引用的是出发事实，通用建议允许general。选择相关维度、替代解释和可核实办法，不强制凑项目数量。
3. 保留首轮和最近有界前文，优先用户原话和纠正，历史AI不是证据。按问题和前文改进quoteCatalog相关选句，同时保留来源覆盖、任务隔离及逐字校验。
4. 默认/最大输出100000；官方Chat Completions当前允许到393216，因此100000有效（2026-10-29核对 https://api-docs.deepseek.com/api/create-chat-completion/）。这是最大额度不是目标长度；总输出安全边界1600000字符、HTTP响应16MiB，引用边界保持。默认生成超时1800秒、最大3600秒，embedding维持短超时。
5. 长生成等待期间每15秒回调检查任务/来源/账号并续租；网络请求不占用数据库事务，取消或失效停止等待，不自动重试。收到完整响应先记可得用量，再由worker和最终事务检查是否可发布，避免取消边界丢失usage。完成日期尚无额度行时先创建空行，次数仍按开始日期预留。两类worker同步接入，旧报告保持可读。
6. 观察/假设等数组安全边界1000；建议最多20条，与现有人工采纳来源索引0至19及数据库约束一致，不为增加条数引入迁移。提示按相关性优先级取舍，不要求填满。

## Risks / Trade-offs

- 共享configured入口CRITICAL → 保留认证/白名单/日额度逻辑，仅放宽明确数值与新增生成超时，针对边界测试。
- 长回答增加耗时/费用 → 最大额度不强制写满，保留原次数额度、显式提交与不自动重试。
- 新观点被当作事实 → 提示区分、引用校验、UI“待核实/一般建议”，语义质量单独人工评审。
- 长请求丢租约或取消后发布 → 周期心跳与HTTP前后状态校验，模拟慢响应、取消、源变更验证。
- 超范围上下文 → 保持完整正文与提示预算，不静默裁切；提示缩小范围。

## Migration Plan

无DB迁移。本地测试、构建后，未来发布前备份旧JAR与前端，更新受限外置配置max-output-tokens=100000、generation-timeout-seconds=1800、max-response-bytes=16777216（在diary.ai层级明确设置，保留知识库助手原有800）。失败时回退应用和配置，不重放未知任务。真实日记语义效果由本人选择资料验收；本次仅使用合成资料。
