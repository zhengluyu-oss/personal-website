# blog-home-experience-visual-layout Specification

## Purpose
首页与工作经历页的视觉叙事、推荐轮播行为保留，以及主题/减少动画兼容。

## Requirements

### Requirement: 首页内容形成清晰的视觉叙事
系统 SHALL 在首页主内容区以程序员个人品牌、推荐文章、最新文章和职业经历入口组织内容，并在桌面与移动端保持清晰层级，同时保留现有后台可配置 Banner 内容。

#### Scenario: 桌面端浏览首页
- **WHEN** 用户在桌面宽度打开首页
- **THEN** Banner 与首屏后内容共同传达站主身份、技术输出和经历入口，推荐文章仍是主栏的重要视觉焦点

#### Scenario: 移动端浏览首页
- **WHEN** 用户在 640px 或更窄的视口打开首页
- **THEN** 内容按单栏顺序展示且不存在横向溢出，标题、按钮和正文保持可读

### Requirement: 推荐文章轮播逻辑保持不变
系统 MUST 保留现有推荐文章 Swiper 的数据接口请求、内容过滤、循环、导航、可点击分页、自动播放和文章详情跳转能力，同时使用统一品牌样式并在减少动态效果偏好下停止自动播放。

#### Scenario: 推荐数据加载成功
- **WHEN** 推荐文章接口返回至少一条数据
- **THEN** 系统展示可导航、可分页点击且点击可进入对应文章的轮播，并在允许动效时自动播放

#### Scenario: 推荐数据尚未加载
- **WHEN** 推荐文章列表为空且请求仍在进行
- **THEN** 系统显示与最终布局尺寸一致的加载状态而不是空白或报错

### Requirement: 工作经历列表呈现职业成长路径
系统 SHALL 将工作经历呈现为便于招聘者扫描的职业叙事，突出公司、职位、任职时间、关键成果和详情入口，并保证整项可由鼠标、触控或键盘打开。

#### Scenario: 浏览多条工作经历
- **WHEN** 接口返回多条启用经历
- **THEN** 用户能快速识别每段经历的时间、公司、职位和主要成果，且视觉样式与整站品牌一致

#### Scenario: 键盘访问经历条目
- **WHEN** 键盘用户聚焦经历条目并按 Enter
- **THEN** 系统导航到对应的工作经历详情页

### Requirement: 工作经历详情保持沉浸且易读
系统 SHALL 在详情页提供清晰返回入口、时间与职位信息、关键成果摘要、可读的 Markdown 正文容器以及友好的加载、不可用和空内容状态。

#### Scenario: 查看含正文的经历
- **WHEN** 用户打开一条包含 Markdown 正文的启用经历
- **THEN** 页面以适合招聘阅读的层级和舒适行宽呈现完整图文正文

#### Scenario: 查看无正文的经历
- **WHEN** 用户打开一条没有 Markdown 正文但有摘要的启用经历
- **THEN** 页面以友好提示和格式清晰的摘要替代空白正文

### Requirement: 视觉效果兼容主题与辅助偏好
系统 SHALL 兼容现有明暗主题，并在用户启用减少动画偏好时禁用非必要动画和位移效果。

#### Scenario: 启用深色主题
- **WHEN** 用户在深色主题下浏览首页或工作经历页
- **THEN** 背景、文本、边框与装饰保持足够对比且属于同一深色主题体系

#### Scenario: 启用减少动画
- **WHEN** 操作系统报告 `prefers-reduced-motion: reduce`
- **THEN** 页面关闭自动播放、装饰漂移和卡片位移动画，同时保留完整内容与交互
